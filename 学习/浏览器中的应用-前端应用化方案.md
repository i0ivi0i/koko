# 浏览器中的应用 - 前端应用化方案

目标：把前端从“浏览器里的网页”进化成“浏览器中的 IM 应用”。浏览器只提供运行时能力，群聊应用自己的状态机和控制器决定真相。

## 现在的问题

最近连续出现的媒体点击、视频全屏、滚动误触历史分页，本质不是 CSS 问题，也不是某个 click handler 写错了。根因是前端还在很多地方把浏览器事件直接当成应用真相。

错误思路：

- `scrollTop === 0` 就当成用户要翻历史。
- `click` 就直接打开或下载媒体。
- `fullscreenchange / popstate` 就直接影响聊天视口。
- DOM 列表就是消息流真相。
- `聊天壳.ts` 既做页面，又做编排，又做状态裁决。

正确思路：

- 浏览器事件只是输入信号。
- 应用状态机才决定用户意图。
- DOM 只是投影，不是真相。
- 成熟轮子负责通用难题，我们只写业务边界和薄适配层。

## 地基原则

1. `聊天壳.ts` 不再当“大脑”，只当应用壳和渲染入口。
2. 浏览器事件先转成应用事件，再交给应用运行时裁决。
3. 消息流、视口、媒体、实时连接各有唯一真相 owner。
4. 不手搓虚拟列表、播放器、图片查看器、缓存框架。
5. 每个模块只做一件事，Unix 式小而清楚，可组合、可替换。
6. DDD 只用于守业务真相，不搞聚合/工厂/服务的仪式堆叠。

## 推荐轮子

### 应用状态机：XState

用途：管理应用级 actor 和状态机。项目已经安装 `xstate`，不需要新引入一套状态框架。

它负责：

- 房间进入/退出。
- 快照加载/恢复。
- 实时连接和重连。
- 媒体查看模式。
- 视口状态。

它不负责：

- 直接操作 DOM。
- 直接调用播放器 UI。
- 直接持久化后端真相。

### 页面外壳：Lit ReactiveController

用途：继续沿用现有 Lit，但把生命周期和浏览器事件接入做薄。Lit 组件不直接决定业务状态，只把事件交给应用运行时。

### 万人消息列表：TanStack Virtual

用途：虚拟化消息列表。万人群聊不能让 DOM 承载所有消息。DOM 只保留可见窗口和少量 overscan。

它负责：

- 可见项计算。
- overscan。
- 大列表滚动性能。

它不负责：

- 消息排序。
- 历史分页规则。
- 已读位置真相。

### 视频播放器：Vidstack

用途：接管视频 UI、全屏、控制条、移动端播放体验。WebTorrent 继续负责提供播放源，Vidstack 负责播放器体验。

### 图片查看器：PhotoSwipe

用途：接管高清原图查看、缩放、滑动、移动端手势。图片点开必须看原图，不走下载逻辑。

### PWA / App Shell：Workbox

用途：用成熟方案管理 App Shell、静态资源预缓存、更新策略。聊天实时数据仍走网络和实时链路，不把实时消息错误地缓存成旧真相。

## 应用运行时设计

新增一个前端应用运行时概念，名字暂定 `AppRuntime`。它不是框架，不是大总管，而是组合根。

```text
浏览器事件
  -> Lit 外壳
  -> AppRuntime
  -> XState actors
  -> view model
  -> Lit 渲染
```

### RoomTimelineActor

唯一负责消息时间线真相。

输入：

- 房间快照。
- 实时增量事件。
- 历史分页结果。
- 重连补事件。

输出：

- 已排序消息窗口。
- 最老/最新 event_position。
- 是否还有更早历史。
- 去重后的附件列表。

禁止：

- DOM 决定消息是否存在。
- shell 自己拼接消息真相。

### RoomViewportActor

唯一负责聊天视口真相。

输入：

- 用户滚动意图。
- 程序性滚动。
- 虚拟列表范围变化。
- 历史页前插。
- 媒体查看器占用/释放视口。

输出：

- 是否允许加载更早历史。
- 是否贴底跟随。
- 未读定位是否完成。
- 读锚点候选。
- 程序性滚动尾波是否需要吸收。

禁止：

- `scrollTop === 0` 直接触发历史分页。
- 媒体覆盖层的副作用被当作用户翻历史。

### MediaViewerActor

唯一负责媒体查看模式。

输入：

- 打开图片/视频。
- 关闭查看器。
- 系统返回键。
- 全屏变化。
- 屏幕方向变化。
- WebTorrent 源就绪/降级。

输出：

- 当前是否占用聊天视口。
- 当前媒体类型。
- 当前播放源。
- 是否需要冻结或恢复聊天滚动判定。

禁止：

- 图片点击变下载。
- 视频内联播放器遮挡页面头尾。
- 浏览器返回直接破坏聊天房间状态。

### RealtimeActor

唯一负责实时连接生命周期。

输入：

- socket 连接/断开/重连。
- room event。
- session refresh。
- 补事件请求结果。

输出：

- 连接状态。
- 待补事件范围。
- 已交给 timeline 的事件。

禁止：

- socket 回调直接改 UI 真相。
- 重连后重复消息直接进入 DOM。

### AppShellActor

唯一负责浏览器应用壳状态。

输入：

- Service Worker 状态。
- 网络状态。
- 应用更新可用。
- 页面可见性变化。

输出：

- 弱网提示。
- 更新提示。
- 是否允许后台恢复。

禁止：

- 缓存层决定聊天业务真相。
- 页面刷新/返回时丢失应用恢复语义。

## 迁移顺序

### 第 0 步：写保护性测试

先补 characterization tests，不改行为。覆盖：

- 进入房间后的快照恢复。
- 用户滚到顶部才加载历史。
- 媒体打开/关闭不触发历史。
- 贴底时新消息跟随。
- 离底时新消息不抢视口。
- 重连后事件去重。

### 第 1 步：建立 AppRuntime 薄壳

只把现有 `聊天壳.ts` 的事件入口统一收口，不改变 UI。

验收：

- 原测试全过。
- `聊天壳.ts` 不再直接解释媒体/滚动/实时的核心真相。

### 第 2 步：抽 RoomViewportActor

把 `房间滚动器.ts` 的状态机语义收敛成 actor。

验收：

- 历史分页只能由 `RoomViewportActor` 裁决。
- 程序性滚动和用户滚动分开。
- 媒体查看器尾波不触发历史。

### 第 3 步：接入 TanStack Virtual

先让虚拟列表在测试里等价替换当前列表，再逐步打开真实虚拟化。

验收：

- 消息很多时 DOM 数量受控。
- 未读定位、历史前插、贴底跟随仍正确。

### 第 4 步：抽 MediaViewerActor，替换媒体轮子

视频接 Vidstack，图片接 PhotoSwipe，WebTorrent 只提供源。

验收：

- 图片点击看高清原图。
- 视频点击进入应用级播放模式。
- 手机返回键退出媒体，不退出房间。
- 竖屏视频按自身方向展示。

### 第 5 步：抽 RoomTimelineActor / RealtimeActor

把快照、历史、实时增量、重连补事件收口。

验收：

- 事件按 `event_position` 排序和去重。
- 重连补事件不重复。
- socket 回调不直接改 UI 真相。

### 第 6 步：Workbox App Shell

把静态壳缓存交给 Workbox。

验收：

- 静态资源可缓存。
- 实时消息不被错误缓存。
- 应用更新有明确提示或刷新策略。

## 不做什么

- 不重写成 React/Vue。
- 不把所有逻辑塞进 XState。
- 不自研播放器、图片查看器、虚拟列表、缓存框架。
- 不为了 DDD 增加一堆装饰性 service/factory/interface。
- 不把后端契约改成前端 UI 专用形状。

## 第一阶段完成标准

- `聊天壳.ts` 明显变薄。
- 滚动/媒体/实时至少各有一个清晰 owner。
- 新增的抽象必须删除或压缩旧逻辑，不允许叠新层留旧层继续活着。
- 每个阶段都有失败测试或 characterization test 保护。
- `pnpm --dir frontend test`、`typecheck`、`build` 必须通过。

## 一句话

把浏览器当运行时，不当业务真相；把成熟轮子当基础设施，不手搓通用能力；把 IM 的状态机和领域语义收口到应用运行时，页面只负责表达和展示。
