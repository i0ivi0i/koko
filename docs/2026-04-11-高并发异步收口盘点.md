# 高并发异步收口盘点

> 时间：2026-04-11  
> 范围：当前 `E:\koko` 实码状态  
> 目的：回答“还剩多少要收”，并说明为什么要按这个顺序收

## 前因

目标不是“项目里用了 Tokio 就算高性能”，而是：

- Rust 热路径尽量不走同步桥接
- Tokio worker 不被图片/视频解析这类重 CPU 工作顶住
- 群聊主链和媒体主链都能在高并发下保持可预期延迟

这轮已经先收掉了 `realtime socket` 主链里的 `spawn_blocking + block_on` 桥接。  
也就是说，连接认证、订阅补洞、创建消息这三条 realtime 热链，已经改成直接 `await` async 仓储口。

## 现状

当前剩余显式阻塞点一共 `32` 处：

| 类别 | 数量 |
|---|---:|
| `spawn_blocking` | 21 |
| `block_on` | 5 |
| 同步 `fs` / 路径落盘 IO | 6 |

另外还有 `1` 条没有桥出去的 CPU 重路径：

- `complete_media_upload` 里直接做图片解码、视频元数据探测、缩略图生成、分发元数据生成  
- 这类工作即使没有显式 `block_on`，也会直接占住 Tokio worker

## 为什么现在还不够

虽然 realtime socket 主链已经比之前干净，但系统还没有达到“万人实时在线群聊 + 收发图 + 收发视频”的目标，原因有三层：

1. HTTP 群聊主链还在用 `spawn_blocking`
2. 仓储层还保留 `Pg仓储::在运行时执行 -> block_on`
3. 媒体 `complete` 阶段还有重 CPU 工作直接跑在 async 主链上

所以现在的状态更准确地说是：

- `socket` 热路径先收了一步
- 但“聊天入口主链 + 媒体主链 + 仓储同步桥根”还没有收完

## 收口清单

| 优先级 | 类目 | 数量 | 位置 |
|---|---|---:|---|
| 已完成 | realtime socket 主链 blocking | 0 | `src/实时外壳.rs` |
| P0 | 群聊 HTTP 主链剩余 `spawn_blocking` | 6 | `src/房间外壳.rs` 的 `bootstrap_session / join_or_create_room / load_room_snapshot / update_room_read_anchor / load_room_events / load_room_history` |
| P0 | 媒体 `complete` CPU 重路径 | 1 条链 | `src/房间外壳.rs` 的 `complete_media_upload`，内部会跑图片/视频解析 |
| P1 | 媒体链剩余 `spawn_blocking` | 12 | `src/房间外壳.rs` 的 `prepare_media_upload / rustus hook / 等待回执 / locator / torrent / peer alive / attachment content` |
| P1 | 仓储同步桥根 | 1 个根 | `src/适配.rs` 的 `Pg仓储::在运行时执行` |
| P2 | 后台入口 `spawn_blocking` | 3 | `src/后台外壳.rs` |
| P2 | 启动/文件系统同步 IO | 6 | `canonicalize / 静态资源读取 / 启动期 block_on` |

## 推荐顺序

1. 先收 `P0`
   原因：这部分最直接影响聊天延迟和大图/大视频上传完成时的卡顿风险。
2. 再收 `P1`
   原因：媒体链量一上来，`prepare/complete/locator/torrent` 会放大 blocking 线程池和仓储同步桥的压力。
3. 最后拔 `P1` 的根
   原因：如果 `Pg仓储::在运行时执行` 还在，外围 handler 即使继续 async 化，也只是把同步桥换位置。

## 完成标准

这份盘点对应的“收完”标准，不是只看代码风格，而是看运行边界：

- 聊天主链不再依赖 `spawn_blocking + block_on`
- 媒体 `complete` 的重 CPU 解析迁到受控 worker，不直接占 Tokio worker
- `Pg仓储::在运行时执行` 退出运行态主链
- 群聊、图片、视频三条高频链路都能保持 async 直通

## 一句话结论

当前不是“已经高并发完成”，而是“realtime socket 先收完了第一段”。  
真正还要继续收的是三件事：`群聊 HTTP 主链`、`媒体 complete 重 CPU 路径`、`仓储同步桥根`。
