2. 前端热点仍然集中在“聊天应用总内核 + 聊天壳 + 聊天媒体编排”这组总控文件。
3. 现阶段还不能先做目录美化；必须先把这几颗热点总控的 owner 收回业务模块。

## 2. 当前不可先动的专项边界

以下专项边界在本轮重构里只能被尊重，不能被顺手改写：

- WebTorrent 正式视频字节主链
- `群聊视频禁止事项.md` 中的专项媒体禁令
- 浏览器零崩溃与零闪烁专项禁令
- 现有 `socketioxide` / `socket.io-client` 实时主链

判词：

1. 本轮重构只负责 owner、边界、门面变薄、门禁加固。
2. 如果后续某一步看起来需要推翻专项文档，先停下来重新裁决，不得顺手改写。

## 3. 当前首轮拆分坐标

- 后端先拆 `用例 / 契约 / 适配 / 外壳` owner
- 前端再拆 `聊天应用内核 / 聊天壳 / 聊天媒体编排` 的平台污染与交互混控
- 媒体、恢复、实时放在第二波 owner 收口，不与第一波混做

判词：

1. 第一步先收“谁判案”，不是先收“目录叫什么”。
2. 只有门面已经变薄、测试已经护住后，才轮到更外层目录落位。

### 4.3 计划命令修正记录

本轮发现并确认一个**计划文档级问题**，不是产品代码问题：

1. 在 `pnpm --dir frontend test` 的上下文中，Vitest 过滤路径必须写成 `tests/...`。
2. 原计划里若写成 `frontend/tests/...`，Vitest 会报 `No test files found`。

因此当前执行以真实可运行命令为准，后续需要同步回写计划文档，避免实现者按错命令卡住。

### 4.4 观察到的非阻塞信号

执行 `frontend/tests/聊天应用内核/架构边界与公开入口测试.spec.ts` 时出现：

```text
(node:82456) Warning: `--localstorage-file` was provided without a valid path
```

当前判定：

1. 这次 warning 没有导致测试失败，不构成当前重构的阻塞项。
2. 它值得在同 slice 上顺手深挖，因为它可能说明本地存储测试支撑或运行参数存在瑕疵。
3. 只有在不打断 owner 主线、且能定位到明确逻辑 bug 时，才把它纳入本轮一起修。
