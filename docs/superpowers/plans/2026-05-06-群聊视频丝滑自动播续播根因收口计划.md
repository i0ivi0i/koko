# 群聊视频丝滑自动播续播根因收口 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把群聊消息流视频的进入自动播、滑走、滑回、查看器升格、全屏接管、退出归位，以及滚动 / resize 期间的 owner 稳态播放收口成同一条无黑闪、无首帧跳、无抽搐的播放连续性链。

**Architecture:** 本轮只动前端播放表面链路，不碰后端、上传复用、WebTorrent 退字节、图片正式主链或数据库 schema。`媒体运行时.ts` 继续拥有自动播 owner 和播放位置真相，`全局丝滑自动播.ts` 成为唯一露出门禁，`全局唯一播放器.ts` 只执行同一颗 `Video.js` player/container 的挂载、seek、play、查看器和全屏迁移，`房间消息窗` 只把状态机阶段投影成稳定 DOM 表面，并把滚动 / resize 都降级为几何事实输入。

**Tech Stack:** TypeScript, Lit, XState v5, Video.js v10, WebTorrent, Vitest, Playwright CLI, browser-trace, `requestVideoFrameCallback`, MutationObserver

---

## Reality Check

这份计划来自当前代码事实和 `docs/superpowers/specs/2026-04-25-项目视频播放要求.md` 的 2026-05-06 裁决，不是凭空重写播放器。

当前真实链路：

- `frontend/媒体/全局丝滑自动播.ts`
  - 已有 `判定播放连续性表面(...)`。
  - 当前能输出 `cold_placeholder / hidden_handoff / visible_canonical / hold_frame / viewer_handoff / fullscreen_handoff / retire`。
  - 问题是它还没有足够强地成为唯一露出门禁，渲染层仍可绕过它组合 poster、preview、冻结帧、canonical host 和 stage host。
- `frontend/房间消息窗/视频附件渲染.ts`
  - 当前 `渲染视频附件(...)` 里有大量局部布尔判断。
  - 它在同一处决定 `poster / preview video / frozen frame / canonical host / stage host / first-frame guard` 谁能露出。
  - 这是本轮最可疑的漂移点：渲染层已经不只是投影，它在做第二裁判。
- `frontend/房间消息窗/时间线媒体基类.ts`
  - `同步时间线自动播播放状态(...)` 会遍历 preview videos，给 owner 执行恢复位置和 `play()`，给非 owner 执行 seek、冻结帧捕获和 pause。
  - `广播自动播播放位置(...)` 已经能在强制退场时捕获冻结帧并上报位置。
  - 问题是位置真相和首个可见帧真相还没有在状态机里合成一个原子露出结果。
- `frontend/房间消息窗/时间线画面缓存.ts`
  - 当前通过 canvas 导出 `data:image/webp` 冻结帧。
  - 这只能是同一会话的只读帧投影，不能升级成第二视觉真相，也不能绕过状态机直接露出。
- `frontend/房间消息窗/时间线播放器宿主.ts`
  - 当前在 visible host 和 stage host 之间选一个挂给全局唯一播放器。
  - 这层只能是 DOM 适配，不能决定“现在可以让用户看见什么”。
- `frontend/媒体/全局唯一播放器.ts`
  - 当前已经是唯一 `Video.js` player/container owner。
  - 它能同步时间线自动播、接管查看器、进入全屏、暂停当前时间线播放。
  - 本轮要让它按状态机结果做隐藏接管、帧提交确认和归位，不让它自己长第二套业务状态。

当前用户肉眼症状：

1. 进入自动播放时黑闪、空闪或先露占位。
2. 滑走时闪一下才暂停。
3. A 视频在 `0:18` 滑走，滑回时先露首帧，再跳到 `0:18`。
4. 点击查看器或全屏时断一下。
5. 退出查看器或全屏归位时闪一下。
6. 群聊消息窗滚动时自动播放视频抽搐、来回抢状态。
7. 页面 resize 或视频仍在屏幕中间时，画面也会前后跳、闪回首帧或封面；框尺寸本身不一定抖。

统一根因假设：

**中间态被暴露给用户。** 多个层都在好心决定画面，但没有一个唯一门禁把“源、位置、帧证据、宿主、意图、播放器 readiness”合成原子露出结果。

新增必须钉死的不变量：

**同一 owner、同一 source、同一时间线宿主仍有效，且唯一播放器已经处于 visible 播放态时，滚动和 resize 只能刷新几何事实；不得触发 `currentTime` 回灌、seek、source/poster 同步、player 重挂载、stage host 与 canonical host 切换、preview video 回盖 live player。**

## DDD / Hexagonal Boundary

当前 DDD 评分：`8/10`。

好的一面：

- 自动播 owner、播放器 owner、WebTorrent 分发 owner 已经分开。
- `Video.js` 没有被当成业务真相。
- WebTorrent 主链不属于这次前端露出修复范围。

需要补到 `10/10` 的点：

- 把“露出门禁”明确收口到 `全局丝滑自动播.ts`。
- 把 `视频附件渲染.ts` 降回 adapter：只消费阶段，投影稳定表面。
- 把浏览器事件和 DOM readiness 降为事实输入：`readyState / canplay / seeked / requestVideoFrameCallback / MutationObserver` 都不能直接裁决业务状态。
- 把滚动 / resize 明确降级为几何事实输入，不能越层变成恢复播放、seek 或重新接管。

边界表：

| 层 | 文件 | 拥有 | 禁止 |
| --- | --- | --- | --- |
| 应用协调 | `frontend/媒体运行时.ts` | 自动播 owner、pending owner、播放位置快照 | 决定 DOM 露哪一层 |
| 播放连续性 | `frontend/媒体/全局丝滑自动播.ts` | 唯一露出门禁、阶段转换 | 创建播放器、读 WebTorrent、直接操作 DOM |
| 播放器适配 | `frontend/媒体/全局唯一播放器.ts` | 唯一 `Video.js` player/container、seek/play/fullscreen | 裁决 owner、保存第二份位置真相 |
| DOM 投影 | `frontend/房间消息窗/视频附件渲染.ts` | 把阶段投影成稳定 `VideoSurfaceSlot` | 自己判断 poster/preview/frozen/canonical 谁该露 |
| 浏览器事实 | `requestVideoFrameCallback`、MutationObserver、IntersectionObserver | 只提供事实信号 | 直接决定业务状态 |

## Scope And Non-Goals

### 本轮必须解决

- 时间线视频进入自动播放不能黑闪。
- 滑走时先 flush 位置、锁住正确帧，再释放重播放 owner。
- 滑回时首个可见帧必须接近保存时间点，例如 `0:18`，不能先露首帧。
- 点击当前自动播视频进入查看器/全屏时同一颗 player 升格，不断片、不重建。
- 退出查看器/全屏归位时同一颗 player 回到时间线或优雅退场，不先露 poster 再 seek。
- 快滚、慢滚、上下反复滚动时 owner 序列稳定，不抽搐。
- 当前 owner 仍合法时，滚动和 resize 不会让同一条视频边播边抽、前后跳或闪回首帧/封面。

### 本轮禁止扩大

- 不改后端 contract、权限、房间、消息成立真相。
- 不改上传、去重、转发分享、source_hash、content_hash。
- 不改 WebTorrent TTL、presence、tracker、WebSeed、Service Worker 主链。
- 不改图片正式主链。
- 不改数据库 schema。
- 不引入第二播放器框架，不把 Video.js 替换成别的播放器。
- 不新增每条消息一个 live video，不新增第二 position store。
