# Koko 第一阶段实现计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 以纯 Rust 主栈落地 Koko 第一阶段最小稳定闭环，交付 Telegram iOS 风格 Web 前台、只读 admin 后台、PostgreSQL 持久化、`socketioxide` 实时聊天，并保持 Rust 六边形乐高边界、TDD 流程、`.rs <= 13` 文件预算，以及未来 CLI 化所需的多入口壳准备。

**Architecture:** 采用模块化单体 + Rust 六边形架构，稳定树干固定为 `domain / app / contract / store / rt / http / shell`。业务真相全部由后端与 PostgreSQL 定义，`socketioxide` 只做 realtime adapter，前端 `dioxus` 只做 UI 壳和体验态，浏览器端通过官方 `socket.io-client` 做薄协议适配。第一阶段虽然不交付完整 CLI，但所有核心用例与契约都必须保持入口无关，未来主要通过新增少量 CLI 壳层 binary 和 `.rs` 文件即可开始 CLI 化。

**Tech Stack:** Rust stable, Tokio, Axum, Tower HTTP, Socketioxide, Dioxus, socket.io-client, SQLx, PostgreSQL, Serde, Tracing, thiserror, uuid, chrono, cargo-nextest, sqlx-cli, sccache

**Fast Dev Rule:** 本项目明确禁止以 `WSL2` 作为默认开发环境；开发、调试、测试默认走 Win11 原生 Rust 工具链。日常编码主回路默认 `cargo check`，测试主回路默认 `cargo nextest run`，查询编译校验默认走 `sqlx` offline 元数据；Linux 一致性通过目标构建、CI 或最终发布验证补齐，不把“每改一点就全量重编译”当成正常工作方式。

- [ ] **Step 0.2: Freeze the command discipline before implementation**

Use these commands as the default loop:

- `cargo check`
- `cargo nextest run`
- `cargo test --doc`
- `cargo build --timings`

Only use full `cargo build` or `cargo build --release` when a step explicitly requires it.

- [ ] **Step 0.3: Keep SQLx compile-time checks off the hot path**

Adopt this workflow:

- In database-available environments, update metadata with `cargo sqlx prepare`
- Commit the generated `.sqlx` directory
- In normal local loops, compile without requiring a live `DATABASE_URL`
- In CI, verify metadata freshness with `cargo sqlx prepare --check`

- [ ] **Step 0.4: Enable optional compiler caching without coupling the repo to one machine**

Document local and CI opt-in use of `sccache` via `RUSTC_WRAPPER` or Cargo config, but do not hardcode a machine-specific wrapper path into business files.

- [ ] **Step 0.5: Align Win11-native development with Linux deployment semantics**

Keep the default local loop on Win11 native tooling, and use Linux target builds, CI, or remote Linux verification to catch deployment-specific issues before release. Do not introduce WSL2 as a required or recommended development path.

- [ ] **Step 0.6: Freeze CLI-ready shell boundaries before any feature code**

Treat `main.rs` as a thin service shell only. Do not let HTTP bootstrapping, Dioxus concerns, or Socket.IO adapter details leak into app-layer signatures or shared support types in ways that would block a future `koko` CLI binary.
