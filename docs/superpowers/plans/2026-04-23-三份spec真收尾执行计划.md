## Decision Lock

1. `streaming_video / streaming_audio` 继续被视为 `0-24 小时` 服务器冷备阶段的权威资产语义；本计划**不**把它们当成自动删除目标。
2. 本计划要删的是 locator / 播放 / worker 上仍在活着的**兼容别名与兼容回退**：顶层 `original_url`、`locator.original_url` 播放兜底、把 `presence_url` 绑在顶层 `original_url` 上的隐式基底依赖、`legacy（缺少 distribution）` fallback、单 worker owner 外层的双入口兼容快照。
3. `preview_asset` 仍然是消息流与 locator 共用的静态封面协议面；locator 顶层 `distribution` 仍然是 runtime transport 片段，本计划**不**误删这两个正式表面。
4. 任何“源码里不再包含某句字符串”的检查，都只能叫**架构守卫**，不能再冒充业务行为测试或迁移验证。
5. 三份 spec 只有在本计划最后一项验收全部通过后，才允许继续维持 `Implemented` 的绝对化表述；否则必须把实现记录改成和证据强度一致的话。
