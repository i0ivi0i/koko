# Web 视频默认循环播放策略 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让 Web 前端所有视频在“当前播放态”里默认循环播放，同时继续保持单一播放器壳、单一媒体主链和单一自动播 owner。

**Architecture:** 循环播放不是壳层补丁，而是统一播放策略。策略 owner 收口在前端媒体播放层的一个薄策略投影上；消息流自动播 `<video>` 和唯一 `Video.js` 正式播放器壳都只消费这条策略，不手搓 `ended -> replay` 第二套逻辑，也不按 `swarm / blob / anchor / manifest` 特判。

**Tech Stack:** TypeScript、Lit、Video.js custom elements、Vitest、happy-dom

---

## 文件结构与职责

- `frontend/媒体/媒体播放.ts`
  - 当前前端媒体主链的播放策略 owner。
  - 本次只允许在这里新增一个很薄的“视频默认循环播放”投影，不新增状态机，不新增配置层。
- `frontend/媒体/videojs播放器壳.ts`
  - 唯一正式播放器壳。
  - 负责把统一循环策略投影到唯一那颗真实 `<video>` 上，并保证切源时不丢。
- `frontend/房间消息窗.ts`
  - 消息流视频卡片壳层。
  - 负责把同一条循环策略投影到当前自动播 owner 的内联 `<video>` 上。
- `frontend/tests/媒体播放测试.spec.ts`
  - 锁死统一循环策略 owner 的语义，只允许视频默认循环。
- `frontend/tests/videojs播放器壳测试.spec.ts`
  - 锁死正式播放器壳默认循环，以及 file/hls 切源不丢循环语义。
- `frontend/tests/房间消息窗媒体查看器测试.spec.ts`
  - 锁死消息流自动播 `<video>` 会带循环语义，且不破坏单 owner。
- `frontend/tests/媒体查看器测试.spec.ts`
  - 锁死正式查看器继续走唯一 `Video.js` 壳，并且壳里的真实 `<video>` 默认循环。

不在本期范围内的文件：

- 后端 Rust 代码
- 共享前后端 contract
- P2P/WebTorrent 来源裁决
- 自动播 owner 选择算法

## 本计划的硬约束

- 不能把循环播放做成 `ended -> replay` 手搓机制
- 不能按 `swarm / blob / anchor / manifest` 分来源特判
- 不能在消息流和正式查看器各造一套循环规则
- 不能为此新增重型状态机、配置平台或私有基础设施
- 若实现里发现 `媒体是否默认循环播放(...)` 这种薄策略 owner 放在 `媒体播放.ts` 不合适，只允许挪到现有 `frontend/媒体/` 模块里的同层薄 helper，不能新长一套抽象

## 备注

- 本期不处理“手动暂停是否要跨 reopen 记住”这类新需求
- 本期不修改后端或共享 contract
- 若在实现中发现正式查看器和消息流之外还有第三条视频播放路径，必须先停下来补根因分析，不能继续把 loop 补丁复制过去
