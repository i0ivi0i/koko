# 真DDD满分收口 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. 当前仓库默认在 `main` 上按顺序执行；未获主人明确授权，不开分支、不起 worktree、不派发子代理。

**Goal:** 让 `koko` 从“方向正确但仍有总入口、临时桥、巨型壳和过厚 owner”的状态，收口到可证明的真 DDD / 六边形 / 洋葱 / 乐高积木架构：业务真相唯一、交互真相唯一、跨模块只走稳定契约、没有兼容链和冗余转发文件、核心代码足够简单到资深工程师不会说它过度复杂。

**Architecture:** 先删“第二入口、第二判断、第二 owner”，再拆“过厚 owner”。后端按 `身份 / 房间 / 消息 / 媒体 / 恢复 / 实时` 六个业务闭包收口，前端按 `房间 / 时间线 / 媒体播放会话 / 媒体查看器 / 协作分发 / 恢复 / 实时 / 总装` 收口。`domain / application` 只留业务语义与不变量，`adapter / shell` 只做翻译、装配、编排；凡是默认空实现、临时转发、跨适配借道、总控大桶，都要删或下沉。

**Tech Stack:** Rust stable、Tokio、Axum、SQLx、socketioxide、TypeScript、Lit、XState、Vitest、Playwright CLI、browser-trace、graphify、Serena。

## 当前评分与目标

- 当前 DDD：`6.5 / 10`
- 当前六边形边界：`6 / 10`
- 当前简洁度：`6 / 10`

要到 `10 / 10 / 10`，必须同时做到：

1. 没有跨业务总入口继续替代 bounded context。
2. 没有 `Ok(None)` / `Ok(vec![])` / `系统错误` 这种默认空实现把缺能力藏到运行期。
3. 没有“临时导出 / 兼容链 / 转发表面 / helper 借道”继续活在生产代码里。
4. `shell` 和 `总装` 只做装配，不再吞业务判定、清理策略、tracker 代理、媒体对账、DOM 平台细节。
5. 前后端热点文件继续变薄，但不是机械切碎；目标是主链更短、owner 更清楚、概念更少。

## 满分硬闸门

这份 plan 的目标不是“显著改善”，而是**达到满分后才能收工**。执行时必须按下面这套硬闸门打分；任一条不满足，都不能宣布完成：

### DDD = 10 / 10

1. 任何业务事实都只有一个 owner，没有第二判断点。
2. 没有跨业务总入口继续转发业务用例。
3. 没有“临时导出 / 兼容链 / 旧路径桥接”留在生产代码。
4. 聚焦业务语言，命名里不再靠 `helper / manager / wrapper / common` 解释职责。
5. 领域和应用层的行为能直接映射到身份、房间、消息、媒体、恢复、实时这些业务词，而不是技术桶。

### 六边形边界 = 10 / 10

1. `domain / application` 不含框架和平台细节，不偷摸 `Axum / SQLx / socketioxide / DOM / localStorage / Video.js`。
2. 适配器不跨适配器借道，不靠默认空实现糊边界。
3. 外部系统只通过明确端口进来，缺实现时优先编译期失败，不是运行期 `Ok(None)`。
4. `shell / 总装` 只接线和装配，不拥有业务裁决。

### 简洁度 = 10 / 10

1. 没有只转发一次的函数、只包一层的对象、只为“像架构”存在的抽象。
2. 没有资深工程师会一眼判定“过度设计”的结构。
3. 任何大文件都能解释为什么还必须大；解释不通就继续拆 owner。
4. 能删路径绝不加路径，能直表达绝不套三层。

本计划不是重复 `docs/superpowers/plans/2026-05-01-真DDD领域驱动重构执行计划.md`。昨天那份主要处理“旧根文件删除”和“根目录防回流”；今天这份只处理**删除旧根文件之后仍残留的结构性债务**：
