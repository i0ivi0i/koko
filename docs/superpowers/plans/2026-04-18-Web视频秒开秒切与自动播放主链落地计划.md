# Web 视频秒开秒切与自动播放主链落地计划 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把 `koko` 的 Web 视频主链落实成“查看器冷启动稳定秒开、同会话切换秒切、消息流自动播放也能吃到 HLS/P2P 热收益”的正式实现，同时补齐私有 swarm ticket 门禁。

**Architecture:** 后端继续作为媒体定位、流媒体生命周期和协作分发门禁的唯一 truth owner：`locator/complete` 签发短时 `join_ticket`，浏览器运行时只消费受控 `torrent_url / announce_urls / web_seed_url / presence_url`，不自己造 swarm 事实。前端继续保持 `Video.js v10 (@videojs/html)` 为唯一播放器壳，`hls.js` 为正式 HLS 引擎，`p2p-media-loader-hlsjs` 只增强 HLS 支路，`WebTorrent` 继续承担 whole-file backfill 与删源后的长期平面；查看器与 `inline_autoplay` 统一走同一个媒体编排 owner，只是 surface 策略不同。

**Tech Stack:** Rust、Axum、SQLx、Vitest、Lit、`webtorrent 2.8.5`、`bittorrent-tracker 11.2.2`、`@videojs/html 10.0.0-beta.22`、`hls.js 1.6.16`、`p2p-media-loader-hlsjs 2.2.2`。

## Constraints

- 不新增第二套播放器壳；`Video.js v10 (@videojs/html)` 仍是唯一播放器壳。
- 不让 `p2p-media-loader` 变成新的长期资产 owner；它只增强 HLS 支路。
- `inline_autoplay` 只共享同一条正式媒体主链，不允许因为滚动列表再冷启一套 whole-file swarm 风暴。
- ticket 过期/刷新属于运行时门禁，不得污染共享业务 contract 为页面流程语义。
- 所有行为改动必须先有失败测试，再做最小实现，再转绿，再提交。
- 任何代码改动完成后都要重跑 graphify rebuild、相关测试、`git status --short`，并用中文提交。
