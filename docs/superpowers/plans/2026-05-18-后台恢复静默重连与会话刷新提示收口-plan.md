# 后台恢复静默重连与会话刷新提示收口 实现计划

> **面向 AI 代理的工作者：** 必需子技能：使用 superpowers:test-driven-development，逐任务按 RED / GREEN / REFACTOR 执行。

**目标：** 修复页面切后台/恢复时把运行时主动挂起误显示为“会话已刷新”的体验 bug，让短暂后台恢复静默完成，同时保留真实断线和 `invalid_session` 恢复能力。
**架构：** 平台层继续收口浏览器生命周期；realtime adapter 暴露 socket 是否由运行时挂起的只读事实；实时会话机区分静默重订阅与用户可见重连；房间内核只在真实重连/会话失效时投影提示；壳层按错误码选择文案。
**技术栈：** TypeScript / XState / Socket.IO client / Lit shell / Vitest。
**设计文档：** `docs/superpowers/specs/2026-05-18-后台恢复静默重连与会话刷新提示收口-design.md`

## 1. 成功标准

1. `pagehide` / `frozen` 触发的 runtime suspend 不进入用户可见 `RECONNECTING_STARTED`。
2. 从后台回到 `active` 后会静默 `ensureRealtimeSocket + subscribeRoom(latestEventPosition)`。
3. 普通网络断线仍会触发可见重连和补订阅。
4. `invalid_session` 仍走会话刷新恢复链，并可显示“会话已刷新，正在重新恢复”。
5. 短暂后台回来不清空房间视图、输入、滚动位置、媒体 owner 或 WebTorrent 预热状态。

## 5. 任务 4：GREEN - 实时会话机加入重订阅模式

### 文件

- 修改：`frontend/实时/会话运行时.ts`

### 步骤

增加类型：

```ts
export type 实时断线来源 =
  | "runtime_suspend"
  | "temporary_transport"
  | "server_or_auth"
  | "manual_release";

type 实时重订阅模式 = "none" | "silent" | "visible";
```

扩展上下文：

```ts
resubscribeMode: 实时重订阅模式;
```

初始值：

```ts
resubscribeMode: "none",
```

扩展事件：

```ts
| {
    type: "SOCKET_DISCONNECTED";
    code: string;
    source?: 实时断线来源;
  }
```

在 `CONNECT_REQUESTED`、`SUBSCRIPTION_ESTABLISHED`、`ROOM_VIEW_EXITED` 清为 `"none"`。

在 `标记等待重连` 中加入分支：

```ts
if (event.source === "runtime_suspend") {
  return {
    connectionState: "suspended" as const,
    needsResubscribe: false,
    resubscribeMode: "none" as const,
    lastDisconnectCode: event.code,
  };
}
```

普通断线分支设置：

```ts
resubscribeMode:
  context.online && context.heavyWorkPolicy !== "suspended"
    ? "visible"
    : "none",
```

在 `同步生命周期策略` 里，从 `suspended` 回到 `normal` 时设置静默补订阅：

```ts
if (event.heavyWorkPolicy === "normal" && context.connectionState === "suspended") {
  return {
    heavyWorkPolicy: "normal" as const,
    connectionState: "reconnecting" as const,
    needsResubscribe: context.online,
    resubscribeMode: context.online ? "silent" as const : "none" as const,
  };
}
```

其它 `needsResubscribe=false` 路径同步设置 `resubscribeMode: "none"`。

调整文案：

```ts
function 派生恢复提示文案(
  recoveryState: 房间壳提示文案输入["recoveryState"],
  roomId: string,
  lastRecoveryErrorCode = ""
): string {
  if (recoveryState === "reconnecting") {
    return lastRecoveryErrorCode === "invalid_session"
      ? "会话已刷新，正在重新恢复"
      : "正在同步最新消息";
  }
  if (recoveryState !== "retryable_failure") {
    return "";
  }
  return roomId ? "实时连接暂不可用，可稍后重试" : "恢复失败，可稍后重试";
}
```

## 14. 自检记录

### 第一遍：规格覆盖度

本计划覆盖 spec 的四条主链：runtime suspend 来源标记、silent resume 补订阅、temporary disconnect 可见恢复、invalid_session 强恢复。通过。

### 第二遍：占位符扫描

计划中没有未完成标记、空泛错误处理要求或泛化测试要求。每个任务都有文件、步骤、验证和预期。通过。

### 第三遍：类型一致性

新增类型名统一为 `实时断线来源`、`resubscribeMode`、`读取Socket运行时挂起状态`；事件字段统一为 `source`；文案输入统一使用 `lastRecoveryErrorCode`。通过。

### 100% 自信循环

当前计划作为实现路径有事实层面的充分信心：它先用 RED 证明 runtime suspend 被误当可见重连，再最小实现断线来源和重订阅模式，最后调整文案。风险点是静默恢复漏补订阅和误吞真实断线，计划分别用 `silent` 与 `visible` 两类测试约束，不靠 UI 特判掩盖状态机错误。
