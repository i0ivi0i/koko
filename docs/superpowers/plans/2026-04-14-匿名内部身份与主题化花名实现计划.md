# 匿名内部身份与主题化花名 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把匿名身份链路收口成 `UUIDv7` 内部身份 + 项目级主题化花名投影，并把前台表面缩到 `session_id + display_alias`，同时清掉 `sessions.display_name` 的真相位。

**Architecture:** 这次改造不做“大重写”，而是沿现有 `适配 / 房间阅读适配 / 消息事件适配 / 房间外壳 / frontend` 主链做分阶段切换。真相 owner 收口到 `anonymous_identities(identity_uuid, theme_key, display_alias)`；`session_id` 继续做运行锚点；花名生成站在 `names` 轮子上，主题词库收口在一个小而硬的 `src/用户身份.rs`，不再手搓第二套生成器。

**Tech Stack:** Rust 2021, SQLx, PostgreSQL, Tokio, uuid crate (`v7`), names crate, TypeScript, Vitest, pnpm

### Ownership Lock

- `src/用户身份.rs` 只拥有主题库、花名生成、内部身份/当前资料投影辅助结构，不持有 SQL，不进入壳层。
- `src/适配.rs` 继续拥有 bootstrap 持久化编排，但不再手搓标识和花名算法。
- `src/消息事件适配.rs` 只负责消息发送者当前投影查询与事件装配，不自己决定用户资料。
- `src/房间阅读适配.rs` 只负责房间恢复/历史/增量/阅读锚点查询，不再从 `sessions.display_name` 读取当前花名。
- `frontend` 只消费 `session_id + display_alias`，不再回声匿名内部身份。
