# 群聊统一附件入口与操作台附件能力注册 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把群聊底部发送区的图片/视频双入口收口成一个统一附件入口，在 `frontend/操作台/附件入口` 建立稳定的壳层边界，并让 `frontend/媒体/媒体发布.ts` 对外只暴露一个统一媒体文件入口。

**Architecture:** `shell` 层只拥有附件入口、能力注册和点击编排，不拥有图片/视频事实判断；`frontend/媒体` 继续拥有媒体类型识别、预处理、上传和草稿状态机。当前注册表只注册 `media` 一个能力，策略固定为 `direct`，因此 UI 上是一个统一按钮直接打开一个统一文件选择器，但结构上已经为未来 `file / camera / location` 扩展留出稳定挂点。

**Tech Stack:** TypeScript, Lit, Vitest, happy-dom, @uppy/core, @uppy/tus

- [ ] **Step 3: 实现附件入口编排器，并让聊天壳只做装配**

  在 `frontend/操作台/附件入口/附件入口编排.ts` 落一个极薄控制器：

  ```ts
  import {
    创建附件能力注册表,
    统一媒体文件选择配置,
  } from "./附件能力注册";

  export function 创建附件入口编排(input: {
    auxSlot: { visible: boolean; disabled: boolean; label: string };
    获取统一媒体文件输入: () => HTMLInputElement | null;
    处理选择媒体文件: (files: Iterable<File>) => Promise<void>;
  }) {
    const 能力列表 = () =>
      创建附件能力注册表({
        auxSlot: input.auxSlot,
        执行默认媒体能力: () => input.获取统一媒体文件输入()?.click(),
      });

    const 执行默认附件能力 = (): void => {
      const [默认能力] = 能力列表();
      if (!默认能力 || !默认能力.visible || 默认能力.disabled) {
        return;
      }
      默认能力.execute();
    };

    const 处理统一媒体文件变更 = async (event: Event): Promise<void> => {
      const target = event.currentTarget as HTMLInputElement | null;
      if (!target?.files || target.files.length === 0) {
        return;
      }
      const files = Array.from(target.files);
      target.value = "";
      await input.处理选择媒体文件(files);
    };

    return {
      能力列表,
      执行默认附件能力,
      处理统一媒体文件变更,
      统一媒体文件选择配置,
    };
  }
  ```
