# 群聊图片发送单链收口与复杂度清理 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 删除旧 `/api/attachments/image` 双链，把前端图片发送从 [聊天壳.ts](E:/koko/frontend/聊天壳.ts) 收口到 `frontend/图像/`，让群聊图片发送只剩 `prepare -> upload -> complete -> create_message` 一条可读、可测、可定位的主链。

**Architecture:** 后端继续保留 DDD 里的 `prepare/upload/complete/create_message/load_attachment_content` 边界，只删除旧直传 handler、旧 route、旧登记用例和旧 trace 语义。前端继续复用 `@uppy/core`、`@uppy/aws-s3`、`heic2any`，把图片草稿、图片预处理、上传诊断、Uppy 编排从 [聊天壳.ts](E:/koko/frontend/聊天壳.ts) 抽到 `frontend/图像/`，聊天壳只保留 UI 接线和必要本地体验态。

**Tech Stack:** Rust, Axum, Tokio, SQLx, object_store, infer, image, kamadak-exif, TypeScript, Lit, Vitest, @uppy/core, @uppy/aws-s3, heic2any
