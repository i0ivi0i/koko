# 真DDD领域驱动重构 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:executing-plans` 在当前会话按任务逐段执行。步骤使用 checkbox (`- [ ]`) 语法追踪。除非主人明确允许，禁止改走 subagent 路线。

**Goal:** 把 [真DDD领域驱动重构铁律](</E:/koko/docs/superpowers/specs/2026-05-01-真DDD领域驱动重构铁律.md:1>) 从“已经立起部分门面”推进到“后端唯一业务真相、前端唯一交互真相、模块 owner 完整收口、适配与外壳显著变薄、门禁可防漂移”的完成态。

**Architecture:** 这不是目录美化，也不是一次性推倒重来，而是严格按“先冻结真相与基线，再补齐缺失 owner，再把旧总控实质性掏空，最后才删旧路和收目录”的增量重构。后端优先，因为后端拥有唯一业务真相；前端随后收口房间、时间线、输入框、媒体、恢复、实时这些交互 owner；所有阶段都必须靠测试、负向守护和真实烟测过门，禁止靠主观感觉宣布完成。

**Tech Stack:** Rust 稳定版、Axum、SQLx、Tokio、socketioxide、TypeScript 6.0.2、Lit 3、Vitest、Playwright、WebTorrent 2.8、Video.js v10、Serena、graphify。

应该：

1. 把“完成”理解为 owner 真正换位、旧总控真正变薄、门禁真正生效。
2. 把“脱胎换骨”理解为以后新增功能默认只能长进对应模块，不能再回流进统一总控。

1. 因为已经出现新目录、新门面，就提前宣布是真DDD。
2. 因为测试暂时都绿，就跳过结构性未完成项。
3. 因为旧文件还没真正掏空，就把“过渡态”包装成完成态。
