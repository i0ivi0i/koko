# 真DDD无屎山架构收口 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. 当前宿主未获显式授权时不要派发子代理，按本计划在当前 `main` 上逐段执行。

**Goal:** 让 `koko` 从“已有 DDD 方向但仍有旧根文件和重复入口”收口到可证明的真 DDD / 洋葱 / 乐高积木架构：业务真相只有一个 owner，旧根包装文件删除，冗余代码和失效验证链清掉，架构守卫能长期阻止回流。

**Architecture:** 先修断掉的验证链，再清除重复模块身份，然后把 `src/契约.rs`、`src/用例.rs`、`src/适配.rs`、`src/外壳.rs` 里的真实职责按业务 owner 下沉到已有模块，最终删除旧根文件。前端根目录当前已干净，下一步只守防回流和拆薄模块内部热点，不恢复旧入口，不新增空壳，不为未来幻想造抽象。

**Tech Stack:** Rust stable、Axum、SQLx、Tokio、socketioxide、TypeScript、Vitest、Playwright CLI、browser-trace、graphify、Serena。

## 0. 执行前总判断

当前不能宣布“无屎山真 DDD 完成态”。第一轮审查已经证明：

1. `cargo check --all-targets` 会失败，原因是迁移后的测试 fixture 相对路径仍指向旧位置。
2. `src/实时/外壳.rs` 被两条模块路径编译，制造重复模块身份和 22 个 dead_code 警告。
3. `tests/架构边界守卫.rs` 仍把旧根文件当成允许状态，而不是要求删除。
4. `docs/superpowers/reports/2026-05-01-真DDD重构完成矩阵.md` 仍传播旧口径，和铁律冲突。
5. 后端根目录还保留 4 个大文件：`契约.rs`、`用例.rs`、`适配.rs`、`外壳.rs`。
6. 大热点仍存在：`src/媒体/适配.rs`、`src/媒体/上传/外壳/媒体上传.rs`、`src/外壳.rs`、`src/用例.rs`、`frontend/房间消息窗/壳.ts`、`frontend/媒体/资产协作分发运行时.ts`、`frontend/总装/聊天壳.ts`。

本计划的核心不是“拆更多文件”，而是删掉无必要路径，让每条业务链只剩一个 owner。

## 1. 成功标准

完成时必须同时满足：

1. `cargo check --all-targets` 通过。
2. `cargo test` 通过。
3. `cargo test --test 架构边界守卫` 通过，并且它不再保护旧根文件。
4. `cargo test --test 媒体测试边界守卫` 通过。
5. `node scripts/check-frontend-architecture-fitness.mjs` 通过。
6. `node scripts/check-frontend-browser-app-constitution.mjs` 通过。
7. 如触及前端生产链路，必须用 `playwright-cli` / `browser-trace` 在真实浏览器进 `1234b` 做烟测。
8. 如改代码，必须跑 `graphify update .`；纯文档改动不强制。
9. 根目录新增 `.rs` / `.ts` 业务文件默认失败。
10. 旧根包装文件被删除，而不是改名后继续活着。
11. 最终 `git status --short` 干净，提交信息用中文。

完成判词只能基于这些新鲜证据，不能靠“看起来已经分层”。

## 3. 执行纪律

每个代码任务都按 TDD：

1. 读目标文件、调用链、相邻模块、测试和报告。
2. 写最小失败测试或 characterization。
3. 确认失败原因是目标问题。
4. 写最小实现。
5. 跑能证明该改动的测试。
6. 必要时重构，保持测试绿。
7. 如改代码，跑 `graphify update .`。
8. `git diff --check`。
9. `git status --short`。
10. 中文提交。

禁止：

1. 复制旧逻辑到新文件后保留双活。
2. 为了让测试绿恢复旧入口。
3. 新建 `utils / helpers / common / manager / service` 这种兜底桶。
4. 用空 trait、空接口、空模块制造 DDD 外观。
5. 一次迁移多个无关 owner。
6. 把大文件机械切碎，却不缩短主链。
7. 为了兼容过期测试继续留下无价值文件。

Unix 判断尺：

1. 200 行能写成 21 行，就重写到 21 行。
2. 资深工程师会说“绕、虚、过度”的方案，不能继续推进。
3. 能删除路径，就不要增加路径。
4. 能直接表达业务语言，就不要套三层抽象。

1. 每个任务都有 RED / GREEN / REFACTOR 顺序。
