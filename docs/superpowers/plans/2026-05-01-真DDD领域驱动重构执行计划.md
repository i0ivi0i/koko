# 全仓真DDD物理文件架构收口 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:executing-plans` 在当前会话按任务逐段执行。步骤使用 checkbox (`- [ ]`) 语法追踪。除非主人明确要求，禁止改走 subagent 路线。

**Goal:** 按 [真DDD领域驱动重构铁律](</E:/koko/docs/superpowers/specs/2026-05-01-真DDD领域驱动重构铁律.md:1>) 把全仓前后端物理文件位置收敛到真实 owner：后端优先清理 `src/` 根目录历史 `.rs` owner，前端守住根目录业务 owner 已清零的基线并防止回流。

**Architecture:** 先冻结当前事实和门禁，再按业务闭包迁移。后端按 `媒体 -> 房间/消息/身份/实时/后台 -> 总门面` 收口；前端不重建已删除根门面，只做防回流、总装防长胖和测试锚点修正。每个 slice 都先读调用链和测试，再写失败守卫或 characterization，最小迁移，跑验证，提交。

**Tech Stack:** Rust 稳定版、Axum、SQLx、Tokio、socketioxide、TypeScript 6.0.2、Lit 3、Vitest、Playwright CLI、browser-trace、WebTorrent 2.8、Video.js v10、Serena、graphify。

## 0. 前因后果

这份 plan 接在提交 `f5de97c6 文档: 融合全仓DDD物理架构裁决` 之后执行。

这次不是重新争论 DDD，也不是为了目录树好看而搬文件。前因是：

1. 仓库已经有 `身份 / 房间 / 消息 / 媒体 / 实时 / 恢复 / 总装 / 平台` 等模块。
2. 但历史上前端和后端都曾经把真实 owner 留在根目录大文件里。
3. 前端根目录业务 owner 已经完成第一轮清零，不能再把它们写成待办，更不能为了兼容恢复它们。
4. 后端 `src/` 根目录仍然有较多业务/适配/外壳 owner 文件，是真正剩余的物理架构债。

为什么要这么做：

1. 根目录旧 owner 会制造第二真相：目录里有模块，真实逻辑却还在根文件。
2. 新功能会自然回流到最容易 import 的旧文件，模块目录会变成空壳。
3. 未来 agent 如果看到旧 plan 里的过期清单，会重新创建已经删除的前端根门面。
4. 真 DDD 的价值不在目录名，而在 owner、依赖方向、测试门禁和真实运行链路一致。

本计划只解决物理架构和 owner 落位问题，不改变业务规则、媒体主链、播放器策略、身份/房间/消息成立性。

## 2. 执行纪律

每个任务必须按下面顺序做：

1. 读 `graphify-out/GRAPH_REPORT.md` 和本任务涉及文件。
2. 用 `rg` 或 Serena 查生产引用、测试引用、门禁引用。
3. 写失败守卫或 characterization test。
4. 做最小迁移，不复制双活。
5. 跑 targeted tests。
6. 跑该 slice 需要的架构门禁。
7. 如果改代码，跑 `graphify update .`。
8. 跑 `git diff --check` 和 `git status --short`。
9. 中文提交。

禁止：

1. 复制旧逻辑到新目录后保留旧逻辑双活。
2. 因为搬文件风险大就无限期保留散落 owner。
3. 把测试继续锚定旧根文件，反向保护旧结构。
4. 把前端已删除根门面重新创建出来。
5. 一次性同时迁移多个互相不相关的业务 owner。
6. 为了目录好看新建空目录、空模块或无调用包装。
