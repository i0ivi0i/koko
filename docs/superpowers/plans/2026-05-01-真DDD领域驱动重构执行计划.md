# 真DDD物理文件架构严格收口 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:executing-plans` 在当前会话按任务逐段执行。步骤使用 checkbox (`- [ ]`) 语法追踪。除非主人明确要求，禁止改走 subagent 路线。

**Goal:** 按 [真DDD领域驱动重构铁律](</E:/koko/docs/superpowers/specs/2026-05-01-真DDD领域驱动重构铁律.md:1>) 把根目录散落 `.rs` / `.ts` 收成入口、总装、极薄门面和明确 owner 模块，防止“目录像 DDD、真实逻辑还在根目录旧总控”的双结构继续存在。

**Architecture:** 先建门禁和基线，再按后端媒体、后端房间/消息/身份/后台、后端总门面、前端平台/总装、前端房间/时间线、前端实时/恢复、前端媒体、测试结构八条 slice 逐步迁移。每条 slice 都先写失败守卫，再移动最小 owner，再让旧根文件退成门面或删除；禁止大爆炸重命名、禁止旧新双活、禁止把 WebTorrent / Video.js / 恢复 / 实时专项规则顺手改松。

**Tech Stack:** Rust 稳定版、Axum、SQLx、Tokio、socketioxide、TypeScript 6.0.2、Lit 3、Vitest、Playwright CLI、browser-trace、WebTorrent 2.8、Video.js v10、Serena、graphify。

---

## 0. 计划边界

本计划接在规格文件提交 `72f1636d 文档: 融合真DDD物理文件架构铁律` 之后执行。它不是重新设计业务，不是一次性换目录名，也不是借重构顺手改媒体策略；它只做一件事：让物理文件位置表达真实 owner。

必须保住的旧裁决：

1. 后端拥有唯一业务真相；前端只拥有交互真相、体验真相和平台适配真相。
2. `contract` 只放稳定 command / query / event / snapshot / error，不能混壳层流程。
3. 正式媒体字节主链仍是唯一 `WebTorrent` whole-file swarm，禁止 HLS / DASH / 原文件直链 / range / CDN / 静态预览变第二真相。
4. `Video.js v10` 只是唯一播放器壳，不能拥有 source owner、分发真相或业务真相。
5. 恢复链只恢复体验和重放意图，不拥有房间、成员、消息、媒体成立性。
6. 修改代码后必须运行 `graphify update .`；纯文档改动不强制。

当前 graphify 基线：`graphify-out/GRAPH_REPORT.md` 显示 `635 nodes / 1344 edges / 33 communities`，强连接点仍集中在媒体、外壳、适配、测试支撑等链路。这个信号说明迁移重点不是“再造目录”，而是把真实调用、真实 owner 和真实门禁移出根目录旧总控。

## 2. 执行纪律

每个任务都按下面小循环执行：

1. 读目标文件、调用方、被调用方、相邻模块和对应测试。
2. 写失败守卫或 characterization test。
3. 最小移动 owner；旧根文件只做转发或删除。
4. 跑本任务命令，读完整输出和退出码。
5. 如果改了代码，运行 `graphify update .`。
6. `git status --short`，清掉自己造成的噪音。
7. 单任务提交，中文提交说明。

禁止：

1. 同时迁移后端和前端同名 owner。
2. 复制旧逻辑到新模块后保留旧逻辑双活。
3. 因为搬文件风险大就无限期保留散落 owner。
4. 用临时 guard、timeout、mock 让测试变绿但不收 owner。
5. 把测试继续锚定旧根文件，反向保护旧结构。
