# 万人实时群聊去屎山终态收尾计划

日期：2026-04-23
状态：Draft
前置事实：`docs/superpowers/specs/2026-04-23-万人实时群聊去屎山与长期防漂移约束.md` 的大部分总执行已经落地，但 Serena + graphify 复核确认，当前还不能判定为“彻底完成”。

## 1. 当前剩余阻断项

### 1.1 shared owner 仍有活着的大表依赖

1. `frontend/后台应用内核.ts` 还在直接消费 `this.platform.transport.transport()`；
2. 这意味着后台壳层虽然不再自己 new transport，但后台内核仍然抱整张 shared transport 大表；
3. 该问题不解决，就不能说 shared hotspot 已彻底收口。

### 1.2 生产契约与媒体主链仍有明确兼容尾巴

1. `frontend/契约.ts` 里 `body` 仍标注为“兼容旧纯文本链过渡字段”；
2. `frontend/契约.ts` 里 `availability` 仍标注为“旧链路兼容字段”；
3. `frontend/媒体/媒体播放.ts` 仍保留图片 blob 主链兼容分支；
4. 这些都属于 spec 明确禁止长期存活的兼容尾巴。

### 1.3 滚动链仍保留迁移期兼容口

1. `frontend/房间滚动器.ts` 的 `更新状态?` 还带着“迁移期避免测试基建爆炸”的注释；
2. 这说明视口 owner 已经迁走，但旧测试基建还没跟上；
3. 不清零这条口子，就不能说旧路径真正退场。

### 1.4 media owner 仍有单点总控

1. `frontend/聊天媒体编排.ts` 已拆出协作模块，但函数本体仍然过大；
2. 查看器、自动播、预览、补齐之外，还混着媒体会话表、缓存恢复、生命周期副作用；
3. 这仍然会被 graphify 打成热点。

### 1.5 graphify 热点尚未达到终态门禁

1. `HttpRealtime传输` 仍是第 1 god node；
2. `Invoke-HttpsBootstrap()`、`Start-AppViaRunScriptIfNeeded()`、`Write-ManagedProcessLogs()` 仍在前排；
3. 只有当源码和图谱同时减压，才允许宣布 spec 完成。

## 2. 唯一执行顺序

1. 先补剩余阻断项的失败测试或护栏测试；
2. 先收 shared owner 最小切口：后台 transport 窄口；
3. 再清理兼容字段与媒体 blob 旧分支；
4. 再清理滚动迁移口；
5. 再继续削薄 `聊天媒体编排.ts` 与相关协作边界；
6. 最后跑全量验证与 graphify 复核。

## 3. TDD 施工任务

### Task 1：后台 transport 窄口化

目标：

1. `后台应用内核` 不再持有完整 `前端传输端口`；
2. 改成分别持有 `后台查询传输端口` 与 `后台会话传输端口`；
3. 平台默认值从 `this.platform.transport.后台查询传输()` / `后台会话传输()` 读取。

验证：

1. `frontend/tests/后台应用内核测试.spec.ts`
2. `frontend/tests/浏览器应用平台测试.spec.ts`
3. `frontend/tests/传输运行时测试.spec.ts`

### Task 2：文本链兼容字段退场

目标：

1. 删除消息契约里的 `body` 过渡字段；
2. 前端统一只读 `text`；
3. 删除相关测试支架和视图里的 `body` 旧期待。

验证：

1. `frontend/tests/媒体共享契约测试.spec.ts`
2. `frontend/tests/聊天壳阅读与消息测试.spec.ts`
3. `frontend/tests/realtime真实链路.spec.ts`
4. `pnpm --dir frontend test`

### Task 3：媒体 availability / blob 兼容尾巴退场

目标：

1. 读取协作分发状态只认 `media_state.code`；
2. 删除 `availability` 兜底兼容；
3. 删除图片 blob fallback 为正式播放结果的分支，只保留共享资产事实与 backfill 所需能力；
4. 调整测试支架与媒体播放测试到 WebTorrent / canonical 新真相。

验证：

1. `frontend/tests/媒体播放测试.spec.ts`
2. `frontend/tests/媒体协作分发测试.spec.ts`
3. `frontend/tests/blob媒体资产测试.spec.ts`
4. `frontend/tests/聊天媒体编排测试.spec.ts`

### Task 4：滚动迁移口清零

目标：

1. 删除 `房间滚动器依赖` 里的 `更新状态?` 兼容口；
2. 同步清理旧测试支架与任何残余调用；
3. 保证视口 owner 只走当前观察/上报接口。

验证：

1. `frontend/tests/聊天壳恢复与分页测试.spec.ts`
2. `frontend/tests/聊天壳未读恢复测试.spec.ts`
3. `frontend/tests/浏览器应用平台测试.spec.ts`

### Task 5：继续削薄媒体编排热点

目标：

1. 继续把 `创建聊天媒体编排` 里仍然混杂的副作用同步与会话释放逻辑下沉；
2. 至少把“媒体会话集合清理 / 运行时副作用同步 / 统一释放逻辑”再收成窄 helper；
3. 不能只是换目录，必须让主编排函数明显变薄。

验证：

1. `frontend/tests/聊天媒体编排测试.spec.ts`
2. `frontend/tests/聊天应用内核测试.spec.ts`
3. `pnpm --dir frontend typecheck`

## 4. 最终完成门禁

只有同时满足下面条件，才允许把 spec 判定为完成：

1. `git status --short` 干净；
2. `pnpm --dir frontend test` 通过；
3. `pnpm --dir frontend typecheck` 通过；
4. `pnpm --dir frontend build` 通过；
5. `cargo test -j 1` 通过；
6. `pwsh -File tests/启动器脚本检查.ps1` 通过；
7. `pwsh -File tests/powershell/https-script.tests.ps1` 通过；
8. `python3 -c "from graphify.watch import _rebuild_code; from pathlib import Path; _rebuild_code(Path('.'))"` 执行完成；
9. graphify 热点不能继续用原样事实证明 shared/media owner 仍未收清。
