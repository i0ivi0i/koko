# 前端浏览器应用化 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 按 `docs/superpowers/specs/2026-04-12-前端浏览器应用化-design.md`，把前端从“浏览器里的网页事件补丁”迁移成“浏览器中的万人实时 IM 应用”。

**Architecture:** 这不是重写前端，也不是一次性把所有东西塞进 XState。先用 `AppRuntime` 建立应用事件入口，再逐步把房间视口、消息时间线、媒体查看、实时同步、App Shell 收口到各自唯一 owner；每一阶段都必须删除或压缩旧入口，不能只新增包装层。

**Tech Stack:** TypeScript、Lit、XState、socket.io-client、WebTorrent、Uppy/Tus、Vitest、esbuild；后续阶段按官方文档复核并引入 TanStack Virtual、Vidstack、PhotoSwipe、Workbox。

## 范围裁决

这份 plan 覆盖 spec 的阶段 0 到阶段 6，目的是让后续执行有一张完整施工图；执行时仍按阶段切片、单独测试、单独提交。

这份 plan 明确不做：

- 不切 React/Vue；
- 不改后端 Rust 契约，除非某一阶段的失败测试证明现有契约无法表达应用语义；
- 不自研虚拟列表、播放器、图片查看器、Service Worker 缓存框架；
- 不新增 ceremony-first DDD 层，不做没有压缩旧逻辑的 wrapper/manager/service；
- 不在一个提交里吞掉 AppRuntime、虚拟列表、媒体播放器、Workbox 全部改造。

执行位置：

- 按当前仓库规则，默认在 `main` 当前工作区执行，不另开 branch/worktree，除非主人明确要求。
- 每阶段最后必须 `git status --short`，验证通过后中文提交。

## 文档与依赖复核

已用 Context7 初步复核：

- TanStack Virtual：官方资料强调 `getScrollElement`、`estimateSize`、动态测量、`getTotalSize()`、virtual items 只渲染可见窗口；计划中它只做显示窗口，不做消息顺序真相。
- Vidstack：官方资料支持 Web Components 入口 `import 'vidstack/elements'` 与 `<media-player><media-provider></media-provider><media-video-layout></media-video-layout></media-player>`；计划中它只做播放器 UI，不做媒体源或房间视口 owner。
- Workbox：官方资料支持 `precacheAndRoute(self.__WB_MANIFEST)` / `cleanupOutdatedCaches()` / runtime routes；计划中只缓存 App Shell 和静态资源，明确排除聊天 API、socket、媒体业务数据。
- PhotoSwipe：执行到媒体阶段前必须再查官方 `https://photoswipe.com/getting-started/`，只让它承担图片查看、缩放、手势，不让它拥有房间滚动或附件真相。

## 文件结构锁定

### 新增文件

- `frontend/应用运行时.ts`
  唯一新增的第一阶段组合根。它接收应用事件，转发给现有 `房间滚动器 / 阅读推进编排 / 媒体查看器 / 房间实时编排`。它不能直接操作 DOM、不能拼后端契约、不能吃掉已有 actor 的职责。
- `frontend/tests/应用运行时测试.spec.ts`
  专门保护应用事件入口和反漂移规则：浏览器事件必须先变成应用事件，不能绕过 runtime 触发核心副作用。
- `frontend/房间时间线.ts`
  阶段 5 才创建。只承接消息 timeline 真相：snapshot/history/realtime/reconnect/optimistic 的排序、去重、合并；不持有 socket、不读 DOM。
- `frontend/tests/房间时间线测试.spec.ts`
  阶段 5 才创建，纯函数/actor 测试 timeline 合流，不依赖 Lit。
- `frontend/app-sw.ts`
  阶段 6 才创建。Workbox App Shell service worker，不和 `frontend/media-sw.ts` 混用。
- `frontend/tests/应用壳测试.spec.ts`
  阶段 6 才创建，保护 App Shell 注册、静态资源缓存边界和 API/socket 不缓存。

### 主要修改文件

- `frontend/聊天壳.ts`
  逐步退回壳层：组合、渲染、事件转译；不得继续新增滚动/媒体/实时业务裁决。阶段 1 必须把 `@room-scroll-intent`、`@room-scroll`、`@jump-to-latest`、`@room-open-media-viewer` 转到 `AppRuntime`。
- `frontend/房间滚动器.ts`
  阶段 2 收口为 `RoomViewportActor` 的现有承载点。顶部阈值、贴底阈值、程序性滚动尾波、历史补偿都只能在这里或它的直接内核里裁决。
- `frontend/阅读推进编排.ts`
  继续负责已读推进、跳到最新、历史补偿用例编排；阶段 2 后不得直接接浏览器事件，只接 runtime/viewport 输出。
- `frontend/房间消息窗.ts`
  保持只表达消息视口和抛应用意图。阶段 3 接 TanStack Virtual 时，它只消费消息窗口/virtual range，不拥有消息顺序真相。
- `frontend/房间实时编排.ts`
  阶段 5 移出 `reconcileMessages` 与 optimistic 合并真相，只保留 socket 生命周期、订阅、控制面错误转译。
- `frontend/房间恢复编排.ts`
  阶段 5 改为调用 `房间时间线.ts` 合并 snapshot/delta，不再依赖 realtime 编排提供合并真相。
- `frontend/媒体/媒体查看器.ts`
  阶段 4 收口 `MediaViewerActor` 语义并替换 GLightbox 路径。Vidstack/PhotoSwipe 只做 UI 轮子，WebTorrent 仍是源 provider。
- `frontend/媒体/媒体播放.ts`
  保持媒体源选择和 WebTorrent/anchor fallback 语义，不把播放器 UI 逻辑写进来。
- `frontend/入口.ts`
  阶段 6 注册 App Shell service worker，并继续保留 `media-sw` 的 WebTorrent 角色边界。
- `frontend/build.mjs`
  阶段 6 接 Workbox 构建注入，不把实时/API 数据打进 precache。
- `frontend/package.json`
  阶段 3/4/6 分别引入必要成熟依赖；每次引入前查官方文档并写入本阶段提交。
