# 真浏览器中的应用完整实施总计划 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在不破坏现有聊天、媒体、上传、查看器、离线补发与 P2P 主链功能的前提下，把 `koko` Web 前端按同一条施工主线完整升级为“真浏览器中的应用”，直到 `BrowserAppPlatform -> AppRuntime -> 唯一 owner -> 壳层快照 -> 生命周期/恢复/预算/更新/P2P 长期平面` 全部落地，并满足 `docs/superpowers/specs/2026-04-12-前端浏览器应用化-design.md`、`docs/superpowers/specs/2026-04-17-真浏览器中的应用宪法与防漂移治理-design.md`、`docs/superpowers/specs/2026-04-16-Web大视频上传秒开播放与P2P协同主链-design.md` 的完成标准。

**Architecture:** 这是总计划，不是某一个 phase 的局部切片。执行顺序必须严格从平台信号收口开始，逐步建立生命周期、视口、时间线、实时会话、媒体运行时、协作分发、缓存更新、多上下文和预算 owner，并在每个 phase 内同步退场旧入口。现有 `frontend/平台/**` 继续只做浏览器 adapter，现有 Lit 壳继续只做 shell，前端运行时真相统一收口到 `AppRuntime + xstate actors + 薄应用编排`，不再让组件、DOM 观察器、socket 回调、SW 消息各自宣布真相。

**Tech Stack:** TypeScript, Lit 3, xstate 5, socket.io-client, Workbox, idb, @tanstack/lit-virtual, Video.js v10, hls.js, p2p-media-loader-hlsjs, WebTorrent, Vitest

## Scope / Program Rules

1. 这份文档是“完整总计划”；执行完这里的全部 task，相关 spec 才算完成。现有 `docs/superpowers/plans/2026-04-17-真浏览器中的应用Phase0-1实施计划.md` 只是本总计划的第一施工切片，不是完成定义。
2. 这是同一条连续施工主线，不允许做成“先挑一个自己喜欢的 phase 改改看”。执行顺序固定：`Task 1 -> Task 2 -> ... -> Task 9`。
3. 每个 task 都必须满足：先补失败测试，再做最小实现，再跑目标回归，再清退旧入口，再提交。任何“新层上线但旧真相继续活着”的实现一律视为未完成。
4. 保持当前 `main` 工作区，不另开分支或 worktree；每个 task 结束后都要 fresh verify、`git status --short` 复核、中文 commit。
5. 修改代码文件后必须执行 graphify 重建：`python3 -c "from graphify.watch import _rebuild_code; from pathlib import Path; _rebuild_code(Path('.'))"`。
6. 不允许为“浏览器应用化”手搓第二套播放器、第二套虚拟列表、第二套缓存框架、第二套 transport 核心；只允许在现有成熟轮子之上补 owner、contract 和薄适配层。
7. 任何 phase 如需新增文件，优先贴近现有边界：`frontend/平台/**` 只放浏览器能力 adapter，`frontend/媒体/**` 只放媒体与协作分发 owner/adapter，`frontend/*运行时.ts` 或 `frontend/*内核.ts` 只放前端运行时真相 owner。
8. 任何阶段都不能破坏现有业务功能和“满血能力”：聊天、进房、恢复、分页、查看器、上传、离线补发、P2P 协作分发都必须继续通过已有或新增测试证明。

## Completion Gates

整份 spec 只有同时满足下面 10 条才算完成：

1. `BrowserAppPlatform` 成为唯一浏览器全局能力组合根。
2. `AppRuntime` 成为唯一前端运行时事件入口，浏览器信号不再直接裁决真相。
3. `AppLifecycle / RoomViewport / RoomTimeline / RealtimeSession / MediaRuntime / AssetDistribution / CacheUpdate / MultiContext` 各有唯一 owner。
4. `聊天壳.ts`、`房间消息窗.ts`、`房间滚动器.ts` 退化为 shell 或 DOM adapter，不再持有运行时真相。
5. `hidden / pagehide / pageshow / freeze / resume / controllerchange / offline / online / 多标签切换` 都有正式恢复协议。
6. 预算制度正式落地：`activeVideoCount / autoplayOwnerCount / activeSwarmCount / inflight* / hiddenHeavyTaskCount / longTaskCount / storageUsage / updatePendingDuration` 可观测且可治理。
7. `0-24 小时` 与 `24 小时后` 的媒体/P2P 主链裁决在前端行为上被严格执行：`HLS + p2p-media-loader` 只服务冷备窗口，删源后长期正式平面只有 `WebTorrent`。
8. 静态守门、测试守门和构建前置检查能挡住未来越层直接碰浏览器全局能力和第二真相 owner。
9. 旧入口全部退场：新 owner 上线后，旧的直连平台监听、直 patch 状态、直摸 `navigator.storage`、直摸 `BroadcastChannel`、直摸 `serviceWorker` 路径不再继续活着。
10. 全量验证通过：目标前端单测、集成测试、`pnpm --dir frontend typecheck`、`pnpm --dir frontend build`、graphify 重建、`git status --short` 复核均为绿色。

## Program Composition

总计划被拆成 9 个连续 task：

1. `Task 1`：执行并收口现有 `Phase0/1` 子计划，建立宪法门禁、`AppRuntime` 平台桥接、`AppLifecycleActor`、存储收口与静态检查。
2. `Task 2`：建立 `RoomViewportActor`，把滚动、未读、历史分页、贴底跟随从 DOM/controller 收回前端运行时真相。
3. `Task 3`：建立 `RoomTimelineActor`，把 snapshot/history/realtime merge 收口到唯一时间线 owner。
4. `Task 4`：建立 `RealtimeSessionActor`，把 socket 生命周期、重连、补洞、后台补发编排收口。
5. `Task 5`：建立 `MediaRuntimeActor + AssetDistributionActor`，把时间线预览、自动播、查看器、协作分发 owner 全部拉直。
6. `Task 6`：正式落地预算制度和后台降载协议。
7. `Task 7`：完成缓存/更新/多上下文治理，堵住 SW、存储驱逐、旧 bundle 混跑和多标签打架。
8. `Task 8`：把前端媒体播放和 P2P 行为彻底对齐 `24 小时` 主链 spec。
9. `Task 9`：做总集成、全量验证、graphify 更新和收尾提交。

任何 task 未完成，都不允许宣布 spec 完成。

## File Structure / Responsibility Map

### Existing files that remain but must shrink to clear boundaries

- `frontend/应用运行时.ts`
  - 保留为唯一前端事件入口；继续变薄，只做 `Browser/DOM/Viewer/SW/Socket signal -> AppCommand` 翻译。
- `frontend/聊天应用内核.ts`
  - 保留为应用编排根；只组合 owner、投影快照、触发副作用；不再自己订阅平台或直 patch 各 slice。
- `frontend/聊天壳.ts`
  - 保留为 Lit shell；只绑定输入、消费快照、调用稳定 runtime 入口。
- `frontend/状态.ts`
  - 继续作为壳层快照定义，但只保留壳层投影，不再作为多 owner 共写真相仓库。
- `frontend/房间滚动器.ts`
  - 退化成纯 DOM scroll adapter / ReactiveController；不再负责阅读、未读、分页真相。
- `frontend/阅读推进编排.ts`
  - 退化成 viewport actor 的应用编排辅助；不再自己持有最终滚动/已读真相。
- `frontend/房间时间线.ts`
  - 保留纯 reducer / merge helper；不再允许被多个入口直接调用。
- `frontend/房间实时编排.ts`
  - 退化成 realtime actor 的 adapter；不再直接宣布恢复、连接或新消息真相。
- `frontend/房间恢复编排.ts`
  - 退化成恢复用例编排；不再偷偷持有时间线/实时 owner。
- `frontend/聊天媒体编排.ts`
  - 退化成媒体应用编排；媒体真相 owner 下沉到专门 runtime。
- `frontend/媒体/媒体协作分发.ts`
  - 退化成 WebTorrent/browser adapter；不再自己碰浏览器持久化全局，也不再兼任长期播放主链裁决。
- `frontend/平台/浏览器应用平台.ts`
  - 保留为 BrowserAppPlatform 组合根。
- `frontend/平台/生命周期运行时.ts`
  - 保留为浏览器 lifecycle adapter，不直接等价于应用生命周期真相。
- `frontend/平台/服务工作线程运行时.ts`
  - 保留为 SW adapter，统一注册、waiting、controllerchange、message。
- `frontend/平台/多上下文运行时.ts`
  - 保留为 BroadcastChannel adapter，不拥有业务或运行时 owner。
- `frontend/平台/存储运行时.ts`
  - 保留为本地存储/配额/持久化入口，不拥有业务语义。
- `frontend/app-sw.ts`, `frontend/media-sw.ts`
  - 保留 service worker 逻辑，但必须受更新协议与主上下文治理。
