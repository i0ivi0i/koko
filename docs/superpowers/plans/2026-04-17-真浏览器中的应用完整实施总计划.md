# 真浏览器中的应用完整实施总计划 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 基于当前已经落地的 `BrowserAppPlatform / AppRuntime / AppLifecycle / RoomViewport / RoomTimeline / RealtimeSession / MediaRuntime / AssetDistribution / CacheUpdate` 第一波骨架，把 `koko` Web 前端连续施工到真正收口完成，直到浏览器信号、运行时真相、缓存更新、多上下文、媒体/P2P 主链和旧入口退场全部闭环。

**Architecture:** 这份计划从当前真实源码出发，不从零假设重建，也不重复创建已经存在的 actor 或 runtime。实施主线只有一条：先用失败测试锁死当前剩余风险，再把 `媒体协作分发全局 singleton`、`聊天媒体编排热点`、`缓存/更新/多上下文协议`、`聊天应用内核残留平行真相` 逐段收口，并且每一段都同步删除旧路径，禁止“新层上线但旧真相继续活着”。

**Tech Stack:** TypeScript, Lit 3, xstate 5, socket.io-client, Workbox, idb, Video.js v10, hls.js, p2p-media-loader-hlsjs, WebTorrent, Vitest

## Program Rules

1. 这份文档是当前唯一有效的总计划；不再新建第二份同主题总计划。
2. 所有 task 都从当前真实源码出发，不允许再把已存在文件写成 “Create”，也不允许把未做工作标成已完成。
3. 默认优先在现有文件内压缩职责，只有在明确减少热点复杂度、减少转发层、避免跨层混杂时，才允许新增文件。
4. 绝不重复手搓成熟轮子：继续复用 `xstate`、`Workbox`、`idb`、`Video.js`、`hls.js`、`p2p-media-loader-hlsjs`、`WebTorrent`、`socket.io-client`。
5. 新 owner 上线时，旧路径必须在同一 task 里删除、退化为纯翻译，或明确改成只读投影；不允许双活。
6. 目录名不是边界本身，行为才是。若“移动文件”只是制造纯转发层或格式化噪音，则优先保持原路径、缩行为边界。
7. 每个 task 都必须走 TDD：先写失败测试，再做最小实现，再跑目标回归，再复核工作树，再中文提交。
8. 每次改代码都要运行与该风险面直接对应的验证命令；整份计划结束前必须运行全量验证。
9. 修改代码文件后必须重建 graphify：

```bash
python3 -c "from graphify.watch import _rebuild_code; from pathlib import Path; _rebuild_code(Path('.'))"
```

10. 默认在当前 `main` 工作区执行，不另开分支、不另开 worktree。

## File Structure / Responsibility Map

- `frontend/应用运行时.ts`
  - 保留为唯一浏览器信号桥接入口，只做 event translation，不吞业务语义。
- `frontend/聊天应用内核.ts`

  - 保留为协作分发 owner，但必须去掉模块级 singleton，改成实例化端口。

  - 保留为平台组合根，只组合 adapter/runtimes，不吸收聊天业务判断。
- `frontend/平台/缓存更新运行时.ts`
  - 保留现有路径，继续承担更新与加速层状态 owner；不额外造第二套 cache manager。

  - 保留现有路径，继续承担主上下文/通知去重运行时真相；不额外造第二套 BroadcastChannel 框架。
- `frontend/平台/存储运行时.ts`
  - 保留为浏览器存储 adapter；只发出稳定事件，不冒充业务 ready。
- `frontend/房间恢复编排.ts`

## Completion Gates

整份计划只有全部满足才算完成：

1. `BrowserAppPlatform -> AppRuntime -> owner -> shell snapshot` 成为唯一主链。
2. `frontend/媒体/资产协作分发运行时.ts` 不再通过模块级 singleton 暗中持有全局真相。
3. `frontend/聊天媒体编排.ts` 不再同时持有查看器、自动播、缓存、协作分发和平行会话真相。
4. `frontend/聊天应用内核.ts` 不再共写运行时真相，只装配和投影。
5. `controllerchange / update ready / storage eviction / primary context handoff / hidden / frozen / offline` 都经过统一运行时协议。
6. 旧路径全部退场：无第二入口、无第二真相 owner、无越层浏览器全局访问、无 dead helper。
7. `0-24 小时` 与 `24 小时后` 的媒体/P2P 主链行为符合现有 spec，不再模糊。
8. 静态守门、单测、类型检查、构建、graphify 都通过。
