# 适配层拆分瘦身 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把 `src/适配.rs` 恢复成真正的 PostgreSQL adapter 装配壳，并把房间阅读、消息事件、媒体附件三类持久化职责拆到 3 个明确 owner 文件。

**Architecture:** `Pg仓储` 继续作为稳定仓储表面，对外 `impl 仓储端口 / Realtime仓储端口` 不变；内部改成“薄转发 + 三个 owner 模块”。拆分顺序严格遵守“先媒体，再房间阅读，最后消息事件”，每一轮都先用编译级或测试级红灯锁住边界，再迁实现、删旧代码、跑回归。

**Tech Stack:** Rust 2021, SQLx, Tokio, PostgreSQL, cargo test, cargo clippy

### Ownership Lock

- `src/媒体附件适配.rs` 只拥有附件快照、待完成附件、运输授权、运输回执、协作分发、流媒体清单、附件可读内容、冷源清理
- `src/房间阅读适配.rs` 只拥有会话/房间/成员资格、房间快照、历史、增量、阅读位置与后台房间查询
- `src/消息事件适配.rs` 只拥有消息事件落库、幂等回查、消息页组装、附件引用校验和发送者投影
- `src/适配.rs` 只保留 `Pg仓储` 壳、运行时桥、事务入口和少量真正共享的基座

- 不允许新增 `utils/common/helpers/sql_helper/service/manager`
