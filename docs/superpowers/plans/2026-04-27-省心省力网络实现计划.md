# 省心省力网络实现计划 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 按 [2026-04-27-省心省力网络 spec](/E:/koko/docs/superpowers/specs/2026-04-27-%E7%9C%81%E5%BF%83%E7%9C%81%E5%8A%9B%E7%BD%91%E7%BB%9C.md) 把 `koko` 的网络真相彻底收口成“浏览器只认一个 HTTPS 入口”，同时保证未来正式部署到 Linux 公网服务器时不依赖 `run.ps1`、`https.ps1`、Windows 证书流程或本地 Caddy 特判。

**Architecture:** 这轮不再围绕“某个端口能不能通”打补丁，而是同时收口 3 条 owner 链：浏览器公开入口 owner、Tus 上传下一跳 owner、WebTorrent announce owner。Rust 后端和同源代理负责唯一公开契约，前端只负责把相对路径收口成当前 origin 的绝对地址，本地 Windows 脚本只允许做开发适配层，禁止再发明产品真相。

**Tech Stack:** Rust, Axum, Reqwest, TypeScript, Vitest, PowerShell, Caddy（仅本地 HTTPS 适配）, `tusd`, `bittorrent-tracker`, graphify.

## 0. 实施前先锁死 4 条红线

后续每个任务都必须同时服从下面 4 条：

1. **禁止** 再把 `127.0.0.1`、`localhost`、`:1081`、`:7072`、`:7073` 暴露给浏览器契约。
2. **禁止** 让 `run.ps1` / `https.ps1` / Windows 本地证书流程成为正式 Linux 部署前置条件。
3. **禁止** 出现“页面入口是 HTTPS，但上传或 announce 下一跳掉回 HTTP / 内部地址”的双真相。
4. **禁止** 为了兼容旧逻辑，让浏览器同一能力同时接受“相对路径一套、内部绝对地址一套、Windows 特判再一套”。

## 1. 文件地图与 owner 锁定

### 1.1 浏览器公开契约 owner

- `src/媒体上传外壳.rs`
  - `prepare` 返回值、`/files` 同源 Tus 代理、`Location` 改写入口。
- `src/媒体协作分发.rs`
  - 同源 announce 路径常量和分发表面归一。
- `src/外壳.rs`
  - `/api/swarm/announce` 同源代理与浏览器可见入口约束。
- `src/总装.rs`
  - 启动配置读取，决定哪些环境变量属于公开入口真相，哪些只属于内部 sidecar 通信。

### 1.2 前端消费 owner

- `frontend/传输.ts`
  - 平台组合根，只负责把相对路径收口成当前 origin。
- `frontend/媒体/适配/媒体HTTP接口.ts`
  - `prepareMediaUpload`、`loadMediaLocator` 的地址归一和 `AbortSignal` 透传。
- `frontend/平台/传输运行时.ts`
  - 浏览器侧唯一 `baseUrl` owner，禁止页面/功能各自猜地址。

## 4. Task 3: 收口 Tus 同源代理，禁止 `Location` 再泄漏内部地址

- [ ] **Step 1: 写代理层红测**

在现有 Rust / PowerShell 测试里补下面这组失败用例：

```rust
assert_eq!(location, "https://im.example.com/files/upload-1");
assert_ne!(location, "http://127.0.0.1:1081/files/upload-1");
```

重点：

1. 浏览器通过 `/files` 进入时，返回的 `Location` 必须回到当前浏览器入口。
2. **禁止** 再出现 `http://.../files/...`、`127.0.0.1:1081/files/...`。

- [ ] **Step 2: 在 Rust 代理层改写 `Location`**

目标实现：

```rust
if header_name == LOCATION {
    rewritten = 根据当前请求公开入口改写到浏览器可见地址(...);
}
```

要求：

1. 代理层只改写浏览器可见 `Location`，不改 sidecar 内部路由。
2. forwarded 头存在时优先信任公网协议/authority。
3. 没有 forwarded 头时，以当前请求 host/proto 推导浏览器下一跳。
4. **禁止** 再把 `tusd` 原始 header 生吞活剥转给浏览器。

- [ ] **Step 3: 本地 Win11 启动器只做开发适配**

要求：

1. `run.ps1` 在启用本地 HTTPS bootstrap 时，默认把 `TUSD_BEHIND_PROXY` 打开，避免本地 HTTPS 测试天然跑偏。
2. `run.ps1` / `https.ps1` 的日志和入口摘要必须优先打印 `https://局域网IP/`，**禁止** 再把内部 Tus URL 冒充成给测试用户的入口。
3. 这些改动都只能属于本地开发适配层，**禁止** 反向变成 Linux 正式部署依赖。
