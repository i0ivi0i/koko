# 阅读锚点与未读恢复 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让 `koko` 为同一内部身份保存房间阅读锚点，进入房间时围绕第一条未读恢复首屏，显示未读分隔条，并在上滑补历史时稳定守住当前视口。

**Architecture:** 后端新增“匿名内部身份 + 房间 + last_read_event_position”这一用户级真相，由应用层统一裁决、仓储层持久化、快照接口返回稳定恢复语义。前端不再自己猜未读起点，只消费后端给出的锚点和首屏消息，并把“首屏落点”和“上滑前插补偿”拆成两套独立机制；`socketioxide / socket.io` 继续只负责后续增量，不承担阅读进度真相。

**Tech Stack:** Rust, axum, socketioxide, sqlx/PostgreSQL, TypeScript, Lit, socket.io-client, Vitest, Tokio

### Structural decisions locked by this plan

- 阅读真相主键
  - 固定使用 `anonymous_identity_id + room_id`，不使用 `session_id + room_id`
- 房间快照恢复语义
  - 不再是“最近 55 条”；改成“围绕第一条未读的一屏消息”
- 首屏恢复锚点
  - 后端直接返回 `first_unread_event_position`，前端不得自行猜测
- 阅读推进
  - 单独冷路径写入，不和“进房”“建连”“订阅成功”混用
- realtime 边界
  - 继续只做 `latest_event_position` 之后的权威增量，不替代阅读锚点或历史恢复

### Suggested snapshot shape to preserve throughout implementation

Rust / HTTP / TS 三层保持同一语义：

```text
{
  room_id,
  latest_event_position,
  last_read_event_position | null,
  first_unread_event_position | null,
  snapshot_messages,
  has_more_before
}
```

说明：
- `last_read_event_position`
  - 表示该身份上次已读到哪里
- `first_unread_event_position`
  - 表示首屏里哪条消息前要画“未读消息”分隔条
- `snapshot_messages`
  - 围绕未读起点返回的一屏消息，仍按 `event_position ASC`
- `has_more_before`
  - 告诉前端当前首屏上方是否还有更早历史，避免首屏上方阈值一碰就误判

```sql
CREATE TABLE IF NOT EXISTS room_read_anchors (
    id BIGSERIAL PRIMARY KEY,
    anonymous_identity_id BIGINT NOT NULL REFERENCES anonymous_identities(id) ON DELETE CASCADE,
    room_id BIGINT NOT NULL REFERENCES rooms(id) ON DELETE CASCADE,
    last_read_event_position BIGINT NOT NULL CHECK (last_read_event_position >= 0),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    UNIQUE (anonymous_identity_id, room_id)
);
```

实现约束：
- 这里保存的是“身份级阅读真相”，不是页面滚动位置
- `0` 表示“还没有读过任何已成立事件”
- 不额外引入 `session_id` 列，避免真相漂移

- 默认执行顺序：Task 1 -> Task 6，不跳步。
- 每个任务都必须走 `失败测试 -> 运行确认失败 -> 最小实现 -> 运行确认通过 -> commit`。
- 中文注释重点解释四件事：
  - 为什么阅读真相绑在匿名内部身份而不是 session
  - 为什么进入房间和推进已读必须分离
  - 为什么前端不能自己猜第一条未读
  - 为什么历史前插补偿和首屏定位必须是两套逻辑
- 如果实现中想把“搜索 / 按时间跳转 / 已读人数 / 在线状态 / 虚拟列表”一起做，立刻停下；全部超出本轮范围。
- `socketioxide / socket.io` 继续是 realtime adapter，不得趁机再造一套“阅读状态 socket 协议”。
- 若实现中发现 `snapshot_messages` 改名会引发大面积噪音，也可以保留旧字段名 `recent_messages`，但必须在计划执行前先做一次命名决断，并保持 Rust / HTTP / TS / tests 四处同步；不要半新半旧并存。
