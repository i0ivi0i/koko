# 高清视频自动播放加速 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让同一个 `canonical video` 真正承担时间线预览、自动播放、查看器播放、协作补齐和后续做种，并把“滑过即继续补齐、群友越多越快”的效果落成受测试保护的代码。

**Architecture:** 后端继续只守单文件资产与分发表面，不再偷偷复活长期 still/poster；前端继续围绕现有 `媒体运行时Actor + 媒体播放 resolver + WebTorrent runtime + 视频预览/缓存` 收口成一条媒体 owner 链。`Video.js v10` 只消费已裁决的 source，`WebTorrent` 负责流与 store，预览和自动播都不得引入第二资产或第二来源真相。

**Tech Stack:** Rust/Axum/SQLx、TypeScript/Lit/XState、WebTorrent 浏览器运行时、Video.js v10 壳、Vitest、Chrome DevTools smoke

## File Map

- `src/媒体上传外壳.rs`: 上传 complete 热路径；锁住“新视频只入 canonical、不抽静态封面”。
- `src/媒体附件适配.rs`: 附件读写与受控内容变体选择；当前仍保留 `thumbnail_storage_key` / `preview` 兼容分支。
- `src/媒体资产外壳.rs`: locator / snapshot / preview_asset / thumbnail_url 投影；是“有没有 still_url” 的主要出入口。
- `src/契约.rs`: 共享 contract；锁住跨端可以看到什么，避免壳层表面继续泄露旧 still 语义。
- `frontend/媒体/视频预览.ts`: 从同一媒体源抓取预览；当前已走 `requestVideoFrameCallback()` + `readyState` fallback。
- `frontend/媒体/预览缓存.ts`: 运行时预览缓存；保证预览不依赖 autoplay owner 才存在。
- `frontend/媒体/媒体协作分发.ts`: WebTorrent client / server / torrent store / streamURL 主表面。
- `frontend/媒体/资产协作分发运行时.ts`: swarm 会话、consumer lease、complete 事件与 session 生命周期。
- `frontend/媒体/媒体缓存.ts`: 完整资产 retain / restore；是“滑走后继续补齐并记住 complete” 的持久化入口。
- `frontend/媒体/媒体播放.ts`: viewer / inline autoplay 共用的播放裁决入口。
- `frontend/媒体运行时.ts`: inline autoplay owner、viewer 打开状态、heavy work policy 和预算投影。
- `frontend/媒体/消息视频自动播编排.ts`: 自动播候选只裁决“谁是唯一 owner”，不拥有播放源与媒体真相。
- `frontend/房间消息窗.ts`: `IntersectionObserver` 候选收集与时间线卡片节点复用。
- `frontend/聊天媒体编排.ts`: 旧壳层编排残留；必须持续变薄，不能继续自持第二份媒体真相。
- `frontend/tests/视频预览测试.spec.ts`: 锁住 RVFC / readyState / fallback 行为。
- `frontend/tests/房间消息窗媒体查看器测试.spec.ts`: 锁住时间线卡片、同一 `video` 节点复用、无 poster 路径和 observer 候选逻辑。
- `frontend/tests/媒体协作分发测试.spec.ts`: 锁住 WebTorrent runtime、torrent store 和 complete 事件。
- `frontend/tests/媒体缓存测试.spec.ts`: 锁住 complete retain / restore。
- `frontend/tests/媒体运行时测试.spec.ts`: 锁住 inline autoplay owner、viewer 抢占、lifecycle 策略。
- `frontend/tests/媒体播放测试.spec.ts`: 锁住 swarm 主链裁决与“不回退到 original”。
- `frontend/tests/聊天应用内核测试.spec.ts`: 锁住“正式查看器、inline autoplay、协作分发预算变化都来自同一条媒体 owner 链”。
- `tests/媒体上传测试/complete.rs`: 锁住 complete 后视频不再写静态封面。
- `tests/媒体上传测试/单文件主链.rs`: 锁住视频 canonical 单文件主链。
- `tests/协作分发测试/投影一致性.rs`: 锁住 legacy still 兼容投影，不让兼容路径误伤旧数据。
