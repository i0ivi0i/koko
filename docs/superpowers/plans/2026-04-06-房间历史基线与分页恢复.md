# 房间历史基线与分页恢复 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让 `koko` 在首次进房、刷新回房时直接显示最近 `55` 条消息，并支持上滑继续加载更早消息，同时保证历史分页与 realtime 新消息合流时不重复、不乱序。

**Architecture:** 继续坚持“后端给权威房间基线，前端只消费稳定快照并派生滚动体验”。后端把现有房间快照升级成“房间信息 + 最近 55 条消息”，再补一条独立的历史分页冷路径；前端在房间壳里统一合并三段来源：首屏基线、上滑历史页、realtime 新消息。`socketioxide / socket.io` 继续只负责连接和广播，不手搓第二套 realtime 基础设施。

**Tech Stack:** Rust, axum, socketioxide, sqlx/PostgreSQL, TypeScript, Lit, socket.io-client, Vitest, Tokio

### Concrete route and contract decisions locked by this plan

- `/api/rooms/{room_id}/snapshot?session_id={session_id}`
  - 返回 `{ room_id, latest_event_position, recent_messages }`
- `/api/rooms/{room_id}/history?session_id={session_id}&before_event_position={n}&limit=55`
  - 返回 `{ room_id, messages }`
- `recent_messages` 和 `messages`
  - 固定按 `event_position` 升序，也就是老的在前、新的在后
- 历史分页默认值
  - `limit = 55`
- 去重主锚点
  - 默认以 `message_id` 为主；若当前代码需要同时保留 `client_message_id` 以替换 optimistic 消息，可以双锚点并存，但排序锚点始终是 `event_position`
