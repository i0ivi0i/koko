# 聊天恢复与展示语义收口 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让 `koko` 的 Web 聊天壳在刷新恢复、普通聊天视图展示、以及冷路径成员门禁上与 spec 完全对齐，不再暴露内部锚点，也不再让恢复链路和权限判断漂移。

**Architecture:** 继续坚持“后端裁决真相，前端只保存恢复锚点和派生展示模型”。Rust 后端统一收口 `snapshot / events / subscribe` 的成员资格与错误语义；前端只保存 `koko_device_anonymous_token` 与 `koko_current_room_id`，用 bootstrap 返回的权威 `session_id` 驱动快照、补洞和 realtime 连接。展示层从稳定事实派生“我发的/别人发的”气泡，不把 `session_id`、`event_position` 倒灌进 UI。

**Tech Stack:** Rust, axum, socketioxide, sqlx/PostgreSQL, TypeScript, Lit, socket.io-client, Vitest, Tokio, tracing
