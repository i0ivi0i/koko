# 全项目播放无预览图预热真相收口 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 从代码逻辑根因上修掉“新人首次进房没有预览图时，滚到视频 owner 会先看到类似占位/卡一下再自动播”的链路，让消息流在没有作者预览图的前提下，仍然能靠同一条正式 swarm 字节主链给出丝滑预览与自动播放。

**Architecture:** 这次不再接受“消息窗自己拿 playback.src 现场冒充预览底板”的双真相。真正要收口的是两层：第一层是 `视频预览协作` 不能把 `missing_source` 锁死在旧版本上，必须在同一条 swarm 正式播放源真正到位后重试并生成 runtime preview；第二层是 `房间消息窗` 必须拆开“正式 canonical 播放源”和“可见预览底板来源”，禁止在 `missing_source` 时继续把冷 paused `<video>` 当成 hidden-stage cover。

**Tech Stack:** TypeScript, Lit, XState actor runtime, Video.js v10 shell, Vitest, Happy DOM, Playwright CLI 真实浏览器冒烟

---

## 0. 这轮根因必须先写死

真实冒烟已经证明，这次的占位感不是旧 owner 退场，不是 `owner = null`，也不是首帧 guard 图片闪出来。

真正根因是下面这条冲突链：

1. `视频预览协作` 已经把某附件判成 `missing_source`
2. 但同一轮里，媒体会话后来又拿到了正式 `swarm playback.src`
3. 由于 `missing_source` 被“当前 sourceVersion”阻断，预览协作没有重试，仍然停在 `missing_source`
4. 与此同时，消息窗却继续把这条正式 `swarm playback.src` 当成时间线 preview `<video>` 的 `src`
5. 然后 `hidden stage` 又把这张 `currentTime = 0` 的冷 paused `<video>` 认成“已经有可见预览底板”
6. 用户肉眼看到的就变成：先像占位一样僵一拍，再切成自动播

一句话：

**当前系统嘴上说“没有 preview source”，实际又偷拿 formal playback source 当可见 preview 底板。**

这轮必须同时修掉：

1. `missing_source` 不再阻断“同一条 swarm 正式源已经到位后的重试”
2. 消息窗不再把 `missing_source` 状态下的 formal playback source 当可见 preview 底板

## 1. 文件边界

### 需要修改

- `frontend/媒体/壳层/视频预览协作.ts`
  - 收口 `missing_source` 阻断条件；当同 attachment 的正式 `swarm` 预览候选已经出现时，允许在同一 sourceVersion 内重新解析 preview。
- `frontend/聊天媒体编排.ts`
  - 收口 `读取视频预览候选播放源` 与 `onSnapshotChange` 触发关系，确保 preview 协作真正能看见“同一条正式 swarm 主链已就绪”这个事实。
- `frontend/房间消息窗.ts`
  - 拆开“formal canonical 播放源”和“可见 preview 底板源”；禁止 `missing_source` + `无 poster` + `无 runtime preview` 时继续拿 `playback.src` 现场顶 cover。

### 需要修改的测试

- `frontend/tests/聊天媒体编排测试.spec.ts`
  - 新增“同一 sourceVersion 下先 missing_source、后正式 swarm playback 到位时，preview 协作必须重试并转 ready”红测。
- `frontend/tests/房间消息窗媒体查看器测试.spec.ts`
  - 新增“`missing_source` 时禁止把 cold playback `<video>` 当 hidden-stage cover”红测；
  - 收口旧用例中默认允许“无 poster 直接拿 playback.src 当首帧预览”的口径。

### 不动的边界

- 不改 `WebTorrent` 正式播放主链，不回退 original/canonical 冷源
- 不引入第二颗正式播放器
- 不把消息窗变成第二个 preview owner
- 不把 runtime preview 缓存真相下放到 DOM 观察结果

## 7. 计划自审

这份计划已经按 6 条做过自审：

1. **有没有只修表面？**  
   没有。计划直接改的是 preview 协作的缺源阻断逻辑和消息窗的 source 真相拆分。

2. **有没有放宽成冷源 fallback？**  
   没有。计划明确禁止回退 original/canonical 冷源；允许重试的只有同一条 swarm 正式源。

3. **有没有再让消息窗当 preview owner？**  
   没有。消息窗只消费 preview 真相，不再自己把 `playback.src` 冒充成 preview 真相。

4. **会不会破坏单一正式播放器？**  
   不会。`ownerCanonicalVideoSrc` 仍只服务唯一播放器 owner 接管；这轮只是禁止它再兼做可见 preview 底板。

5. **有没有覆盖 newcomer 真场景，而不是只看老测试？**  
   有。计划明确要求用全新 session 重跑 `1234b` 的首次进房滚动链路。

6. **会不会把“无预览图”偷换成“继续用占位图糊过去”？**  
   不会。计划要消灭的是 `missing_source` 和冷 paused preview 底板的冲突，不是再加一张新的占位图。
