# 上传吞吐专项优化 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在不重做 `Uppy + Tus + Rustus` 主链的前提下，提升单大视频与多文件并发上传吞吐，同时把前端 `transporting / processing` 体验态拆开，并补齐 request id 与 Rustus 参数接线。

**Architecture:** 保持 `prepare -> tus transport -> post-finish -> complete -> ready` 作为唯一真相路径，吞吐增强只发生在 adapter / shell。前端通过“草稿状态拆分 + 两种 uploader profile + 诊断增强”提升吞吐与可观测性；后端与 launcher 只负责 header 透传、日志衔接和 sidecar 参数接线，不修改领域模型与业务 ready 语义。

**Tech Stack:** TypeScript + Vitest + Uppy/Tus；Rust + Axum + Tokio；PowerShell 启动脚本；Rustus hooks。

## Notes For The Implementer

- `chunkSize` 继续保持默认，不要手痒去切小块。
- `parallelUploads` 只给大视频 profile，不能全量默认开。
- `request id` 只做诊断关联，不进领域模型、不进数据库真相。
- `upload-success` 必须先进入 `processing`，不能直接跳 `ready`。
- 如果某个 touched file 在实现时已经继续漂移，先重读，再动 patch。
