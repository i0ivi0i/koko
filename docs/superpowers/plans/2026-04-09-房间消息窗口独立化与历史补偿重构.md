# 房间消息窗口独立化与历史补偿重构 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把房间页拆成“稳定房间壳 + 独立消息窗口”两个边界，并把历史分页补偿从总高度差值升级成锚点恢复，消除首次上滑补历史时的闪烁抽搐。

**Architecture:** 保留现有 `聊天壳 -> 恢复编排 / realtime 编排 / 阅读推进编排 / 房间滚动器` 的整体结构，不改后端契约，不把历史加载语义倒灌进房间内核。新增一个 `房间消息窗` 组件承接消息视口内部 UI 和交互边界；`房间滚动器.ts` 升级为“锚点恢复优先、高度差值兜底”的滚动补偿执行器；`阅读推进编排.ts` 只负责请求历史页和驱动补偿，不负责 DOM 细节。

**Tech Stack:** Lit 3、自定义元素、TypeScript、Vitest、happy-dom、现有前端编排器与滚动控制器

- 不要在 `房间内核.ts` 里新增 `historyLoading` 之类的局部滚动状态；这会把消息窗口边界重新污染回房间壳。

- `房间消息窗.ts` 优先复用现有 DOM id / data attribute，减少测试和滚动查询的震荡。
- 如果新组件使用 shadow DOM，先明确 `聊天壳.ts` 如何安全拿到滚动容器与消息节点，再继续实现；不要临时用跨层脆弱选择器硬穿透。
- 任一阶段如果发现必须修改 `frontend/房间内核.ts` 或后端 Rust 文件，先停下复核 spec 与 plan，不要边做边扩 scope。
