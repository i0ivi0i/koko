# 后端外壳 DDD 与 Unix 收口拆分 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在不改变现有 HTTP / realtime 业务语义的前提下，把 [src/外壳.rs](/E:/koko/src/外壳.rs) 中混住的房间 HTTP、后台 HTTP、realtime 热路径拆回 3 个专用壳层子模块，让总壳只保留装配、共享状态和少量公共转码。

**Architecture:** 继续保持当前后端的 DDD 分层不变：`domain/usecase/contract` 仍掌握业务真相，`adapter` 仍掌握持久化与 IO，`shell` 只做协议解码、错误转码与命名空间接线。本次不把新模块暴露成 crate 顶层 public API，而是在 [src/外壳.rs](/E:/koko/src/外壳.rs) 内通过私有子模块方式收口，避免 API 面额外膨胀。

**Tech Stack:** Rust 2021、Axum 0.8、Tokio、SQLx 0.8、socketioxide 0.18、Serde、tower-http、现有 `cargo test` / `cargo clippy`

## Implementation Notes

### 1. 为什么用私有子模块而不是扩 crate 顶层模块

因为这次拆的是 `shell` 内部 adapter 闭环，不是新增需要对外稳定暴露的公共模块。  
用 [src/外壳.rs](/E:/koko/src/外壳.rs) 的私有子模块方式能同时满足：

1. 文件拆开
2. 不扩 public API
3. 新模块能直接复用 `super::` 公共 helper
4. 保持 DDD 边界不外泄

### 2. 为什么 realtime 必须最后拆

因为它最容易引入“看起来没问题、实际前端恢复链已经坏了”的软性 bug。  
HTTP 冷路径即使出问题，通常更快暴露；realtime 的时序和控制面分流一旦漂移，往往是运行一阵后才显现。

### 3. 哪些变化一律视为超 scope

以下任一行为出现，都应停止执行并回到设计确认：

1. 想顺手改 socket payload
2. 想顺手改错误码文本或 code
3. 想顺手把 admin token 机制升级
4. 想顺手改 SQL 或 repo 接口
