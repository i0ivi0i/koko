# 群聊图片实时收发第一阶段 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在统一附件平台地基下，完成“文字 + 多张图片”的群聊实时收发、图片持久化、图片展示与断线恢复兼容。

**Architecture:** 保持现有单一消息主链不变，把“纯文本消息”升级成“文本 + 附件引用”的统一消息模型；第一阶段只点亮 `image` 附件。后端继续坚持 `domain / usecase / contract / adapter / shell` 分层，前端继续坚持 `transport / orchestrator / presenter / shell` 分层；文件上传走 HTTP，消息成立走现有 realtime 权威事件链。

**Tech Stack:** Rust、Axum Multipart、SQLx、PostgreSQL、socketioxide、object_store、image、infer、kamadak-exif、TypeScript、Lit、Uppy、Vitest、cargo test、pnpm test

```sql
CREATE TABLE IF NOT EXISTS attachments (
    id BIGSERIAL PRIMARY KEY,
    attachment_id TEXT NOT NULL UNIQUE,
    owner_anonymous_identity_id BIGINT NOT NULL REFERENCES anonymous_identities(id),
    kind TEXT NOT NULL,
    mime_type TEXT NOT NULL,
    byte_size BIGINT NOT NULL,
    width INTEGER,
    height INTEGER,
    storage_key TEXT NOT NULL,
    thumbnail_storage_key TEXT,
    status TEXT NOT NULL,
    committed_at TIMESTAMPTZ,
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE TABLE IF NOT EXISTS message_attachment_refs (
    message_id TEXT NOT NULL REFERENCES messages(message_id) ON DELETE CASCADE,
    attachment_id BIGINT NOT NULL REFERENCES attachments(id),
    sort_order INTEGER NOT NULL,
    display_role TEXT NOT NULL,
    PRIMARY KEY (message_id, attachment_id),
    UNIQUE (message_id, sort_order)
);
```
