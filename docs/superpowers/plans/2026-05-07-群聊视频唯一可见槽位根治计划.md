# 群聊视频唯一可见槽位根治计划 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把群聊消息流视频的自动播放进入、离开、滑回、查看器接管、全屏归位，统一收口成“同一颗 `Video.js v10` live player + 同一条正式视频链 + 同一个可见槽位”的单一真相，实现快滑、慢滑、大跳转、resize 下都无黑闪、无抽搐、无首帧跳。

**Architecture:** 本轮不再追加“快滑模式”“大跳转模式”之类的真相分支，而是删除多表面补洞思路：`poster / preview / frozen / canonical` 不再是并列可见 owner，只允许同一个可见槽位在任一时刻承载一种表面。`frontend/媒体/全局唯一播放器.ts` 继续是唯一 `Video.js` 生命周期 owner；`frontend/媒体/全局丝滑自动播.ts` 升格为单一可见槽位协议；消息窗渲染层只投影协议结果，不再自己判断谁先露；冻结桥接从 `webp data URL` 升级成内存帧对象，不再让编码图片成为第二视觉真相。

**Tech Stack:** TypeScript, Lit, Video.js v10, WebTorrent, Vitest, Playwright CLI, Chrome DevTools CLI, browser-trace, `requestVideoFrameCallback`, `ImageBitmap`, `OffscreenCanvas`, `MediaCapabilities`, `getVideoPlaybackQuality`

## 0. 为什么前几次一直修不干净

这不是阈值问题，也不是“再补一个 guard”就会好的问题。前几次之所以一直修不干净，是因为底层还存在这四件互相打架的事实：

1. `preview` 自己会试图证明“我已经能继续露给用户看”。
2. `frozen frame` 会在 owner 退场时顶一拍。
3. `visible canonical host` 会在同一时间提前挂载。
4. `hidden stage canonical` 还在后台追 `src/currentTime/rVFC`。

于是快滑/大跳转时会反复出现：

1. 旧卡还没停稳，新的 host 已经挂出来。
2. 新的 canonical 还没提交正确帧，旧的 preview 或 frozen 又被撤了。
3. 同一颗 live player 的 `currentTime` 已经是对的，但渲染层先露了错误时间点或黑底。
4. 渲染层和播放器层各自都在“好心帮忙”，但没有一个唯一 owner 真正决定“这一拍用户该看什么”。

**这份计划的核心不是“再修一个黑闪点”，而是把上面四股真相收口成一个协议。**

## 1. 正式裁决

### 1.1 唯一真相

同一条视频在消息流里任何时刻都只允许存在：

1. 一颗正式 `Video.js v10` live player
2. 一个可见槽位
3. 一个可选 bridge frame

其中：

1. `Video.js v10` 继续是唯一 live player / container 真相。
2. `bridge frame` 只能是同一颗正式视频刚刚提交过的一帧投影。
3. `poster / preview / frozen / canonical` 只能是**同一可见槽位的不同投影**，不能成为并列 owner。

### 1.2 明确禁止

本轮必须明确禁止：

1. 新增“快滑模式”“大跳转模式”“慢滑模式”等第二套业务真相。
2. 继续把 `webp data URL` 冻结帧当成正式桥接真相。
3. 继续让 `视频附件渲染.ts` 同时裁决 `poster / preview / frozen / canonical` 谁露给用户。
4. 继续让 `scroll / resize / candidate sorting` 直接触发同 owner 的 `seek / play / remount`。
5. 继续把“浏览器说 ready 了”当成“用户已经看见正确帧了”。

### 1.3 本轮要收口成什么

唯一允许成立的协议是：

1. **hidden_preparing**：唯一 live player 在后台追正确 `src/currentTime`，可见槽位只允许 bridge 占位。
2. **bridge_visible**：可见槽位由 bridge frame 顶住，但 bridge 必须来自同一颗 live player 的已提交帧。
3. **live_visible**：只有当 live player 已拿到**对齐续播点的 committed frame** 时，才允许揭帘。
4. **retiring_bridge**：离开时先锁住最后一帧 bridge，再释放重播放 owner；不能先掉回 `poster`。

一句话：**任何时刻只有一个可见槽位；可见槽位要么是 bridge，要么是 live canonical，不允许两者并列抢位。**

### 1.4 官方依据

这份计划不是自创播放器哲学，直接依赖下面几条官方事实：

1. `requestVideoFrameCallback()` 提供的是“视频帧已经提交给 compositor”的证据，不是单纯 `canplay`。
2. `requestVideoFrameCallback()` 是 best effort，可能晚一个 v-sync，所以 reveal gate 不能只吃“回调到了”的布尔值。
3. `drawImage(video, ...)`、`ImageBitmap`、`OffscreenCanvas.transferToImageBitmap()`、`VideoFrame` 都是浏览器官方支持的同源视频帧投影路径。
4. `Video.js` 负责的是播放器壳和生命周期，不负责“群聊卡片在快滑时哪一层可以先露给用户”的业务真相。

执行时如果实现与这些事实冲突，按实现错误处理，不按“体验差一点也能接受”处理。

### 4.1 新协议草图

```ts
export type 视频可见槽位阶段 =
  | "cold"
  | "hidden_preparing"
  | "bridge_visible"
  | "live_visible"
  | "retiring_bridge"
  | "viewer_handoff"
  | "fullscreen_handoff"
  | "retired";

  | { kind: "none" }
  | { kind: "bridge"; src: string; currentTime: number; capturedAt: number }
  | { kind: "live_committed"; src: string; currentTime: number; presentedFrames: number };

export interface 视频可见槽位输入 {
  source: { src: string | null };
  savedPosition: { src: string; currentTime: number; updatedAt: number } | null;
  frameEvidence: 视频桥接帧证据;
  dom: {
    sourceMatches: boolean;
    previewCommitted: boolean;
    canonicalCommitted: boolean;
    visibleHostMounted: boolean;
    stageHostMounted: boolean;
  };
  intent: {
    viewerOpen: boolean;
    fullscreen: boolean;
    retiringOwner: boolean;
    retire: boolean;
  };
}

export interface 视频可见槽位决策 {
  phase: 视频可见槽位阶段;
  targetCurrentTime: number;
  revealLive: boolean;
  keepBridgeVisible: boolean;
  allowPreviewVisible: boolean;
}
```

`frontend/房间消息窗/视频桥接帧.ts` 至少要接近下面这种形状：

```ts
export interface 视频桥接帧 {
  src: string;
  currentTime: number;
  capturedAt: number;

  dispose(): void;
}

export function 从已提交视频帧创建桥接帧(video: HTMLVideoElement): Promise<视频桥接帧>;
export function 渲染桥接帧到画布(
  frame: 视频桥接帧,
  canvas: HTMLCanvasElement | OffscreenCanvas
): void;
```
