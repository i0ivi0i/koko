# 群聊视频自动播放全链路收口 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` when the host explicitly allows subagents, otherwise use `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把 `docs/superpowers/specs/群聊视频禁止事项.md` 落成可执行工程路径：自动播放不再靠可见换壳、兜底图和零散 guard 硬扛，而是用唯一 owner、稳定 `VideoSurfaceSlot`、唯一 Video.js live player、WebTorrent 正式源和 Socket.IO 控制面边界一起保证群聊视频丝滑续播。

**Architecture:** 先做事实归属和真实浏览器反证，再只按证据修改真正破坏不变量的层。`媒体运行时.ts` 拥有 pending/settled owner 与释放规则，`全局丝滑自动播.ts` 只产出播放连续性阶段，`附件渲染.ts` 只投影稳定表面槽，`全局唯一播放器.ts` 只管理唯一 live player 的事务迁移，WebTorrent 继续是正式视频字节主链，socketioxide/Socket.IO 继续只承载已认证控制事件和权威领域事件。执行原则是第一性原理：删掉“可见换壳”这个问题源，只保留一个稳定可见槽和一个可迁移 live 解码能力。

**Tech Stack:** TypeScript 6.0.2、Lit 3、XState 5、Video.js v10、WebTorrent 2.8、Socket.IO client 4.8、Rust socketioxide 0.18、Vitest、`chrome-devtools-cli`、`playwright-cli`、`browser-trace`、Serena、graphify。

## 2. 核心不变量

这些不变量比任何单个实现细节更高优先级：

1. 同一时间线自动播只能有一个 settled owner。
2. 同一时间只能有一个正式 Video.js live player/container。
3. 同一卡片只能投影一个稳定 `VideoSurfaceSlot`。
4. 滑走后保留的是同一播放会话的 frame evidence 和位置，不是另起一条可见主壳。
5. 滑回续播必须从运行时 owner、保存位置、正式 WebTorrent source 和帧证据恢复。
6. 查看器、全屏和时间线共用同一播放会话，不开第二套业务状态机。
7. 正式视频源只来自 WebTorrent whole-file swarm，不引入 HLS/DASH、原文件直链、range、CDN 或 UI 旁路快源。
8. Socket.IO / socketioxide 只传控制事件和权威领域事件，不传大视频字节，不拥有播放 owner。
9. 浏览器验收不是截图验收，必须反向校验 owner、phase、DOM mutation、player count、source 和帧提交序列。

- `viewerHandoff` and `fullscreenHandoff` keep timeline slot stable while live player migrates.
- `retired` is the only phase that may clear slot after release.
