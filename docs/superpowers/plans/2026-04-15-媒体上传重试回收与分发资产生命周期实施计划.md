# 媒体上传重试回收与分发资产生命周期 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把当前媒体上传链从“模糊 retry + 成功后冷源清理”推进到“明确 `resume / restart / abandon / gc` 语义、原片秒删、`mezzanine` 24 小时回退、分发资产长期保留”的单一生命周期真相。

**Architecture:** 保持 `prepare -> rustus transport -> post-finish -> complete -> distribution_ready` 作为唯一业务成功路径，不改 `Uppy + Tus + Rustus + ffmpeg + Shaka Packager + WebTorrent` 轮子组合。新增内容只放在现有 `usecase / 适配 / 壳层 / 前端媒体发布器` 接缝上：应用层统一裁决 `resume / restart / 删除资格 / 清理资格`，adapter 只负责执行副作用并回写事实，前端只表达意图与展示状态。

**Tech Stack:** TypeScript + Vitest；Rust + Axum + Tokio + SQLx；PostgreSQL migration SQL；PowerShell 启动/验证脚本；Rustus hooks；ffmpeg / ffprobe / Shaka Packager。
