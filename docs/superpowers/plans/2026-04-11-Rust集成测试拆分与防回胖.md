# Rust 集成测试拆分与防回胖 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把 `tests/集成测试.rs` 按能力域拆成稳定的多个集成测试入口与热点子模块，在不改变业务语义的前提下提升 Rust TDD 体验，并用软约束防止未来重新回胖。

**Architecture:** 这次执行被视为“测试结构重组”，不是业务重写。保留 `领域测试.rs / 用例测试.rs / 集成测试层` 三层测试分工；将原 `集成测试.rs` 中的测试按能力域迁入新的顶层 `xxx测试.rs`，对持续增长的热点能力使用“顶层入口 + 同名目录子模块”，通用 helper 收口到 `tests/测试支撑/`，且 helper 只负责协议/环境/日志/fixture 支撑，不承载业务断言。

**Tech Stack:** Rust integration tests、Tokio test harness、Axum `Router::oneshot`、`serial_test`、现有 PostgreSQL/SQLx 测试路径、PowerShell、`cargo test`

这份 plan 只覆盖：

- `tests/` 下 Rust 集成测试目录重组；

- 文件头边界注释与旧 `集成测试.rs` 退役；

- `src/` 下业务实现调整；
- 新测试框架引入；
- `serial` 大规模治理；

- 额外功能开发。

## 模块约定

### 顶层测试文件的基本形状

所有新的顶层测试文件统一使用下面的组织方式：

```rust
mod 测试支撑;

use 测试支撑::{
    环境::*,
    http::*,
    媒体::*,
    日志::*,
};

/// 这里说明“负责什么 / 不负责什么”。
```

### 热点子模块的基本形状

对于会继续增长的热点，顶层文件通过 `#[path]` 显式挂载子模块，避免 Rust 默认去错误路径找模块：

```rust
mod 测试支撑;

#[path = "房间接口测试/快照.rs"]
mod 快照;
#[path = "房间接口测试/增量事件.rs"]
mod 增量事件;
#[path = "房间接口测试/阅读推进.rs"]
mod 阅读推进;
#[path = "房间接口测试/历史分页.rs"]
mod 历史分页;
```

### `测试支撑` 的禁止事项

`tests/测试支撑/*` 只允许：

- 构造请求
- 读取响应
- 环境管理
- 日志采集
- fixture 准备
- 通用断言壳

禁止放：

- “谁应该成功 / 谁应该失败”的业务判断
- 把多个业务步骤封成高语义万能场景器
- 媒体/房间/消息/协作分发的业务成立裁决

## 执行总原则

- 每一刀先跑当前现有测试，建立安全网，再移动代码。
- 结构重组阶段不修改 `src/` 业务代码；一旦必须改业务代码，立即停下并单独立项。
- 每完成一个能力文件，就执行该能力文件测试；全部完成后跑全量 Rust 测试。
- 每个任务结束都提交一次，提交说明用中文，聚焦本任务的结构变化。
- 任意时刻都不要同时进行“目录重排 + 业务逻辑顺手优化”。
