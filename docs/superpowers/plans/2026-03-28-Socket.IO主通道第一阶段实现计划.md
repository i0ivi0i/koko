# Socket.IO 主通道第一阶段实现计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在不破坏 `core` 领域语义的前提下，用 `socketioxide` 替换当前手搓 realtime 层，并让 `web` 从 raw WebSocket 客户端迁到 Socket.IO 客户端 adapter。

**Architecture:** 本计划只覆盖设计文档里的阶段 A，不直接做“全系统去 HTTP 化”。做法是先固定 canonical 命令/事件语义，再把 `server/src/ws.rs` 收敛为 `socketioxide` adapter，最后把 `web/src/client.rs` 从 raw WS 改成 Socket.IO client adapter，同时保留 HTTP 冷路径和现有核心领域调用。

**Tech Stack:** Rust workspace, axum, tokio, socketioxide, serde, Dioxus, wasm32, JavaScript Socket.IO client adapter, PostgreSQL, sqlx

---

## 范围说明

本计划只做第一阶段：

- 停止继续手搓房间 realtime 广播
- 用成熟 Socket.IO 轮子接管主 realtime 通道
- 保护 DDD 边界，让 `core` 不认识 transport
- 保留 HTTP 冷路径，避免一次性把全部交互塞进 socket

本计划不做：

- 一次性删除全部 HTTP 接口
- 一次性把所有查询都事件化
- 一次性重写前端状态管理
- 为了抽象漂亮而新增一堆 `.rs` 文件

## 完成定义

当以下条件同时成立时，本计划可以视为完成：

- `server/src/ws.rs` 不再继续维护手搓 raw WS 房间广播
- 服务端 realtime 主通道改由 `socketioxide` 承担
- 前端不再直接使用原生 raw WebSocket 对接房间 realtime
- `core` 没有引入任何 Socket.IO 或浏览器 transport 细节
- HTTP 冷路径仍然可用
- 端到端 smoke 使用官方 Socket.IO client，而不是继续自己拼协议

## 执行备注

- 这份计划故意只覆盖阶段 A
- 阶段 B，也就是把更多主业务交互从 HTTP 收敛到 Socket.IO，应单独写下一份计划
- 整个执行过程中，若出现“为了适配 Socket.IO 而把业务规则搬进前端或 handler”的倾向，应立即停下并回到 DDD 边界检查
