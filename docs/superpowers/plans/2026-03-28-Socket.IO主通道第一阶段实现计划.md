# Socket.IO 主通道第一阶段实现计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在不破坏 `core` 领域语义的前提下，用 `socketioxide` 作为唯一主 realtime 通道，并让浏览器前端通过官方 `socket.io-client` 的极薄 JS bridge 接入。

**Architecture:** 本计划只覆盖设计文档里的阶段 A，不直接做“全系统去 HTTP 化”。做法是先固定 canonical 命令/事件语义，再把 `server/src/ws.rs` 收敛为 `socketioxide` adapter，同时把 `web/src/client.rs` 的 realtime 入口改成“Rust 应用适配层 + 极薄 JS transport bridge”，HTTP 冷路径继续保留。

**Tech Stack:** Rust workspace, axum, tokio, socketioxide, serde, Dioxus, wasm-bindgen, socket.io-client, JavaScript transport bridge, PostgreSQL, sqlx

---

## 范围说明

本计划只做第一阶段：

- 停止继续手搓房间 realtime 广播
- 用成熟 Socket.IO 轮子接管主 realtime 通道
- 保护 DDD 边界，让 `core` 不认识 transport
- 保留 HTTP 冷路径，避免一次性把全部交互塞进 socket

本计划不做：

- 一次性删除全部 HTTP 接口
- 一次性把所有查询都事件化
- 一次性重写前端状态管理
- 为了抽象漂亮而新增一堆 `.rs` 文件

### Task 3: 接入官方浏览器 Socket.IO client，并把 JS 约束在极薄 transport bridge

**Files:**
- Modify: `web/Cargo.toml`
- Modify: `web/src/app.rs`
- Modify: `web/src/client.rs`
- Modify: `web/src/main.rs`
- Create: `web/js/socketio-bridge.js`

- [ ] **Step 1: 先补前端失败测试，锁定 Rust 应用适配层不感知 JS 细节**

在 `web/src/client.rs` 现有测试基础上新增最小断言：

- Rust 侧仍只认 `ClientRealtimeCommand` / `ServerRealtimeEvent`
- HTTP 只继续承接 `bootstrap / history / members / governance` 等冷路径
- JS bridge 加载失败时，`JoinedRoomClient` 只暴露 transport 不可用，不把异常扩散到 UI 层

- [ ] **Step 2: 运行测试并确认先失败**

Run: `cargo test -p koko-web client`

Expected: FAIL，提示当前实现仍围绕 raw WS，而不是官方 Socket.IO bridge。

- [ ] **Step 3: 写极薄 JS bridge，并让 Rust 适配层调用它**

要求：

- `web/js/socketio-bridge.js` 只负责 `connect / emit / on / close`
- JS bridge 不保存业务状态，不做权限判断，不做成员资格判断
- `web/src/client.rs` 继续作为前端应用适配层，对上暴露稳定的 Rust API
- `web/src/app.rs` 调用形状尽量稳定，不让 UI 直接碰 JS transport 细节
- 优先使用官方推荐的浏览器 client 形态；不再维护前端 raw WS 主链路
- 不再把 HTTP 写成聊天主交互的通用 fallback，只保留冷路径职责

## 完成定义

当以下条件同时成立时，本计划可以视为完成：

- `server/src/ws.rs` 不再继续维护手搓 raw WS 房间广播
- 服务端 realtime 主通道改由 `socketioxide` 承担
- 前端主 realtime 通道改为官方 `socket.io-client`，且 JS 只承担极薄 transport bridge
- `core` 没有引入任何 Socket.IO 或浏览器 transport 细节
- HTTP 冷路径仍然可用
- `/socket.io` 握手、入房、发消息、房间广播链路有真实集成验证
- 没有把业务语义、权限真相、成员资格真相搬进 JS bridge

## 执行备注

- 这份计划故意只覆盖阶段 A
- 阶段 B，也就是继续扩大服务端 `socketioxide` 的承担范围，应单独写下一份计划
- 浏览器端不再把 pure Rust raw WS 视为推荐主路线
- 整个执行过程中，若出现“为了适配 Socket.IO 而把业务规则搬进前端、把 UI 状态搬进 JS、或把业务规则搬进 handler”的倾向，应立即停下并回到 DDD 边界检查
