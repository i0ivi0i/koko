# 前端首页群列表与双态控制台 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把当前“进房页 + 房间页”的网页式前端，重构成“同壳双态”的 IM 应用空间：默认是群列表首页，底部控制台固定贴底，进入房间后主舞台切到消息流，控制台无声切成消息发送态。

**Architecture:** 继续保留 [frontend/聊天壳.ts](/E:/koko/frontend/聊天壳.ts) 作为唯一主壳，不新增第二个首页壳，不改后端契约。新增的真状态只有“历史房间列表”，`shellView / consoleMode` 只允许作为基于 `roomId` 与恢复结果的只读派生语义；点击历史房间与手动输入房间号都必须继续汇入现有 `joinRoom()` / `enterRoomFromSnapshot()` 主链。

**Tech Stack:** Lit 3、自定义元素、TypeScript、Vitest、happy-dom、本地 `localStorage` 适配层

export function 派生壳主舞台模式(input: {
  bootstrapState: "booting" | "ready";
  roomId: string;
}): "boot" | "home" | "room" {
  if (input.bootstrapState === "booting") return "boot";
  return input.roomId ? "room" : "home";
}

export function 派生控制台模式(input: {
  bootstrapState: "booting" | "ready";
  roomId: string;
}): "join" | "message" | "hidden" {
  if (input.bootstrapState === "booting") return "hidden";
  return input.roomId ? "message" : "join";
}
