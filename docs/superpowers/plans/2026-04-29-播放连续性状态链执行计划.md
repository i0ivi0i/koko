# 播放连续性状态链 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` when the host explicitly allows subagents, otherwise use `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把 `2026-04-25-项目视频播放要求.md` 里的播放连续性状态链落成代码：高速/慢速滚动、离屏暂停、回屏续播、查看器升格、全屏接管和退出归位都走同一条会话状态转换，不再由 `房间消息窗.ts` 分散裁决。

**Architecture:** 不新增第二播放器、不新增第二 WebTorrent 字节链、不扩大成全局事件总线。新增 `frontend/媒体/全局丝滑自动播.ts` 只做一个小 XState owner：接收 owner、source、保存位置、DOM ready、查看器/全屏意图和宿主存在性事实，输出表面决策；这颗状态机必须真实驱动阶段裁决，禁止只声明 `createMachine` 后 `void` 掉当装饰。`媒体运行时.ts` 继续拥有播放位置，`全局唯一播放器.ts` 继续拥有唯一 player/container，`消息视频自动播编排.ts` 继续拥有候选排序。

**Tech Stack:** TypeScript 6.0.2、Lit 3、XState 5、Video.js v10、Vitest、`chrome-devtools-cli`、`playwright-cli`。

- [ ] **Step 3: 最小实现状态链**

在 `frontend/媒体/全局丝滑自动播.ts` 创建类型和决策函数：

```ts
import { createMachine } from "xstate";

export type 播放连续性表面 = "timeline" | "viewer" | "fullscreen";

export type 播放连续性输入 = {
  attachmentId: string;
  ownerAttachmentId: string | null;
  surface: 播放连续性表面;
  source: { src: string | null };
  savedPosition: { src: string; currentTime: number; updatedAt: number } | null;
  dom: { previewReadyState: number; canonicalReadyState: number; sourceMatches: boolean };
  host: { exists: boolean; hasStableFrame: boolean };
  intent: { viewerOpen: boolean; fullscreen: boolean };
};

export type 播放连续性决策 =
  | { kind: "cold_placeholder"; reason: "no_source" | "no_position" | "host_missing" }
  | { kind: "hold_frame"; src: string | null }
  | { kind: "hidden_handoff"; targetCurrentTime: number }
  | { kind: "visible_canonical"; targetCurrentTime: number }
  | { kind: "viewer_handoff"; targetCurrentTime: number }
  | { kind: "fullscreen_handoff"; targetCurrentTime: number }
  | { kind: "retire" };

const 播放连续性机 = createMachine({
  id: "globalSmoothAutoplay",
  initial: "idle",
  states: {
    idle: {},
    preheating: {},
    hiddenHandoff: {},
    visible: {},
    pausedFrame: {},
    viewerHandoff: {},
    fullscreenHandoff: {},
    retired: {},
  },
});
```

实现 `判定播放连续性表面(input)` 时只做纯判断，不访问 DOM。注意：

- 禁止写成“声明 `播放连续性机`，然后 `void 播放连续性机`，真正分支仍散在 if/else 里”的装饰性状态机。
- `判定播放连续性表面(input)` 的分支名必须和 `播放连续性机` 的阶段名一一对应，测试至少覆盖 `hiddenHandoff / visible / viewerHandoff / fullscreenHandoff / pausedFrame / retired`。
- 如果某个阶段暂时没有生产入口，测试里也要明确证明它为什么不进入，而不是让死状态长期存在。
