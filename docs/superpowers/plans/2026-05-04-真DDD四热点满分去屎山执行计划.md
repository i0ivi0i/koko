# 真DDD六缺口满分收口执行计划 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把 `koko` 从“门禁全绿但仍有 6 条真缺口”的状态，推进到可证明的 `DDD: 满分 / 六边形边界: 满分 / 简洁度: 满分`，并让这个结论在新鲜验证、真实浏览器烟测和图谱复核下站得住。

**Architecture:** 不再新写第二套 spec，而是继续服从 [真DDD领域驱动重构铁律](../specs/2026-05-01-真DDD领域驱动重构铁律.md) 和 [真DDD满分验收规格](../specs/2026-05-02-真DDD满分验收规格.md)。这轮执行顺序固定为：先让“假满分”自动失败，再按 `身份 bootstrap 真相归位 -> 共享适配枢纽拆口 -> 生产公开表面测试 seam 清退 -> 前端剩余热点收薄 -> 第二入口与迁移壳扫尾 -> 全量验证` 的顺序做 TDD 收口。核心原则只有一条：业务真相回到 `domain/application`，适配层只持久化和翻译，测试 seam 只能存在于测试支架，不能存在于生产 API。

**Tech Stack:** Rust、Tokio、Axum、SQLx、socketioxide、TypeScript、Lit、Vitest、Video.js v10、WebTorrent、Playwright CLI、browser-trace、graphify、Serena MCP。

## 0. 当前事实

### 0.1 当前真正还在的 6 条缺口

这轮新鲜审查已经证明：仓库不是屎山，但**还不能诚实地叫“满分真 DDD / 满分洋葱”**。当前真正还在的 6 条缺口是：

1. [src/身份/应用.rs](E:/koko/src/身份/应用.rs) 仍把 `引导匿名身份` 做成极薄转发，文件内还明写“真正的业务真相仍在仓储端口后面”。
2. [src/适配/mod.rs](E:/koko/src/适配/mod.rs) 的 `Pg仓储::引导匿名身份` 仍在决定匿名身份标识、展示花名投影、会话标识和 bootstrap 幂等恢复，身份 bootstrap 真相依旧是 persistence-owned。
3. [src/适配/mod.rs](E:/koko/src/适配/mod.rs) 仍是跨身份 / 房间 / 消息 / 媒体 / realtime 的 PostgreSQL 共享适配枢纽。
4. [frontend/应用根/聊天应用内核.ts](E:/koko/frontend/应用根/聊天应用内核.ts) 仍是偏厚的前端 app root。
5. [frontend/媒体/媒体发布.ts](E:/koko/frontend/媒体/媒体发布.ts) 仍是媒体发布厨房水槽， [frontend/房间消息窗/时间线媒体基类.ts](E:/koko/frontend/房间消息窗/时间线媒体基类.ts) 仍是继承大桶。
6. 生产前端公开表面仍混入测试 seam：`setTransportForTest`、`setKernelForTest`、`设置媒体播放器供测试`、`读取房间滚动器供测试`、`写入视口调试状态供测试` 之类符号还活在生产源码里，而不是只活在 `frontend/tests/common` 支架里。

### 0.2 当前绿灯不够说明什么

当前已确认通过：

- `cargo test --test 架构边界守卫`
- `cargo clippy --all-targets -- -D warnings`
- `pnpm --dir frontend exec tsc --noEmit --noUnusedLocals --noUnusedParameters`
- `node scripts/check-full-architecture-completion.mjs`
- `node scripts/check-frontend-architecture-fitness.mjs`

这些命令证明的是：

1. 旧门禁记录过的缺口大多已被清掉。
2. 低级死代码、死导入、过期迁移壳已经少很多。
3. 当前行为没有明显坏掉。

它们**不能**自动推出：

1. 身份 bootstrap 真相已经回到身份上下文 owner。
2. `Pg仓储` 已经退出跨上下文总枢纽。
3. 测试 seam 已经退出生产公开表面。
4. `聊天应用内核`、`媒体发布器`、`时间线媒体基类` 已经达到终态。

### 0.3 当前权威文档之间已经打架

当前仍存在显式冲突：

1. [真DDD满分验收规格](../specs/2026-05-02-真DDD满分验收规格.md) 还写着“当前代码已通过本规格”。
2. [真DDD重构完成矩阵](../reports/2026-05-01-真DDD重构完成矩阵.md) 还写着 `DDD: 满分 / 六边形边界: 满分 / 简洁度: 满分`。
3. 但这轮代码审查已经确认上面 6 条缺口仍然成立。

所以这轮执行的**第一件事**不是先拆代码，而是先让“错误完成态”自动失败，避免后面再出现：

1. 代码还有缺口。
2. 门禁没抓到。
3. 文档继续写成已完成。

### 0.4 当前计划本身也已经落后于工作树

旧版“四热点”计划现在还有一个新问题：它自己已经不是最新代码树的准确地图了。例如：

1. `frontend/应用根/聊天应用命令路由.ts` 已经存在，不再是待新建文件。
2. `frontend/应用根/聊天房间视图退场.ts` 已经存在，不再是待新建文件。
3. 旧计划完全漏掉了“身份 bootstrap 真相归位”和“生产公开表面测试 seam 清退”这两条真缺口。

因此这次不是在旧计划上补两条备注，而是要**按当前工作树重写真正可执行的计划**。

## 1. 本轮 scope 冻结

### 1.1 必做范围

1. 把当前“已满分完成”降回 `验证中`，并让 6 条真实缺口被门禁直接打红。
2. 把 `引导匿名身份` 的业务真相从 `Pg仓储` 收回身份上下文，让应用层拥有 bootstrap 决策，适配层只做持久化与幂等冲突翻译。
3. 按 bounded context 切最小应用端口，拆掉 `Pg仓储` / `Pg媒体仓储` / `PgRealtime仓储` 这组共享适配枢纽。
4. 清掉生产公开表面的测试 seam，把 `setTransportForTest` / `setKernelForTest` / `供测试` 族能力迁回 `frontend/tests/common` 支架。
5. 把 [frontend/应用根/聊天应用内核.ts](E:/koko/frontend/应用根/聊天应用内核.ts) 继续收成真正的 thin app root。
6. 把 [frontend/媒体/媒体发布.ts](E:/koko/frontend/媒体/媒体发布.ts) 收成 published surface + wiring。
7. 用组合协作替换 [frontend/房间消息窗/时间线媒体基类.ts](E:/koko/frontend/房间消息窗/时间线媒体基类.ts)。
8. 清理执行过程中产生的第二入口、一次转发壳、迁移壳和宽公开表面。
9. 重跑全量验证、`graphify update .`、`1234b` 双浏览器真实烟测，并且只有全部 fresh 通过后，才允许把完成矩阵恢复为满分。

### 1.2 非目标

1. 不再新写一篇真DDD spec；权威 spec 仍是现有两篇。
2. 不做无依据的全仓大改名。
3. 不引入新框架、新服务拆分、新事件总线、新插件体系。
4. 不把“真 DDD”误解成“文件越碎越高级”。
5. 不把任何结构债留给“以后再说”；每一刀都必须删旧路、删旧壳、删旧 seam。

### 1.3 成功标准

执行完成后，必须同时满足：

1. [真DDD重构完成矩阵](../reports/2026-05-01-真DDD重构完成矩阵.md) 能诚实恢复为满分，不再和当前代码冲突。
2. [src/身份/应用.rs](E:/koko/src/身份/应用.rs) 不再是“仓储后面才有真相”的薄转发，身份 bootstrap 决策明确属于身份上下文 owner。
3. [src/适配/mod.rs](E:/koko/src/适配/mod.rs) 不再承载跨上下文宽转发 impl；它只能是 PostgreSQL 基座 / 构造 / 装配。
4. `Pg仓储::引导匿名身份` 不再生成匿名身份、花名投影或会话锚点。
5. 生产前端源码里不再出现 `setTransportForTest`、`setKernelForTest`、`设置媒体播放器供测试`、`设置媒体查看器供测试`、`设置媒体发布器供测试`、`读取房间滚动器供测试`、`写入视口调试状态供测试` 这类测试 seam。
6. [frontend/应用根/聊天应用内核.ts](E:/koko/frontend/应用根/聊天应用内核.ts) 不再同时编排恢复、实时、阅读推进、平台桥接、媒体和退房收尾细节。
7. [frontend/媒体/媒体发布.ts](E:/koko/frontend/媒体/媒体发布.ts) 不再保留大函数局部子系统；[frontend/房间消息窗/时间线媒体基类.ts](E:/koko/frontend/房间消息窗/时间线媒体基类.ts) 被删除或收成极薄兼容壳并在同轮删除。
8. 本轮新加的门禁在未来能持续抓住这 6 类问题，不能只对这次提交有效。

### 1.4 防漂移规则

1. 禁止把“当前门禁全绿”继续当成“已经满分”的替代说法。
2. 禁止先拆文件、后补真相 owner。
3. 禁止 add-only refactor：任何新 owner、端口、文件、支架落地时，旧转发、旧桥接、旧 seam 必须同步删除或显式退役。
4. 禁止把测试 seam 换个名字继续留在生产文件里。
5. 禁止执行期间把完成矩阵提前写回“已完成”。
6. 如果真实浏览器烟测失败，必须回到 `superpowers:systematic-debugging` / `investigate` / `supxcode` 查状态流和 owner 流，不允许直接补 guard、timeout、兼容分支。
