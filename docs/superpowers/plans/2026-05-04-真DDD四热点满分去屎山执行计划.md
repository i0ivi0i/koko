## 1. 本轮 scope 冻结

### 1.1 必做范围

1. 把当前“已满分完成”降回**验证中**，并让新的 4 个热点能被门禁直接打红。
2. 把后端应用端口从共享大口切成**按上下文最小依赖面**，让 `Pg媒体仓储` / `PgRealtime仓储` 不再被迫实现整块共享口。
3. 把 `src/适配/mod.rs` 收回真正的 PostgreSQL 基座与装配层，不再保留跨上下文宽转发面。
4. 把 `frontend/应用根/聊天应用内核.ts` 收成真正的 thin app root：只保留装配、命令路由、快照读取、dispose。
5. 把 `frontend/媒体/媒体发布.ts` 拆成可单独推理的几个 owner：上传器池、source-hash 预检、草稿发布主链、失败恢复 / restart。
6. 用**组合协作**替换 `frontend/房间消息窗/时间线媒体基类.ts` 的大继承桶。
7. 清理执行过程中产生的第二入口、转发壳、兼容壳和过宽公开面。
8. 重跑全量验证、`graphify update .`、`1234b` 双浏览器真实烟测，并且只有全部新鲜通过后，才允许把完成矩阵恢复为满分。

### 1.2 非目标

1. 不再新写一篇真DDD spec；权威 spec 仍是现有两篇。
2. 不做无依据的全仓大改名。
3. 不引入新框架、新服务拆分、新事件总线、新插件体系。
4. 不把“拆热点”演变成“文件越碎越高级”的形式主义。
5. 不把任何结构债留给“以后再说”；每一刀都必须删旧路、删旧壳、删转发面。

### 1.3 成功标准

执行完成后，必须同时满足：

1. [真DDD重构完成矩阵](../reports/2026-05-01-真DDD重构完成矩阵.md) 能诚实恢复为满分，不再和当前代码冲突。
2. `src/适配/mod.rs` 不再承载宽共享转发 impl；它只能是 PostgreSQL 基座 / 构造 / 装配。
3. `frontend/应用根/聊天应用内核.ts` 不再同时编排恢复、实时、阅读推进、平台桥接、媒体和退房收尾细节。
4. `frontend/媒体/媒体发布.ts` 不再保留一个 `600+` 行局部子系统函数。
5. `frontend/房间消息窗/时间线媒体基类.ts` 被删除，或被压成只剩极薄的 DOM 壳；推荐目标是**删除继承桶**。
6. 本轮新加的门禁在未来能持续抓住这 4 类问题，不能只对这次提交有效。

### 1.4 防漂移规则

1. 禁止把这 4 个热点执行到一半后，又说“这次先不算缺口”。
2. 禁止用“门禁没报错”替代结构判断。
3. 禁止 add-only refactor：任何新 owner、协作者、端口、文件落地时，旧转发、旧桥接、旧基类、旧 helper 必须同步删除或显式退役。
4. 禁止执行期间把完成矩阵提前写回“已完成”。
