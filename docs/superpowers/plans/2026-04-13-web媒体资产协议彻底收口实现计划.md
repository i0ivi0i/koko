# Web 媒体资产协议彻底收口 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 完成 `koko` 的 Web 侧媒体协议收口，让图片/视频都站到统一资产协议上，旧附件直链退成冷备，媒体缓存与协作分发生命周期闭环成立。

**Architecture:** 后端继续把媒体真相收口在共享契约上，但把图片的 `blob_asset` 从 `complete` 扩到 `locator` 与受控资产内容路由，避免图片继续挂在旧附件直链上。前端以资产面而不是裸 `original_url` 驱动播放、查看器与时间线展示；`MediaCacheOwner` 负责 Web 本地完整资产元数据与保留状态，`SwarmRuntime` 负责 acquire/release 与 presence 生命周期，不让热路径 runtime 泄漏成第二真相。

**Tech Stack:** Rust (`axum` / `sqlx` / `object_store` / `ffmpeg` / `shaka-packager`), TypeScript (`Vitest` / Web 平台存储运行时), `WebTorrent`, `Workbox` / `CacheStorage`

---

## Scope Lock

- 这份计划只完成 **Web 当前阶段**。
- `音频 / iOS / Android / Desktop / CLI` 只保留协议准备，不纳入本次完成定义。
- 不新增“大媒体总管”文件；优先在现有 `src/房间外壳.rs`、`frontend/媒体/*`、`frontend/聊天媒体编排.ts` 内收口边界。
- 所有语义改动都先补失败测试，再做最小实现，再验证，再提交。
