> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把当前源码里剩余的 4 个真实缺口全部补齐，让 `docs/superpowers/specs/2026-04-13-跨端志愿者媒体资产与P2P分发协议-design.md` 的 `Web 当前阶段已完成` 在代码层面真正成立。

**Architecture:** 这次不允许靠“下调 spec 口径”过关，必须把 4 个缺口都补成真实实现：图片查看后要进入 `MediaCacheOwner.complete`，图片前端要真正接入 `blob_asset.distribution` 的 backfill/runtime，`blob/full` 和 `blob/original` 要变成两份真实后端资产，原始冷源要有真实 `24 小时` 物理删除执行。实现继续站在现有 Rust `attachment/object_store` 主链、现有 TypeScript `媒体缓存/媒体会话/媒体协作分发` owner 上，不新造第二套媒体核心。

**Tech Stack:** Rust (`axum` / `sqlx` / `object_store` / `image` / `tokio`), TypeScript (`Vitest` / `CacheStorage` / Web runtime), `WebTorrent`, `media-sw`

## Scope Lock

- 本计划只完成 `Web 当前阶段真正完成`。
- `音频 / iOS / Android / Desktop / CLI` 继续延期，但不能再把它们当成掩盖当前 4 个缺口的理由。
- 本计划完成后，必须同时满足这 4 条：
  1. 图片查看后会触发受控补齐，并把完整资产真相写进 `MediaCacheOwner`
  2. 图片前端真正接入 `blob_asset.distribution`，具备 backfill / complete / release 生命周期
  3. `blob/full` 和 `blob/original` 对应两份真实后端资产，不再共用原始冷源字节
  4. 原始冷源 `24 小时` 后会被真实清理，不只是 TTL / availability 文案
- 所有行为改动都走 TDD：先失败测试，再最小实现，再转绿，再提交。

## Design Decisions

- 图片资产的真实分层采用：
  - `storage_key`: 原始冷源对象，只保底 `24 小时`
  - `asset_original_storage_key`: 长期保留的 canonical original 资产
  - `full_storage_key`: 查看器优先消费的 full 资产
  - `thumbnail_storage_key`: preview 资产
- 原始冷源删除后：
  - 顶层 `original_url` 失效
  - `blob_asset.origin.available = false`
  - `blob_asset.original/full/preview` 仍可用
- 图片 P2P/runtime 采用：
  - 首屏仍优先给 preview/full 受控地址
  - 查看器打开后立即启动 background swarm backfill
  - swarm `done` 后写 `MediaCacheOwner.complete`
  - 查看器关闭时 release 当前图片 swarm consumer
- 原始冷源清理采用：
  - 启动时拉起后台循环
  - 以数据库里的 `origin_expires_at` + `origin_deleted_at` 为唯一权威
  - 删除对象成功后写 `origin_deleted_at`
