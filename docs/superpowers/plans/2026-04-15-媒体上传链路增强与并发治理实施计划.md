# 媒体上传链路增强与并发治理 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在不重做上传架构的前提下，把当前 `Uppy + Tus + Rustus + 当前存储驱动` 主链升级为支持 `200MB` 视频、删除错误的前端本地 watchdog，并给后端 `complete` 重活阶段补上并发治理与保护测试。

**Architecture:** 继续把业务真相留在 `prepare / hook / complete / usecase` 主链，只在 adapter / shell 层增强资源治理。前端只负责显式化 Uppy/Tus 参数与草稿状态投影，后端只负责统一大小门禁、装配并发闸门并把重活控制在受限并发里，不新增第二套上传器、协议或“上传总管”。

**Tech Stack:** TypeScript + Vitest + Uppy/Tus；Rust + Axum + Tokio + SQLx + serial_test；PowerShell 启动脚本；Graphify 文档图谱。

```rust
#[tokio::test]
async fn 完成阶段并发闸门会阻止超过额度的重活同时进入() {
    let gate = Arc::new(tokio::sync::Semaphore::new(1));
    let first_permit = gate.clone().acquire_owned().await.expect("permit");

    let entered = Arc::new(tokio::sync::Notify::new());
    let released = Arc::new(tokio::sync::Notify::new());

    let entered_clone = entered.clone();
    let released_clone = released.clone();
    let gate_clone = gate.clone();

    let waiter = tokio::spawn(async move {
        let _permit = gate_clone.acquire_owned().await.expect("second permit");
        entered_clone.notify_one();
        released_clone.notified().await;
    });

    tokio::time::sleep(std::time::Duration::from_millis(50)).await;
    assert!(!waiter.is_finished(), "额度被占满时第二个重活不应直接进入");

    drop(first_permit);
    entered.notified().await;
    released.notify_one();
    waiter.await.expect("waiter should finish");
}
```
