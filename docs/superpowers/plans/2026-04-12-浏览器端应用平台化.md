# 浏览器端应用平台化 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 按 [2026-04-12-浏览器端应用平台化-design.md](E:/koko/docs/superpowers/specs/2026-04-12-浏览器端应用平台化-design.md)，把 `koko` 浏览器端从“聊天壳周围的网页式编排”推进成“平台层 + 业务内核 + 壳层”的浏览器内应用平台。

**Architecture:** 这次不是重写前端，也不是把所有东西一下塞进新框架。先用 `BrowserAppPlatform` 收浏览器运行时真相，再把 `ChatAppKernel / AdminAppKernel` 立成壳层上面的业务内核；每一阶段都必须写清唯一 owner、旧入口退场点、失败测试和验证方式，绝不允许新层叠着旧真相一起活。

**Tech Stack:** TypeScript、Lit、XState、socket.io-client、TanStack Virtual、PhotoSwipe、Vidstack、Workbox、Vitest、esbuild、BroadcastChannel/Notification/Badge/Service Worker/Storage API。

---

## 范围裁决

这份 plan 只服务一个目标：落地 [2026-04-12-浏览器端应用平台化-design.md](E:/koko/docs/superpowers/specs/2026-04-12-浏览器端应用平台化-design.md)。

这份 plan 明确不做：

- 不改后端 Rust 契约形状；
- 不切换 Lit / esbuild / Vitest 技术栈；
- 不重写现有 TanStack Virtual、PhotoSwipe、Vidstack、Workbox 接入；
- 不推翻前一轮“浏览器事件只作信号、先补保护测试、先有薄入口再收 owner”的既有约束；
- 不把平台层做成第二个 `聊天壳.ts`；
- 不再拆成多份 plan；
- 不先画目录、后补退场点。

## 现状现实锁定

写 plan 前必须承认当前真实状态，禁止按旧记忆施工：

- `frontend/应用运行时.ts` 已存在，已经是聊天壳的应用事件薄入口；
- `frontend/房间时间线.ts` 已存在，已经承接消息合流纯逻辑；
- `frontend/app-sw.ts`、`frontend/build.mjs`、`frontend/入口.ts` 已存在，App Shell 预缓存已经接入；
- `frontend/聊天壳.ts` 仍然是当前最大风险点，里面还活着 `updateChat()`、`roomShellState()`、`exitCurrentRoomView()` 这类中心点；
- `frontend/后台壳.ts` 仍然是典型网页式直连 transport；
- `frontend/传输.ts`、`frontend/存储.ts` 还是按“薄适配端口”写的，适合收编进平台层，但不能被包成第二核心。

### 重点修改文件

- `frontend/聊天壳.ts`
  最终只保留渲染、事件翻译、极少量纯 UI 临时态；逐阶段退掉 shared patch 总线职责。
- `frontend/后台壳.ts`
  逐阶段退掉登录、查询、详情直连 transport。
- `frontend/应用运行时.ts`
  保持聊天壳事件入口身份；后续只做 bridge，不偷长成平台。
- `frontend/房间恢复编排.ts`
- `frontend/房间实时编排.ts`
- `frontend/阅读推进编排.ts`
- `frontend/房间滚动器.ts`
- `frontend/房间时间线.ts`
  这些是聊天业务 owner 现有落点；计划中只允许它们朝单一 owner 收紧，不允许重新回壳层。
- `frontend/传输.ts`
  保持 HTTP / Socket adapter 身份；只允许被平台运行时包起来，不允许被壳层直持有。
- `frontend/存储.ts`
  保持本地记忆端口身份；只允许被平台运行时托管。
- `frontend/入口.ts`
  改成平台启动入口，不再散落浏览器 API。
- `frontend/app-sw.ts`
- `frontend/media-sw.ts`
- `frontend/build.mjs`
  只做 Service Worker / 缓存范围的正式收口。

## 施工红线

每个任务开始前都必须回答：

1. 这次收口的是哪个 owner / runtime？
2. 这次要退掉哪个旧入口？
3. 哪条测试会先红？

每个任务完成时都必须确认：

1. 浏览器事件仍然只是信号，不是业务事实；
2. 没有新增共享可变大状态对象；
3. 新 runtime 没开始懂聊天业务；
4. 旧路径已经删掉、压缩，或明确只剩一条下一任务移除线；
5. 没有手搓第二套轮子；
6. `pnpm --dir frontend test`、`pnpm --dir frontend typecheck`、`pnpm --dir frontend build`、`git diff --check` 通过；
7. 改代码后运行 graphify rebuild。
