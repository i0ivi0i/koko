# 全项目播放零闪烁零抽搐 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 消灭群聊消息流里自动播 owner 切换时的可见闪烁与抽搐，让任何播放都不在用户可见表面上发生 `loadstart / seeking / seeked / canplay` 这类换源重整链。

**Architecture:** 这轮不再围绕“owner 会不会先掉成 null”修补，而是直接收口真正根因：目标卡片明明已经有同源暂停预览帧，当前实现却先删掉它，再把唯一 canonical player 拖到可见卡片上现场换源、现场 seek。修复方向是引入**隐藏预热宿主 + 可见揭帘门**：canonical player 先在隐藏宿主完成切源、恢复位置、首帧就绪，再无闪烁迁到目标卡片；目标卡片在揭帘前继续显示自己那张已就绪预览帧，不新增第二颗正式 player，不削弱 WebTorrent 主链。

**Tech Stack:** Lit, TypeScript, Video.js v10 shell, Happy DOM/Vitest, Playwright CLI 冒烟

---

## 0. 先把这轮真因写死

这次要修的不是：

1. 不是 `owner=null` 一拍空窗。
2. 不是 destroy/recreate 第二颗壳。
3. 不是简单的 `poster -> video` 换壳。

这次要修的是真正的可见抽搐链：

1. 目标卡片在成为 owner 前，已经有一张同源暂停预览 `<video>`，而且通常已经恢复到正确续播时间。
2. 一旦它成为 owner，消息窗立刻把这张预览视频撤掉，改渲染 `.message-video-canonical-host`。
3. 全局唯一播放器随后把 canonical player 挂到这个**已经可见**的新卡片上，当场 `同步(source)`、当场恢复 `currentTime`、当场 `play()`。
4. 于是 `waiting -> loadstart -> loadedmetadata -> seeking -> seeked -> canplay -> playing` 这整条媒体重载链被用户肉眼看到，表现就是闪一下、抽一下、再开始播。

这份 plan 的唯一目标，就是把这条链彻底掐断。

## 3. Task 2: 在消息窗增加“隐藏预热宿主 + 揭帘门”

**Files:**
- Modify: `frontend/房间消息窗.ts`
- Test: `frontend/tests/房间消息窗媒体查看器测试.spec.ts`

- [ ] **Step 1: 在 `房间消息窗.ts` 里重新阅读并标注当前相关状态**

重点重新确认：

1. `时间线视频首帧就绪源`
2. `inlineAutoplayOwnerAttachmentId`
3. `inlineAutoplayPlaybackByAttachmentId`
4. `同步时间线唯一播放器宿主()`
5. `renderMessageAttachments()`

- [ ] **Step 2: 新增“canonical 可见接管就绪源”状态，只记录唯一播放器本身是否已经为某 attachment/source 准备好可见接管**

实现要求：

1. 不能复用现有 `时间线视频首帧就绪源`，因为那是预览 `<video>` 与 canonical player 共用的“首帧 ready”缓存，语义太宽。
2. 新状态必须是“唯一播放器这颗 canonical video 已经在 hidden stage 上完成该 source 的可见接管准备”。
3. 继续使用 `attachmentId + normalized src` 语义，避免旧 source 的 ready 误判成新 source。

- [ ] **Step 3: 渲染 owner 卡片时引入 reveal gate**

实现要求：

1. 当前 attachment 是 owner 且有可用 canonical source 时，不再只有“直接渲染 canonical host”这一条路。
2. 如果 canonical 还没 ready：
   - 保留当前 attachment 自己那张预览 `<video>` 作为可见帧；
   - 同时渲染一个隐藏的 staging host，供唯一播放器后台切源和恢复位置；
   - 禁止显示 `▶` 播放指示器，避免 owner 卡片看起来像未激活静态卡片。
3. 只有 canonical ready 后，才把可见表面切成 `.message-video-canonical-host`。

- [ ] **Step 4: `同步时间线唯一播放器宿主()` 改成优先读取 visible host，读不到时再回退到 hidden stage host**

实现要求：

1. 禁止因为 visible host 还没显露，就上抛 `null`。
2. hidden stage host 必须也带完整 `attachmentId/src/kind/width/height/poster` 数据，保证唯一播放器完全能工作。
3. 这条回退只服务“owner 已经确定，但 canonical 仍在 hidden stage 预热”的窗口，不能变成第二套永驻路径。

- [ ] **Step 5: 把新的 canonical ready 回调接进消息窗状态，并在 attachment/source 失效时及时清理**

实现要求：

1. 新 owner/source 到来时，如果 ready 结论不匹配，必须重新 gated。
2. attachment 离开当前列表时，清掉对应 ready 状态。
3. 不能让旧 attachment 的 ready 状态泄漏到新一轮消息渲染。

- [ ] **Step 6: 跑消息窗测试，直到新增红测转绿且旧测试继续绿**

Run:
```powershell
pnpm --dir frontend test -- tests/房间消息窗媒体查看器测试.spec.ts
```

Expected:
- 新增 gating/staging 用例转绿；
- 旧有 owner/null/pending/preview/无控件相关测试不回归。

## 4. Task 3: 在全局唯一播放器增加“hidden stage 预热，不在可见表面换源”

目标：

1. 找清楚现在哪一行把 source sync、seek、play 全部压在可见 host 上。
2. 找清楚能否仅靠 mountTarget 语义区分 hidden stage / visible host，而不新增第二条 owner 状态机。

- [ ] **Step 2: 为时间线输入回调增加“canonical 可见接管已就绪”通知**

实现要求：

1. 只表示 canonical player 本身 ready，不表示 preview video ready。
2. 触发时机要晚于恢复位置动作，至少不能早于真正可用的 seek/canplay/playing 节点。
3. 不能因为多次相同 ready 事件造成重复 requestUpdate 抖动。

- [ ] **Step 3: 让 `配置时间线自动播视频()` 区分 hidden stage / visible host**

实现要求：

1. visible host：
   - 仍是 inline autoplay 表面；
   - 允许 `autoplay=true`；
   - 会在 ready 后开始播放。
2. hidden stage：
   - 仍是同一颗 canonical player；
   - 但只负责切源、恢复位置、等首帧 ready；
   - 禁止立刻 `play()`，避免 hidden 预热先偷跑时间轴。

- [ ] **Step 4: `应用时间线自动播表面()` 收口成两段式**

实现要求：

1. 如果当前 mountTarget 是 hidden stage：
   - `挂载到宿主(stage)`
   - `同步(source)`
   - `恢复播放位置(video)`
   - 等 canonical ready 回调
   - 禁止立刻 `play()`
2. 如果当前 mountTarget 已经是 visible host：
   - 同一颗壳迁过去
   - 对同源输入只做挂载，不再可见换源
   - 此时才 `play()`

- [ ] **Step 5: 如壳层在 stage -> visible 迁移时还有多余 DOM remove/add，再补最小 no-op/布局同步修复**

要求：

1. 只在确实观察到重复 DOM mutation 时再动 `videojs播放器壳.ts`。
2. 禁止借机发明第二套挂载器。

   - 先补消息窗红测；

   - 这轮不改媒体运行时主链、不改编排契约、不改分发策略，只修表面迁移语义。
