# 真DDD三满分全量执行计划 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:executing-plans` to implement this plan task-by-task. Use `superpowers:subagent-driven-development` only if the owner explicitly authorizes subagents. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把 `koko` 从当前“测试与门禁大多已绿、但结构仍未满分”的状态，推进到可证明的 `DDD: 满分 / 六边形边界: 满分 / 简洁度: 满分`。

**Architecture:** 当前真正的问题，已经不再是“旧根文件很多”或“明显的 unused 没清”，而是三个高风险汇聚点仍在继续吸附复杂度：`src/消息/应用.rs` 的同步/异步规则复制、`src/适配/mod.rs` 的总仓储壳、`frontend/总装/聊天应用内核.ts` 的总编排壳。执行顺序必须先让假满分自动失败，再用 TDD 逐个拆掉这些回流口，最后靠全量验证、独立全仓复核、graphify 和 `1234b` 双浏览器真实烟测收口。

**Tech Stack:** Rust、Axum、SQLx、socketioxide、TypeScript、Lit、XState、Video.js v10、WebTorrent、Vitest、Playwright/browser-trace、graphify。
