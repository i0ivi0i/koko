# 群聊播放优化与离屏续播彻底完工 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把 [项目视频播放要求](/E:/koko/docs/superpowers/specs/2026-04-25-项目视频播放要求.md) 里仍未完成的两条硬约束彻底补齐，并用真实房间烟测证明消息流视频已经满足“无控件、离屏续播、当前 owner 直达真全屏、退出归位不回退”。

**Architecture:** 这轮不再扩张播放器体系，也不发明第二张位置真相表。继续沿用 `房间消息窗 -> 聊天媒体编排/聊天壳 -> 媒体运行时 -> 全局唯一播放器 -> 媒体查看器` 这条既有 owner 链，只补两处当前真实缺口：一是时间线 inline 表面泄露了统一壳控件；二是 viewer 关闭前没有把最新 `currentTime` 回灌进唯一位置真相，导致退出全屏后回到旧时间点。所有修复都必须守住单 canonical `Video.js v10` player、单位置真相、单 owner。

**Tech Stack:** TypeScript, Lit, `Video.js v10`, existing `media-chrome`/自定义 skin, Fullscreen API, Vitest, Playwright CLI, Serena 符号分析。

## 0. 先把当前失败真相写死

这份 plan 不是“也许会有问题时的预案”，而是针对已经被真实烟测证实的两条硬失败：

1. **消息流里仍会露出统一壳控件。**
   - 当前时间线 owner 虽然关闭了原生 `<video controls>`，但统一壳 `koko-video-skin` 仍渲染 `media-controls`。
   - 这直接违反 spec 第 `2.5`、`7` 节的“消息流永远无控件”。

2. **当前自动播视频进入真全屏后，退出回消息流会回退到旧时间点。**
   - 当前唯一播放器在进入 viewer 前会 flush 一次 inline 位置。
   - 但 viewer 关闭前没有再 flush 最新 `currentTime`，导致退出后只会从旧快照恢复。
   - 这直接违反 spec 第 `2.4`、`6.4` 节的“同一条时间轴连续”。

3. **离屏续播主链当前是活的，不能在修上面两条时顺手打坏。**
   - 真实烟测已经证明：滑出屏幕暂停、滑回继续播这条主链是通的。
   - 本轮必须把它当成回归保护线，而不是再大改播放状态机。

因此这轮的最高裁决是：

1. **禁止** 再长第二颗正式 player。
2. **禁止** 再长第二张播放位置表。
3. **禁止** 把“inline 无控件”实现成另起一套第二播放器壳。
4. **禁止** 把“viewer 退出写回位置”实现成 DOM 私有临时缓存。
5. **禁止** 为了补视觉体验伤到 `WebTorrent` 主链、热会话复用、自动播 owner 粘性或离屏续播。

## 1. 文件地图与边界锁定

### 播放表面与壳

- `frontend/媒体/videojs播放器壳.ts`
  - 统一 `koko-video-skin` 模板与挂载表面逻辑。
  - 本轮只允许增加“时间线 inline 表面”的显隐约束或展示模式。
  - **禁止** 把消息流和 viewer 拆成两套播放器壳实现。

- `frontend/媒体/全局唯一播放器.ts`
  - 同一颗 canonical player 的 inline/viewer 接管 owner。
  - 本轮负责：
    1. inline 挂载时明确声明“消息流表面，无控件”
    2. viewer 关闭前把最新位置回灌到外层唯一位置真相
  - **禁止** 在这里再持有第二张业务状态表。

### 查看器与运行时桥接

- `frontend/媒体/媒体查看器.ts`
  - viewer 生命周期和唯一播放器会话接线。
  - 本轮只允许补“viewer 当前播放位置回调”，把最新 `currentTime` 向外层上报。
  - **禁止** 在这里自己保存“关闭前位置”私货。

- `frontend/聊天媒体编排.ts`
  - 把消息窗/查看器事件转成运行时事实。
  - 本轮负责新增 viewer 位置上报桥接，继续把位置真相收口到媒体运行时。
  - **禁止** 把当前热会话点击打回 recovering。

- `frontend/应用运行时.ts`
  - AppRuntime 只负责把壳层事件转成聊天内核命令。
  - 如果位置事件要从“消息流 inline”升格成“canonical player 通用位置变化”，这里必须同步改名与转发。
  - **禁止** 因为图省事把 viewer 位置旁路塞进壳层私有调用。

- `frontend/聊天应用内核.ts`
  - 聊天内核负责把 AppRuntime 命令路由到 `聊天媒体编排.ts`。
  - 如果位置事件语义变化，这里必须同步调整 command 类型与路由。
  - **禁止** 让“inline 专用事件名”偷偷承载 viewer 语义而不做边界澄清。

- `frontend/媒体运行时.ts`
  - 当前 `inlineAutoplayPositionByAttachmentId` 已是唯一位置真相。
  - 本轮只允许补一个“viewer 最新位置也写回同一张表”的事件处理。
  - **禁止** 新增 `viewerPositionByAttachmentId` 之类的第二张表。

### 消息流表面

- `frontend/房间消息窗.ts`
  - 消息流宿主槽位、预览画面表达、位置恢复与统一打开意图。
  - 本轮重点是验证它继续只消费唯一位置真相，而不是自己发明 viewer 退出恢复逻辑。

## 2. 风险闸门

### 闸门 A：inline 无控件必须是“同一壳不同展示模式”

允许：

1. 给统一 skin 增加“inline / viewer”展示模式。
2. 在 inline 模式下直接隐藏 `media-controls`，必要时关闭相关热键和交互命中。

禁止：

1. 新建第二套“时间线专用播放器壳”。
2. 只关原生 `video.controls`，却继续让 `media-controls` 可见。
3. 在消息流里保留可点击的播放/进度/静音控件。

### 闸门 B：viewer 退出位置写回必须回灌到同一张位置表

允许：

1. viewer 使用统一回调，把当前 `src/currentTime/updatedAt` 写回媒体运行时。
2. 在 viewer 关闭、切源、pause、timeupdate 等关键节点上报“更晚事实”。

禁止：

1. 新增 `viewerPositionByAttachmentId`。
2. 在 `媒体查看器.ts` 或 `全局唯一播放器.ts` 自己缓存一份“退出前位置”而不写回运行时。
3. 用“退出时再手动 seek 一下”掩盖旧快照回退问题。

### 闸门 C：修复后必须保持这三条继续为真

1. 离屏续播仍从中断点继续。
2. 当前 owner 点击仍直达真全屏当前这颗 canonical player。
3. `activeVideoCount` / `autoplayOwnerCount` 仍不大于 `1`。
