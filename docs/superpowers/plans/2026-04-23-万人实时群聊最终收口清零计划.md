# 万人实时群聊最终收口清零 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 清掉当前仍阻断三份 authoritative spec 宣布“彻底完成”的最后兼容缝、旧路径和双真相尾巴，让聊天主链、媒体主链、共享 contract 和文档状态同时收口。

**Architecture:** 先用失败测试把剩余阻断项钉死，再按 `shared contract -> media adapter/read model -> message write path -> 图谱与文档收尾` 的顺序删旧路径。凡是当前还需要的运行能力，都必须先改造成明确 canonical owner，再删“兼容/旧路径”语义；禁止通过新增 wrapper 保留双活。

**Tech Stack:** Rust (`socketioxide`, `axum`, `sqlx`, `tokio`), TypeScript + Vitest, PowerShell smoke tests, graphify.

## 范围锁定

这次不再拆成多份 plan。原因不是偷懒，而是剩余阻断项共享同一条收口目标：

1. 删除共享 contract 里还活着的第二语义；
2. 删除媒体读侧还活着的兼容回退；
3. 删除消息主链还活着的旧提交路径；
4. 用 graphify 和新鲜验证证明这些删除没有把系统打坏；
5. 只有这些都完成，三份 spec 的状态和“已完成”说法才有资格同步落锤。

如果执行中发现某个阻断项需要独立的大型数据迁移，允许在当前 plan 内新增一个“迁移专用 task”，但**不允许**把主线重新拆成“以后再说”的第二入口。
