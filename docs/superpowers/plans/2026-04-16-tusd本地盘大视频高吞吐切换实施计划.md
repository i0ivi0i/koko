# tusd 本地盘大视频高吞吐切换 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在不破坏现有 `prepare / complete / abandon` 业务真相的前提下，把当前 `Uppy + @uppy/tus -> Rustus` 的上传主链一次性切到 `tusd v2 + local disk`，并清掉活代码里的 `Rustus` 历史命名与运行时耦合。

**Architecture:** 浏览器侧继续保留 `Uppy + @uppy/tus`，不重写 uploader，也不提前切 multipart。后端把上传 transport 继续收口在 `prepare / hook / complete / abandon / gc` 主链里，但把 sidecar 从 `Rustus` 切成 `tusd`，同时把代码边界从 vendor 导向改成协议/能力导向：业务真相仍由后端裁决，`tusd` 只负责 resumable upload、concatenation、termination 和 local disk。

**Tech Stack:** TypeScript, Vitest, Rust, Axum, SQLx/PostgreSQL, Uppy `@uppy/tus`, tusd v2, Tokio, PowerShell, `object_store`, `reqwest`

---

### Files to rename

- `src/rustus_hook外壳.rs` → `src/tus_hook外壳.rs`
- `tests/媒体上传测试/rustus_hook.rs` → `tests/媒体上传测试/tus_hook.rs`

### Files intentionally **not** created in this phase

- 不创建 `src/S3兼容层.rs`
- 不创建 `frontend/S3兼容层.ts`
- 不新增数据库 migration

### Why this split

- 代码库已经有 `upload_session_id`、`partial/final`、`current_upload_session_id` 和相关回归测试，说明“上传会话模型”已经落地；这期真正要改的是 sidecar、hook payload、命名边界和运行脚本，不是再重做一遍上传会话。
- `S3兼容层.ts/.rs` 这期不创建，是因为当前代码搜索下来还没有第二个真实 owner 可以立刻被吸收；现在强行落文件只会制造空壳层，违反 spec。
- 协议边界统一用 `tus` 命名，shell 层再显式使用 `tusd`，可以把 vendor 细节收缩到启动脚本和 hook payload adapter，不让业务/测试继续满地 `Rustus`。

## Guardrails Before Execution

- 不改 `frontend/契约.ts` 里的 `媒体上传准备结果` 形状；`attachment_id / upload_session_id / tus_endpoint / tus_headers / tus_metadata` 继续保持稳定。
- 不改数据库 schema；如果执行到一半发现 `0013_Tus_Concatenation上传会话.sql` 仍不够用，立刻停下补 spec addendum，不在本计划里偷塞 migration。
- 不创建 `S3兼容层.ts/.rs`；如果执行中真的发现“立即可吸收的散点职责”，先把证据写回设计文档再决定，不得顺手造空壳。
- 不让客户端直接把 `termination` 变成业务取消真相；前端仍只表达“取消上传”，业务取消继续由后端 `abandon` 裁决。
- 不尝试保留 `Rustus` 与 `tusd` 双轨启动或双轨 hook 路由；这期是一次性切换。
