# 视频唯一播放与自动播视觉连续性修复 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` or `superpowers:executing-plans` to implement this plan task-by-task. Keep this checklist updated as each task is completed.

**Goal:** 修复消息流视频滑走后的视觉割裂：视频离开自动播 owner 后不能偷偷回到 poster / 第一帧，再滑回时也不能从开头画面跳到续播时间点；同源可播放数据和已保存 `currentTime` 存在时，时间线仍应渲染轻量原生 `<video>` 并停在保存帧。

**Architecture:** 这是 Web 壳时间线投影 bug，不是 WebTorrent 分发 bug。正式媒体字节仍由既有 swarm owner 链提供；时间线只负责把“同源可播放视频 + 已保存播放位置”投影成连续画面。Viewer / fullscreen 继续由唯一 Video.js v10 播放器壳承载，消息流不新增 Video.js 实例、不新增 canvas 抽帧缓存、不新增第二预览 owner。

**Tech Stack:** TypeScript, Lit, native `<video>`, existing media playback runtime, Vitest, Chrome DevTools CLI smoke.

---

## 0. 当前根因

当前退化点在 `frontend/房间消息窗.ts` 的 `renderMessageAttachments`：

1. `hasSourcePoster` 为真时，非当前自动播 owner 的视频不会进入 `读取时间线视频首帧预览源(...)`。
2. 只要视频带 `posterSrc` 或 runtime `thumbnailUrl`，滑出自动播 owner 后就会重新渲染 `<img class="message-video-poster">`。
3. `恢复时间线自动播播放位置(...)` 又要求 `inlineAutoplayOwnerAttachmentId === attachmentId`，所以非 owner 的轻量 `<video>` 即便被渲染，也无法恢复到保存帧。

结果就是：时间戳 truth 已经保存，视觉 truth 却回到 poster / 第一帧；再次滑回自动播时才 seek 到保存位置，用户看到“从开头跳到续播点”。

**禁止把这个问题修成预览图系统。** 视频本身就是可展示画面；有同源可播放 src 和保存时间点时，直接用原生 `<video>` 展示保存帧。

## 3. TDD: 先写失败测试

### 3.1 有 poster 的视频释放 owner 后保持视频帧

在 `frontend/tests/房间消息窗媒体查看器测试.spec.ts` 中，放到既有自动播位置恢复测试附近。

测试意图：

1. 视频附件自带 `posterSrc`。
2. runtime 已有 swarm `playback.src`。
3. `inlineAutoplayPositionByAttachmentId` 已保存同源 `currentTime`。
4. 当 `inlineAutoplayOwnerAttachmentId` 从该附件释放为 `null` 后，DOM 仍应是 `video.message-video-preview`。
5. `loadedmetadata` 后 `video.currentTime` 应恢复到保存值。
6. 该非 owner 视频必须是静态预览帧，不能触发播放。

最小测试骨架：

```ts
it("有 poster 的视频释放自动播 owner 后仍显示保存时间点的视频帧", async () => {
  const pane = 创建媒体消息窗();
  const playback = {
    mode: "swarm",
    attachmentId: "att-video-1",
    kind: "video",
    src: "http://media.local/swarm-video-1.mp4",
    thumbnailUrl: "http://media.local/poster-video-1",
    hint: null,
  } satisfies 媒体播放结果;

  pane.items = [创建媒体消息项()];
  pane.mediaPlaybackByAttachmentId = { "att-video-1": playback };
  pane.inlineAutoplayPlaybackByAttachmentId = { "att-video-1": playback };
  pane.inlineAutoplayOwnerAttachmentId = "att-video-1";
  pane.inlineAutoplayPositionByAttachmentId = {
    "att-video-1": {
      src: playback.src,
      currentTime: 24.5,
      updatedAt: Date.now(),
    },
  };

  document.body.appendChild(pane);
  await pane.updateComplete;

  pane.inlineAutoplayOwnerAttachmentId = null;
  await pane.updateComplete;

  const preview = pane.querySelector<HTMLVideoElement>(
    'video.message-video-preview[data-attachment-id="att-video-1"]',
  );
  expect(preview).not.toBeNull();
  expect(
    pane.querySelector('img.message-video-poster[data-attachment-id="att-video-1"]'),
  ).toBeNull();

  preview!.dispatchEvent(new Event("loadedmetadata"));
  expect(preview!.currentTime).toBeCloseTo(24.5, 2);
  expect(preview!.autoplay).toBe(false);

  pane.remove();
});
```

当前代码应失败：释放 owner 后会因为 `posterSrc` 存在而回到 `<img>`。

### 3.2 源不匹配时禁止伪连续

补一条反向测试，防止修复时把旧播放位置误套到新 source：

1. `inlineAutoplayPositionByAttachmentId["att-video-1"].src` 是旧 swarm src。
2. 当前 `mediaPlaybackByAttachmentId["att-video-1"].src` 是新 swarm src，或当前无 swarm src。
3. DOM 应回退 poster。
4. 不得渲染使用旧 src 的 `<video>`。

这条测试守住 session-aware / source-aware 语义，避免为了视觉连续性偷拿旧真相。

## 4. 实现：时间线视频投影收口

### 4.1 保留唯一播放 owner

`frontend/房间消息窗.ts` 中继续保留现有 owner 判断：

```ts
const shouldRenderInlineVideo =
  this.inlineAutoplayOwnerAttachmentId === attachment.attachmentId &&
  isVideo &&
  Boolean(inlineAutoplayPreviewSrc);
```

**禁止把“可显示保存帧”升级成“可自动播放”。** 自动播放仍只属于当前 `inlineAutoplayOwnerAttachmentId`。

### 4.2 新增“可恢复静态视频帧”判断

在 `renderMessageAttachments` 中为视频附件计算：

1. 当前可播放 swarm src：优先使用 `inlineAutoplayPreviewSrc`，其次使用当前 `playback.src`。
2. 已保存位置：只通过 `读取自动播恢复位置(attachmentId, candidateSrc)` 读取，必须 source-aware。
3. 静态恢复帧 src：只有已保存位置和当前候选 src 匹配时才成立。

推荐形态：

```ts
const timelinePlayableVideoSrc =
  inlineAutoplayPreviewSrc ?? (playback?.mode === "swarm" ? playback.src : null);
const restorableTimelineFrame = this.读取自动播恢复位置(
  attachment.attachmentId,
  timelinePlayableVideoSrc,
);
const restorableTimelineVideoSrc =
  restorableTimelineFrame && !shouldRenderInlineVideo ? restorableTimelineFrame.src : null;
```

然后统一决定时间线视频元素：

```ts
const timelinePreviewVideoSrc =
  restorableTimelineVideoSrc ??
  (!hasSourcePoster ? this.读取时间线视频首帧预览源(attachment, playback) : null);
```

关键约束：

1. 有保存位置时，`posterSrc` 不再阻止渲染 `<video>`。
2. 没有保存位置时，既有 poster fallback 保持不变。
3. 不使用 `originalSrc` / `canonical` / 冷源回退。
4. 不新增 canvas、blob 截帧、IndexedDB 预览图或第二缓存。

### 4.3 渲染 `<video>` 时禁止 poster 遮盖保存帧

对 `restorableTimelineVideoSrc` 渲染出的非 owner `<video>`：

1. 不要设置会长期遮住当前帧的 `poster`。
2. `preload="metadata"` 即可。
3. `muted / playsinline` 保留。
4. `autoplay` 必须为 false。
5. `controls` 不出现。

中文注释要解释“为什么这里用视频本身当预览，而不是 poster”：这是为了让滑走后的静态画面仍和保存 `currentTime` 一致。

## 5. 实现：恢复位置允许静态帧 seek

修改 `恢复时间线自动播播放位置(...)`，增加一个窄选项：

```ts
private 恢复时间线自动播播放位置(
  attachmentId: string,
  video: HTMLVideoElement,
  options: { allowPreviewFrame?: boolean } = {},
): void {
  if (!options.allowPreviewFrame && this.inlineAutoplayOwnerAttachmentId !== attachmentId) {
    return;
  }
  ...
}
```

调用侧：

1. 当前自动播 owner：`allowPreviewFrame` 不需要传，保持原语义。
2. 非 owner 静态恢复帧：只在渲染的 src 来自 `restorableTimelineVideoSrc` 时传 `{ allowPreviewFrame: true }`。

**禁止让非 owner 进入播放链。** 这个选项只允许 seek 到保存帧，不能触发 `play()`，不能广播 owner 事件，不能写入新的播放 owner。

---

## 6. 实现：同步状态时保持静态帧

检查 `同步时间线自动播播放状态()`：

1. 当前 owner 仍负责 `play()` / `pause()` / position flush。
2. 非 owner 但可恢复静态帧时，应在 metadata 可用后 seek 到保存位置。
3. 若浏览器把非 owner video 误保持为 playing，应立即 pause。

允许的逻辑是：

```ts
if (shouldAutoplay) {
  this.恢复时间线自动播播放位置(attachmentId, video);
  await video.play();
  return;
}

if (isRestorablePreviewFrame) {
  this.恢复时间线自动播播放位置(attachmentId, video, { allowPreviewFrame: true });
}

if (!video.paused) {
  this.记录并暂停时间线视频(attachmentId, video, { allowReleasedOwner: true });
}
```

如果不方便在该函数直接知道 `isRestorablePreviewFrame`，则通过 `data-*` 标记或复用 source-aware 查询判断；不要新增全局状态 map。

## 7. 禁止事项

1. 禁止新增视频预览图生成链。
2. 禁止新增 canvas 抽帧、blob 截帧或 IndexedDB 预览帧缓存。
3. 禁止为了这个 bug 修改 WebTorrent aggressive backfill / seeding / tracker 语义。
4. 禁止给消息流每个视频挂一个 Video.js 实例。
5. 禁止恢复 `original_url`、`canonical`、服务器直供或任何第二正式播放主链。
6. 禁止把非 owner 静态视频帧变成会自动播放的新 owner。
7. 禁止用固定数量裁剪帮助任务、弱化“看过即帮助”语义。
