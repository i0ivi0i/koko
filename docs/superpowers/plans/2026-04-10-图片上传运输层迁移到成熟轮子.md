# 群聊图片媒体层与对象存储直传 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把当前“前端直打聊天主服务上传图片”的链路，升级成“前端直传 S3 兼容对象存储 + Rust prepare/complete + 消息只引用稳定媒体标识”的链路，同时保留 Win11 本地开发和未来 Linux 公网部署的兼容准备。

**Architecture:** 这次不再把聊天主服务当上传服务器，也不再继续给 `XHR multipart` 链路补洞。首阶段只换上传主链，不做 repo 级大改名：**当前持久化层里的 `attachment_id` 继续作为首阶段 `media_id` 使用**，这样消息主链、附件真相和内容读取链都能继续复用；新增的是 `prepare -> 直传对象存储 -> complete -> send message(attachment_id)` 这条媒体链。开发期默认接本地 `MinIO`，生产期可切 `MinIO / S3 / R2`，不改前端主流程和消息契约。

**Tech Stack:** Rust、Axum、SQLx、socketioxide、object_store(`aws` + `fs`)、image、infer、kamadak-exif、TypeScript、Lit、Uppy、`@uppy/aws-s3`、heic2any、MinIO、Vitest、cargo test、pnpm test、PowerShell `run.ps1`

---

## 先读这个过渡裁决

这份 plan 最容易漂的地方就是命名和迁移顺序，所以先把 3 条钉死：

1. **首阶段不做 repo 级 “attachment -> media” 大改名。**  
   现有数据库表、消息引用、前端草稿字段里已经有大量 `attachment_id`。为了避免屎山式重命名，这一轮先把 **`attachment_id` 视为首阶段 `media_id`**，先换上传主链，后续再评估是否值得统一命名。

2. **旧 `POST /api/attachments/image` 保留为回滚窗，不再是 canonical path。**  
   新主路是 `prepare/complete`；旧直传接口只留到新链稳定，不允许继续往旧链堆功能。

3. **内容读取链先继续复用 `/api/attachments/{attachment_id}/content`。**  
   这能减少前端展示面改动，把首阶段变更集中在“上传”和“媒体状态”上。

最小请求体：

```rust
struct PrepareImageUploadBody {

}
```

固定行为：

1. 校验 `session_id`
2. 前置拒绝：
   - 缺字段
   - `byte_size <= 0`
   - `byte_size > 10MB`
3. 调用 `准备图片附件上传`
4. 生成固定对象 key：

```rust
let original_storage_key = format!("images/{attachment_id}/original");
```

5. 返回：

```json
{
  "attachment_id": "att-...",
  "upload_method": "PUT",
  "upload_url": "...",
  "upload_headers": {
    "content-type": "image/jpeg"
  },
  "expires_at": "..."
}
```

注意：

1. 返回里继续用 `attachment_id`
2. 这就是首阶段 `media_id`
3. 不在这里解码图片
4. 不在这里创建消息

- [ ] **Step 3: 实现 `complete_image_upload`**

在 [src/房间外壳.rs](/E:/koko/src/房间外壳.rs) 新增：

```rust
pub(super) async fn complete_image_upload(
    State(state): State<应用状态>,
    Path(attachment_id): Path<String>,
    Json(body): Json<CompleteImageUploadBody>,
) -> impl IntoResponse { ... }
```

最小请求体：

```rust
#[derive(Deserialize)]
struct CompleteImageUploadBody {

}
```

固定顺序：

1. 校验 session 和 owner
2. 读取当前附件记录，状态必须是 `prepared`
3. 用 `attachment_store.get(original_key)` 取回对象
4. `infer` 判真 MIME
5. `image` 解码，读取宽高
6. `kamadak-exif` 修正方向
7. 生成缩略图 key：

```rust
let thumbnail_storage_key = format!("images/{attachment_id}/thumbnail.png");
```
