# 2026-05-02 真DDD/六边形边界/简洁度 满分收口执行计划

## 0. 目标定义（完成标准）

本计划执行完成后，必须同时满足以下可验证标准：

1. DDD 满分：业务真相 owner 不漂移；展示壳只做投影/编排，不再混入自动播候选观察与调度真逻辑。
2. 六边形边界满分：`房间消息窗/壳.ts` 仅保留 UI 壳职责；自动播候选观察能力下沉为独立 owner（可视作前端 adapter owner）。
3. 简洁度满分：删除壳层重复状态/重复流程，减少跨职责方法；热点门禁不再“只防恶化”，而是推动继续变薄。
4. 验证闭环满分：新鲜执行测试与脚本，文档状态与真实验证一致，不允许“文档绿、代码红”。

## 1. 当前问题归因（基于新鲜证据）

1. `frontend/tests/realtime真实链路.spec.ts` 的 `beforeAll(120000)` 会在部分环境下因后端构建耗时导致超时。
2. `frontend/房间消息窗/壳.ts` 同时持有自动播候选观察器、调度句柄、候选缓存与事件派发，职责越界。
3. `scripts/check-frontend-architecture-fitness.mjs` 对 `壳.ts` 与 `附件渲染.ts` 行数阈值偏宽，无法持续压降热点。
4. `docs/superpowers/reports/2026-05-01-真DDD重构完成矩阵.md` 的验证描述与当前真实测试状态不一致。

## 2. 执行路径（强制 TDD）

### Phase A - RED（先失败）

1. 为自动播 owner 拆分新增/调整测试：
   - 证明消息窗壳不再直接维护自动播观察内部状态；
   - 证明候选仍可由观察器回调产出且事件语义不变。
2. 为真链路预编译流程加失败测试或 characterization：
   - 覆盖“预编译可能超过 120s 但不应让 beforeAll 误超时”。
3. 为门禁阈值收紧加测试（若项目已有脚本测试入口则接入，否则以脚本静态断言覆盖）。
4. 确认以上测试在改动前出现预期失败（RED 成立）。

### Phase B - GREEN（最小实现转绿）

1. 在 `frontend/房间消息窗/` 下新增“自动播候选观察/调度 owner”模块：
   - 内聚 IntersectionObserver 管理、候选计算、rAF+timeout 调度、候选缓存；
   - 对外暴露最小接口：`同步观察`、`调度`、`清理`、`读取候选`、`读取可见候选排序`。
2. `房间消息窗/壳.ts` 改为组合该 owner：
   - 删除壳内重复状态字段与重复实现；
   - 保持事件名与上层契约不变（`room-inline-autoplay-observed`）。
3. `realtime真实链路.spec.ts` 调整预编译策略：
   - 将 hook timeout 与构建流程解耦，避免误把构建抖动当业务失败；
   - 保留“构建失败必须硬失败”的语义。
4. 收紧 `check-frontend-architecture-fitness.mjs` 热点阈值，确保壳层后续继续瘦身。
5. 更新完成矩阵，明确当前验证时间与结果，去掉过期“已全绿”叙述。

### Phase C - REFACTOR（清理并保持绿）

1. 删除壳层中与自动播观察 owner 重复/废弃路径，清掉冗余状态与方法。
2. 清理受影响测试中的旧直连私有方法调用，改成对 owner 行为与公开语义断言。
3. 保持中文注释聚焦“职责/边界/为什么”，避免噪音注释。

## 4. 风险与止损

1. 若自动播观察拆分导致候选事件抖动：先回退到“壳组合 owner + 接口薄包装”，不回退到壳内全实现。
2. 若真链路测试仍偶发超时：先隔离构建与业务验证，再判断是否需要进一步分层用例。
3. 若阈值收紧触发额外违规：只处理与本轮链路同职责模块，避免无关扩散改动。
