# Admin 后台会话与入口收口 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 恢复真实 `/admin` 后台入口，改用服务端后台会话承接管理员登录，统一 `admin_token` 配置文件真相，并保持 DDD 边界清楚、代码可读、测试可证。

**Architecture:** `src/app.rs` 继续承接后台认证与授权用例，只暴露清晰 port，不直接依赖 `tower-sessions`、Axum 或 SQLx 细节；`src/http.rs` 只负责把 `tower-sessions` 的 `Session` 提取成稳定的 application 输入，再把应用错误转成稳定 HTTP error code。`src/support.rs` 负责配置文件真相与启动期初始化，`src/store.rs` 负责 Postgres 中“单有效后台会话”真相与现有后台只读查询，`src/admin.rs` 只负责后台壳登录体验与状态展示，不持有原始管理员口令。实现时严格按 `contract -> application -> adapter/shell` 落位：后台 cookie、tower 类型、浏览器凭据语义只能留在 adapter/shell，后台“谁已登录、是否过期、是否被顶掉”必须回到 application + store 真相；异步热路径不允许跨 `await` 长持业务锁。

**Tech Stack:** Rust 2024, axum 0.8, dioxus 0.7, sqlx/postgres, tokio, tower-sessions, tower-sessions-sqlx-store, time, sha2, tracing, reqwest

```sql
SELECT pg_advisory_xact_lock(hashtext($1), $2)
```

- `hashtext("admin_session_truth")`
- 锁键常量 `1`

替换与 touch 流程都按这个事务形状落：

1. `BEGIN`
2. 获取后台 singleton 锁
3. 读取当前 `admin_session_truth`
4. 校验/替换 `active_session_id` 与 `admin_token_fingerprint`
5. 必要时更新 `last_seen_at`
6. `COMMIT`

只有这样，近乎同时的两次后台登录才不会出现双活窗口。
