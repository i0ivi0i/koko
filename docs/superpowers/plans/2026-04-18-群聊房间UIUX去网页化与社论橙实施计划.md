# 群聊房间 UIUX 去网页化与社论橙实施计划 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在不破坏现有聊天、媒体查看、上传、恢复、未读与 AppRuntime owner 边界的前提下，把房间壳收口成去网页化的主舞台，并补齐 Telegram 式稳定媒体拼贴与昵称完整可读规则。

**Architecture:** 只动 `shell / view-model / renderer` 三层，不改后端 contract，不改 AppRuntime、媒体主链和 transport 语义。多附件工整问题必须在 `frontend/视图.ts` 的展示模型层裁决，再由 `frontend/房间消息窗.ts` 渲染，`frontend/聊天壳.ts` 只负责视觉骨架、颜色 token、头部和输入区空间节奏。

**Tech Stack:** Lit、TypeScript、Vitest、现有 `默认文本布局器`、CSS Grid、现有消息窗与聊天壳组件。

---

## File Map

- Modify: `frontend/视图.ts`
  负责消息展示模型、附件拼贴模板、附件尺寸与外层 surface 宽度裁决；复用已有 `默认文本布局器`，不手搓新的测量轮子。
- Modify: `frontend/房间消息窗.ts`
  只负责把展示模型渲染成稳定 DOM：昵称、拼贴 grid、媒体卡片入口、状态锚点；不新增业务真相。
- Modify: `frontend/聊天壳.ts`
  负责房间头、消息区、输入区、状态带、颜色 token 和拼贴 CSS；不得拥有媒体/恢复/未读业务真相。
- Create: `frontend/tests/视图展示测试.spec.ts`
  专门锁定展示模型：多附件模板、surface 宽度、发送顺序与混合媒体稳定输出。
- Modify: `frontend/tests/房间消息窗媒体查看器测试.spec.ts`
  增加拼贴 renderer、昵称完整可读、媒体 DOM 契约测试。
- Modify: `frontend/tests/聊天壳测试.spec.ts`
  锁定社论橙 token、去网页化头部/主舞台/输入区 CSS、状态带固定区契约。
- Modify: `frontend/tests/输入区布局测试.spec.ts`
  锁定控制台化输入区与状态带共存时的高度、发送行为和布局稳定性。
- Modify: `frontend/tests/聊天壳恢复与分页测试.spec.ts`
  锁定 room subtitle / 状态带 / 滚动恢复在新壳骨架下仍保持稳定。

## Constraints

- 不新增新的 runtime / manager / facade / service。
- 不改 `frontend/聊天应用内核.ts`、`frontend/应用运行时.ts`、`frontend/媒体/**` 里的 owner 语义，除非测试证明 UI 变更逼出了真实边界问题。
- 多附件拼贴只用 CSS Grid + 展示模型，不手搓 canvas 布局器、绝对定位算法或第二套媒体壳。
- 昵称完整优先必须通过稳定布局解决，不能靠 hover、tooltip 或二级面板补救。
- 所有行为改动必须先有失败测试；任何回归都先修测试或撤销改法，不允许“先做完再补测”。
