# PoW 防御开关协议与生产启用 实现计划

> **面向 AI 代理的工作者：** 必需子技能：使用 superpowers:test-driven-development，逐任务按 RED / GREEN / REFACTOR 执行。

**目标：** 消除 `/api/pow/challenge` 404 探测噪音，并让生产部署默认自动开启 PoW 防御，同时保持正常用户丝滑无感。
**架构：** 后端 bootstrap 明确下发 `pow_required`；前端只在该字段为 `true` 时后台解题；部署脚本默认生成 PoW secret 并启用防御；realtime connect middleware 继续负责 PoW token、IP 连接计数和 session 校验；媒体与消息热路径不碰 PoW。
**技术栈：** Rust / Axum / socketioxide / TypeScript / Socket.IO client / Web Worker SubtleCrypto。
**设计文档：** `docs/superpowers/specs/2026-05-18-PoW防御开关协议与生产启用-design.md`

## 1. 成功标准

1. PoW 关闭时，浏览器不再请求 `/api/pow/challenge`，控制台没有预期内 404。
2. PoW 开启时，前端后台请求 challenge/verify，带 `pow_token` 建立 realtime。
3. 无 token 或错误 token 的 realtime 握手在 DB session 校验前被拒绝。
4. 发消息、发视频、WebTorrent 播放不触发 PoW 请求。
5. 生产默认自动启用 PoW，可通过 `KOKO_POW_ENABLED=false` 一键关闭。

it("powRequired=false 时建连不请求 PoW token", async () => {

  const 场景 = 创建实时编排测试场景({ roomId: "r-test" });

### 步骤

#### 9.1 环境模板

补充说明：

```dotenv
# PoW 防御默认开启。正式部署会在缺失时自动生成 KOKO_POW_SECRET。
# 只有明确需要临时回滚时才设置 KOKO_POW_ENABLED=false。
KOKO_POW_ENABLED=true
# KOKO_POW_SECRET=<deploy.sh 自动生成>
KOKO_TRUSTED_PROXY=true
```

#### 9.2 deploy.sh 自动补齐

部署时读取 `/opt/koko/env/production.env`：

```bash
ensure_pow_defaults() {
  upsert_env_value "KOKO_POW_ENABLED" "${KOKO_POW_ENABLED:-true}" "${ENV_FILE}"
  upsert_env_value "KOKO_TRUSTED_PROXY" "true" "${ENV_FILE}"
  if ! grep -q '^KOKO_POW_SECRET=' "${ENV_FILE}"; then
    local secret
    secret="$(openssl rand -hex 32)"
    upsert_env_value "KOKO_POW_SECRET" "${secret}" "${ENV_FILE}"
  fi
}
```

如果生产机没有 `openssl`，用 `/dev/urandom` + `od` 兜底。生成的 secret 只写入生产 env，不进入 git。

#### 9.3 部署门禁

#### 10.1 健康检查

`healthcheck.sh` 加：

```bash
check_pow_contract() {
  local bootstrap
  bootstrap="$(curl -fsS "https://${KOKO_DOMAIN}/api/session/bootstrap" \
    -H 'content-type: application/json' \
    --data '{"device_anonymous_token":"healthcheck-pow"}')"
  echo "${bootstrap}" | grep -q '"pow_required":'
}
```

### 11.4 三遍自审

2. **架构边界**：PoW 只在会话启动/realtime adapter 层，不进入消息、媒体、domain/application。通过。
3. **验证闭环**：覆盖关闭、开启、错误 token、无感体验、部署门禁和公网冒烟。通过。

### 11.5 100% 自信循环

当前 plan 复用既有 PoW 引擎和前端解题器，只把隐式 404 探测改成显式协议开关，并把生产部署收成默认安全。它不增加媒体热路径，不改变 WebTorrent 主链。主要风险是状态字段接入点或部署 secret 生成逻辑出错，已要求以现有 `实时连接运行时策略` 和部署门禁测试为准，先测试再实现。作为实现路线有事实层面的充分信心。
