# 群聊媒体实时收发全链路 TDD 疏通 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把群聊图片/视频从 `prepare -> complete -> 房间事件 -> locator -> 列表预览 -> 查看器 -> backfill -> complete/release -> 24h 清理` 这条实时收发链真正疏通，消灭黑块、无限转圈、错误主链和冷角落漏测。

**Architecture:** 实现继续站在现有 Rust `complete_media_upload / load_media_locator / 24h cleanup` 主链，以及现有前端 `媒体播放 / 媒体查看器 / 媒体会话 / 媒体缓存 / 媒体协作分发 / 聊天媒体编排` owner 上，不新增第二套媒体核心。所有行为改动必须走 TDD：先把真实症状钉成失败测试，再写最小实现，再转绿，再删旧旁路，最后做全链路回归。

**Tech Stack:** Rust (`axum` / `tokio` / `sqlx` / `object_store`), TypeScript (`Vitest` / `tsc`), `WebTorrent`, `Vidstack`, HLS manifest 主链, `graphify`

---

## Scope Lock

- 本计划只覆盖 `Web 前端 + Rust 后端当前阶段`。
- 不纳入本轮：
  - `iOS / Android / Desktop / CLI`
  - 音频
  - 大规模压测与跨端容量治理
- 本计划完成后，必须同时满足：
  1. 视频时间线不再把 `m3u8` 错喂给原生 `<video>`；
  2. 发送者和其他成员拿到同一套 ready 附件事实、同一套 locator 主链；
  3. 查看器、会话、cache、swarm runtime 形成完整 backfill / complete / release 闭环；
  4. 原始冷源 `24 小时` 后真实清理，且删除后旧主链不再继续存活；
  5. 关键失败路径都进入测试矩阵，不再靠手测和运气。

## Design Decisions

- 视频正式查看主链固定为 `streaming_asset.manifest`；时间线卡片只允许使用 `poster` 或安全占位，不允许直接拿 `m3u8` 做原生 `<video src>`。
- 图片正式查看主链固定为 `blob_asset.full / original`；时间线卡片优先 `preview`。
- `MediaSessionOwner` 是唯一媒体运行态裁决者；浏览器媒体事件与 swarm 事件都先变信号再裁决。
- `MediaCacheOwner` 只保存本地完整资产真相；不拥有查看器开关和 UI 流程。
- `SwarmRuntime` 只拥有 acquire / backfill / presence / done / release；不拥有业务成功语义。
- 原始冷源删除后：
  - locator 顶层 origin 必须失效；
  - 长期资产主链仍可用；
  - 任何旧附件直链都不能继续偷偷成功。
- 不新增新的 `.rs` 生产文件；优先在现有模块内收口边界。
