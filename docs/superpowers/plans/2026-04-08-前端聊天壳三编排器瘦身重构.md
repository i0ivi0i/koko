# 前端聊天壳三编排器瘦身重构 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在不改变现有聊天业务语义的前提下，把 [frontend/聊天壳.ts](/E:/koko/frontend/聊天壳.ts) 中的恢复链、realtime 链、阅读推进链分别迁入三个新的编排器，让主壳回到装配/接线/render 职责。

**Architecture:** 继续保持 `frontend` 的既有分层：`契约/传输/视图/滚动器/内核` 不推翻，只补 3 个 application orchestration 文件。迁移必须遵守“先锁行为、再定义 command/event 契约、再复制同语义实现、再让聊天壳转调、最后删旧实现”的顺序；`invalid_session` 与 `need_snapshot_reload` 的业务解释只允许落在恢复编排，`near-bottom` 等 DOM 观测只允许留在滚动器。

**Tech Stack:** Lit 3、自定义元素、TypeScript、Vitest、happy-dom、socket.io-client、本地 `localStorage`、现有 XState 房间内核
