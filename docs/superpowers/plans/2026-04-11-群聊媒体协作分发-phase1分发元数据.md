# 群聊媒体协作分发 Phase 1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在不碰现有 `Tus/Rustus` 上传主链的前提下，为 `ready` 附件补齐稳定的协作分发元数据，并把它通过受控 locator 暴露给前端，为后续 Phase 2 的真实 swarm 接线打地基。

**Architecture:** 这一阶段只做“分发元数据真相面”，不做真实 tracker 接线、不引入 WebTorrent 运行态、不修改房间消息展示路径。后端在 `complete_media_upload()` 成功后立刻为附件落 `content_id / content_hash / swarm_id / web_seed_until`，locator 继续由后端权威返回；前端只扩 shared contract、缓存和 metadata-only 边界文件，不伪造 swarm。

**Tech Stack:** Rust (`axum`, `sqlx`, `sha2`, `hex`)、PostgreSQL migration、TypeScript (`vitest`)、现有 `frontend/媒体` 模块。

---

## 范围裁决

这份 spec 已经明确拆成 `Phase 1 ~ Phase 4`。  
按 `writing-plans` 的要求，这里只写 **Phase 1：补齐分发元数据** 的实施计划。

这份 plan 故意不包含：

- `WebTorrent` 真正下载/做种
- tracker 进程接线
- 浏览器 piece cache / service worker
- “内容已过期” 的最终运行态裁决

这些都要等 Phase 1 的元数据真相面先站稳，再另起后续计划。

## Phase 1 locator 目标形状

这一阶段不要伪造 Phase 2 的 tracker/runtime 字段。  
`distribution` 只包含稳定真相：

```ts
export interface 媒体协作分发定位片段 {
  content_id: string;
  content_hash: string;
  swarm_id: string;
  web_seed_until: string; // Unix 秒字符串，和现有 expires_at 心智保持一致
}
```

后端 JSON 目标：

```json
{
  "attachment_id": "att-123",
  "kind": "video",
  "status": "ready",
  "original_url": "/api/attachments/att-123/content?session_id=s-1&variant=original",
  "thumbnail_url": null,
  "distribution": {
    "content_id": "content_att-123",
    "content_hash": "2cf24dba5fb0a30e...",
    "swarm_id": "swarm_2cf24dba5fb0a30e...",
    "web_seed_until": "1775942400"
  }
}
```

这里故意不把 `swarm_id` 假装成最终 `info_hash`。  
Phase 1 只要一个稳定、可持久化、不会反客为主的分发锚点。

        swarm_id: format!("swarm_{content_hash}"),
        content_hash,
        web_seed_until秒: ready_epoch秒 + WEB_SEED_TTL秒,
