# 领域核心架构强化实现计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在不破坏现有群聊行为的前提下，把项目进一步收敛成“领域稳定、前后端与后端技术可替换”的结构。

**Architecture:** 这轮不推倒重来，只做三类高收益重构：先把 `web` 再壳化，再把共享契约从 `core` 中拆出，最后把 `server` 里的 PostgreSQL 适配实现显性化。所有改动都走小步 TDD，优先保护现有 HTTP/WebSocket 行为。

**Tech Stack:** Rust workspace, Dioxus, axum, tokio, serde, sqlx, PostgreSQL, tracing, just, xtask

---

## 范围说明

本计划只做架构强化，不新增业务功能。

保持不变：

- 房间短码规则
- 会话引导规则
- join-or-create 语义
- 文本消息与房间治理接口
- Win11 开发入口与 Linux 部署思路

本轮目标是让这些规则更不依赖具体前端框架、后端框架和存储实现。

## 执行顺序建议

严格按顺序执行：

1. Task 1 前端壳化
2. Task 2 契约拆分
3. Task 3 后端适配层显性化
4. Task 4 文档与总回归

原因：

- 先让前端不再直接抱住实现细节
- 再把共享契约真正从领域核心里分离
- 最后再收口后端适配层

这样每一步都能独立验证，不会一口气改到失控。
