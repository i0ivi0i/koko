# Web 单一视频播放器壳迁移与双壳退场 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把 Web 视频正式播放主链收口到一套 `Video.js v10 (@videojs/html)` 播放器壳，同时保住 `hls.js`、`WebTorrent / P2P / SwarmRuntime` 现有满血能力，并在任何用户可达路径中消灭第二套播放器实现。

**Architecture:** 以 `frontend/媒体/媒体会话.ts` 和 `frontend/聊天媒体编排.ts` 为唯一播放真相 owner；`frontend/媒体/媒体查看器.ts` 退化为图片查看与单一视频壳路由；新增一个薄 `Video.js` 适配层隔离 beta API，把 `HLS / file / blob / native fullscreen` 压成同壳 provider/展示策略。迁移顺序必须是“先补保护测试，再做隔离适配层，再一次性切主链，再退场旧壳与旧依赖”，不允许长期双活。

**Tech Stack:** TypeScript, Lit, Vitest, `@videojs/html`, `hls.js`, `p2p-media-loader-hlsjs`, `webtorrent`

---

## 文件结构与职责锁定

- `frontend/媒体/媒体查看器.ts`
  - 保留图片 `PhotoSwipe` 路径。
  - 视频路径只负责把当前 `媒体查看器项目` 委托给单一 `Video.js` 壳，不再理解 `HLS overlay / Vidstack overlay / 原生全屏旁路`。
- `frontend/媒体/videojs播放器壳.ts`
  - 新建的薄适配层。
  - 隔离 `Video.js v10` HTML/custom-elements API、`hls.js` attach/sync、同会话 native fullscreen 策略。
- `frontend/媒体/媒体会话.ts`
  - 继续做“这一条附件当前如何播放、如何恢复”的唯一运行时真相 owner。
  - 不直接理解 `Video.js`，只输出 `playback / sourceVersion / status`。
- `frontend/聊天媒体编排.ts`
  - 继续把媒体会话快照投影回查看器请求。
  - 不再给查看器提供分裂的壳层依赖；只提供单壳同步所需的稳定输入。
- `frontend/房间消息窗.ts`
  - 继续只做时间线预览，不升级成第二套正式播放器实现。
  - 允许 `<video>` 作为预览元素存在，但不允许承载第二条正式播放主链。
- `frontend/聊天壳.ts`
  - 继续只转发查看器打开意图和媒体会话信号，不直接依赖某个具体播放器库。
- `frontend/入口.ts`
  - 从 `vidstack` 皮肤/样式导入切换到 `Video.js` 官方 HTML 路线资产。
- `frontend/package.json`
  - 新增 `@videojs/html` 当前 beta 版本。
  - 删除 `vidstack` 及其样式依赖导入。
  - 保留 `hls.js`、`p2p-media-loader-hlsjs`、`webtorrent`。
- `frontend/tests/媒体查看器测试.spec.ts`
  - 继续承担查看器级主保护测试。
- `frontend/tests/videojs播放器壳测试.spec.ts`
  - 新增，专门验证 `Video.js` 适配层的 attach/sync/fullscreen 行为。
- `frontend/tests/房间消息窗媒体查看器测试.spec.ts`
  - 锁定“时间线预览不是正式播放器壳”的边界。
- `frontend/tests/聊天应用内核测试.spec.ts`
  - 锁定媒体会话恢复后查看器跟随同步新播放源的跨 owner 行为。

## 迁移总规则

1. Task 1 和 Task 2 可以先在隔离层推进，但不能让用户可达路径形成第二套正式播放器实现。
2. 真正的用户主链切换必须在 **Task 3 单次 cutover** 中完成：同一个提交里同时切桌面 `file/blob/HLS` 主路径，并删除旧公开工厂入口。
3. 移动端 native fullscreen 只能作为同一播放器会话上的展示策略，不能保留独立初始化路径。
4. `WebTorrent / P2P / SwarmRuntime` 永远只能提供字节流/分发表面，不能创建第二个正式 `<video>` 主链。
5. 任何一步只要需要重新暴露 `createHlsVideoOverlay`、`createVidstackVideoOverlay` 或独立 `openNativeVideoFullscreen` 公开入口，就应立即回滚该步实现并重算方案。
