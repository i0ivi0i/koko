# 广播路径入场券直推 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 消除接收端 HTTP locator 往返——将 join_ticket + 完整 swarm 连接线索直接塞进 room_event 广播，让前端收到消息即可创建 prefetch WebTorrent 会话。

**Architecture:** 后端在 `event_to_json` 序列化后、广播前，用 shell 层运行态上下文（ticket_secret、tracker_public_url、web_seed_endpoint、ice_servers）丰富 JSON 中的 `distribution_hint`。前端收到丰富 hint 后跳过 HTTP locator，直接以 prefetch 模式创建 WebTorrent 会话。tracker 入群票据只锚定 info_hash（代码证据：`诊断协作分发join_ticket` 只验 `ih`），因此一张票所有房间成员都能用，可以随公共广播下发。

**Tech Stack:** Rust (socketioxide 0.18.2), TypeScript (WebTorrent), JWT HMAC-SHA256

### 设计约束

- **`web_seed_url` 广播路径不下发**：URL 含 per-session session_id，无法共享。prefetch (deselect=true) 不下载数据，不需要 web_seed。autoplay 激活后 P2P + 强种子提供数据，web_seed 通过后续 locator HTTP 刷新获取。
- **`torrent_url` 用 ticket 鉴权**：广播路径 URL 为 `/api/media/{id}/torrent?ticket=eyJ...`，不含 session_id。后端 endpoint 先查 session_id，没有则降级用 ticket 验票。
- **ice_servers 失败降级**：CloudflareTURN API 失败时 ice_servers = `[]`，P2P 仍对多数 NAT 类型有效。

- [x] **Step 3: 实现——定义 `SwarmBroadcastContext` 并修改 `attachments_to_json` / `event_to_json`**

在 `src/外壳/协议响应.rs` 中：

```rust
/// 广播路径 swarm 运行态上下文。
/// shell 层负责传入，attachments_to_json 负责丰富 distribution_hint JSON。
pub(crate) struct SwarmBroadcastContext<'a> {
    pub ticket_secret: Option<&'a str>,
    pub tracker_public_url: &'a str,
    pub ice_servers: serde_json::Value,
    pub ticket_ttl_seconds: i64,
    pub now_epoch_seconds: i64,
}
```

修改 `event_to_json` 签名增加 `swarm_ctx: Option<&SwarmBroadcastContext<'_>>`，透传给 `attachments_to_json`。

同步修改 `events_to_json` 签名也增加同一参数（历史/订阅路径调用时传 `None`）：

```rust
pub(crate) fn events_to_json(
    events: Vec<contract::领域事件>,
    session_id: Option<&str>,
    swarm_ctx: Option<&SwarmBroadcastContext<'_>>,
) -> Vec<serde_json::Value> {
    events
        .into_iter()
        .map(|event| event_to_json(event, session_id, swarm_ctx))
        .collect()
}
```

`attachments_to_json` 中，对每个有 `分发线索` 的附件，在已有 4 字段基础上追加：
- `join_ticket` / `ticket_expires_at`：用 `jsonwebtoken::encode` 对 `{ih, iat, exp}` 签名（复用与 `签发协作分发join_ticket` 相同的 JWT 逻辑，但 `sub`/`aid` 用 `"__room_broadcast__"` 标识来源）
- `announce_urls`：`[swarm_ctx.tracker_public_url]`
- `web_seed_url`：广播路径固定为 `null`（URL 含 per-session 鉴权，无法共享；prefetch deselect=true 不下载，不需要）
- `torrent_url`：`/api/media/{attachment_id}/torrent?ticket={signed_ticket}`（ticket 鉴权替代 session_id）
- `ice_servers`：直传（失败时降级为 `[]`）

- [ ] **Step 1: 在 `媒体定位.ts` 增加 `写入定位缓存` 公开方法**

locator 缓存需要接受从 hint 直推写入，这样后续 autoplay/viewport 路径调 `获取定位` 时能命中缓存而不再发 HTTP 请求。

在 `创建媒体定位器` 返回对象中新增：

```typescript
写入定位缓存(attachmentId: string, value: 媒体定位结果): void {
  const currentSessionId = deps.getSessionId();
  const record: 媒体定位缓存记录 = {
    attachmentId,
    sessionId: currentSessionId,
    value,
    stale: false,
  };
  cache.set(attachmentId, record);
  void repo.保存(record);
},
```

同时在 `创建媒体定位器` 的返回对象（`return { 读取缓存, 获取定位, 标记过期, 放弃未完成定位, 清空 }`）中增加此方法，使外部可调。

注意：`创建媒体定位器` 返回的是对象字面量（无独立类型声明），直接在 return 对象中加入即可。

- [x] **Step 3: 改写 `预热权威消息媒体分发` 实现**

> **设计决策变更（实施时发现）：** 丰富 hint 路径只写入 locator 缓存，不在 prewarm 阶段调 `解析协作分发源`。
> 原因：`解析协作分发源` 会触发完整 WebTorrent session 创建链，而 `refreshJoinTicket` 依赖回调会冗余触发 HTTP locator，形成环路。
> locator 缓存写入已消除核心瓶颈（80-200ms HTTP locator 往返），WebTorrent session 在 ~50ms 后 viewport sync 时自然创建，不增加可感知延迟。
