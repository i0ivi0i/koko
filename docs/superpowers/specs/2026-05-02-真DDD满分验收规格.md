## 2. 满分定义

### 2.1 DDD 满分

DDD 满分不是目录名像 DDD，而是代码里的业务模型能被业务语言直接解释。

必须同时满足：

1. `身份 / 房间 / 消息 / 媒体 / 恢复 / 实时` 六个后端 bounded context 都有唯一业务 owner。
2. 前端 `房间 / 时间线 / 媒体播放会话 / 媒体查看器 / 协作分发 / 恢复 / 实时 / 总装` 只拥有交互真相和展示真相。
3. 权限、成员资格、消息成立、媒体成立、恢复合法性只在后端 domain / application 裁决。
4. 同一业务事实不能在 adapter、shell、前端状态、localStorage、播放器或测试支架里再判一遍。
5. 领域对象和值对象必须承载行为和不变量，不能只是字段袋子。
6. 事件必须是领域已经发生的事实，不能是 UI 指令、框架回调或技术状态冒充领域事件。
7. 业务术语必须稳定：禁止用 `manager / helper / wrapper / common / utils / processor` 解释业务职责。
8. 完成矩阵里每个“已完成”必须有当前代码和当前命令证据，禁止把未来计划写成完成态。

DDD 满分失败条件：

1. 有任何业务事实同时存在两个 owner。
2. 有任何旧入口、过渡入口、兼容链、re-export、只转发一次的桥接函数仍在生产代码里。
3. 前端用本地状态、实时回声、恢复缓存或播放状态自行发明业务成立性。
4. handler、repo、adapter、shell 里出现“顺手裁决业务”的分支。

### 2.2 六边形边界满分

六边形满分是依赖方向真实向内，不是只画了 port / adapter。

必须同时满足：

1. `domain / application` 不引用 `Axum / SQLx / socketioxide / DOM / localStorage / Video.js / WebTorrent` 具体 API。
2. adapter 只负责 IO、协议、鉴权材料读取、错误转码、SQL 或外部系统翻译。
3. shell 只负责用户交互编排、DOM 表达、事件转译和调用应用端口。
4. `contract` 只放跨壳稳定 command / query / event / snapshot / error，禁止混入页面文案、布局词、框架类型和某个壳专属流程。
5. 缺少端口实现必须编译期暴露，不能靠 `Ok(None)`、`Ok(vec![])`、默认空方法或 `系统错误` 把能力缺口藏到运行期。
6. adapter 不能横向调用另一个 adapter 的私有 helper 来拼业务结果。
7. 总装只能装配依赖，不能承载业务判断、媒体对账、清理策略、恢复策略或实时补发规则。
8. 每条外部入口都有一条可追踪路径：inbound adapter -> application -> domain / port -> outbound adapter -> contract response。

六边形满分失败条件：

1. 内层出现外层框架类型。
2. 适配器之间互相借道。
3. 总装文件继续承担业务主链。
4. 端口 trait 有默认空实现或默认成功实现。
5. 错误语义被框架错误或泛化 `系统错误` 吞掉。

### 2.3 简洁度满分

简洁度满分不是机械压行数，而是更少概念、更少路径、更短主链、更低维护成本。

必须同时满足：

1. 没有只转发一次的函数。
2. 没有只包一层的对象。
3. 没有为了“像架构”存在的文件、trait、类或目录。
4. 没有长期存在的 `兼容 / legacy / facade / wrapper / helper / common / utils` 生产路径。
5. 热点文件必须继续下降到可读范围，且每个剩余大文件都能解释为什么不能再拆。
6. `cargo clippy -- -W dead_code -W unused_imports -W unused_variables` 零 warning。
7. `pnpm --dir frontend test`、`cargo test` 和架构门禁都全绿。
8. 新增抽象必须删除更多复杂度；如果抽象只是搬家，判负。

简洁度满分失败条件：

1. 为了收口旧复杂度新建一层门面。
2. 为了迁移安全保留旧路径和新路径并存。
3. 代码变短但主链更难追。
4. 测试改成依赖私有转发壳，反向锁死冗余结构。

## 3. 必须删除或收口的剩余债务

### 3.1 后端

必须继续审查并收口：

1. `src/媒体/适配.rs`
   - 当前风险：媒体资产、locator、内容读取、origin 描述、冷源退场、仓储翻译集中度过高。
   - 满分方向：按 `资产读取 / 上传会话 / 协作分发 / 清理退场 / locator 投影` 拆成真实 owner，不新增纯转发文件。

2. `src/媒体/上传/外壳/媒体上传.rs`
   - 当前风险：HTTP/Tus/转发/source_hash/做种触发/响应构造混在同一外壳热点。
   - 满分方向：按协议入口和业务命令拆薄，外壳只翻译请求、调用用例、返回响应。

3. `src/总装.rs`
   - 当前风险：配置、依赖装配、测试支撑、媒体路径推导等可能继续吸附。
   - 满分方向：只保留装配和启动必要 glue，业务推导下沉到对应 owner。

4. `src/应用/mod.rs`
   - 当前风险：跨业务端口和共享校验仍可能成为新的总入口。
   - 满分方向：共享端口只保留真正跨业务稳定基础；业务用例端口下沉到各业务应用。

5. `src/外壳/mod.rs`
   - 当前风险：总路由壳继续聚合过多协议细节。
   - 满分方向：只保留 route mount 和状态装配，具体 handler 落到业务外壳。

### 3.2 前端

必须继续审查并收口：

1. `frontend/房间消息窗/壳.ts`
   - 当前风险：虽已删除自动播观察包装，但仍承担滚动、虚拟列表、媒体窗口、唯一播放器宿主、冻结帧、查看器入口等多种交互 owner。
   - 满分方向：保留消息视口壳，继续把冻结帧、唯一播放器宿主同步、媒体窗口观察等可独立 owner 下沉。

2. `frontend/房间消息窗/附件渲染.ts`
   - 当前风险：附件投影函数和渲染模板仍偏密。
   - 满分方向：把纯投影、图片附件、视频附件、viewer 入口拆成小而真实的模块，不做模板碎片海。

3. `frontend/总装/聊天壳.ts`
   - 当前风险：总壳仍可能持有交互编排和业务流程粘合。
   - 满分方向：只读快照、挂子组件、转译 UI 事件，不直接操作内核 helper。

4. `frontend/总装/聊天应用内核.ts`
   - 当前风险：应用内核仍聚合房间、恢复、实时、媒体、输入、后台存储等多条流程。
   - 满分方向：各应用 owner 自治，内核只做命令路由和快照合并。

5. `frontend/媒体/播放会话/应用.ts`
   - 当前风险：播放会话、查看器、协作分发、自动播热路径仍需要证明没有第二 player / 第二字节 owner。
   - 满分方向：保持 `全局唯一播放器`、`资产协作分发运行时`、`全局丝滑自动播` 三者边界，删掉任何回流候选。

## 4. 满分执行顺序

必须按顺序推进，不能先做看起来容易的大搬家。

### 4.1 第一阶段：消灭假的安全感

目标：让不能满分的事实都被测试和门禁看见。

必须新增或强化：

1. 后端架构守卫：禁止端口 trait 默认空实现。
2. 后端架构守卫：禁止 `src/应用/mod.rs` 新增业务用例转发。
3. 后端架构守卫：禁止 adapter 横向调用另一个 adapter 私有 helper。
4. 前端架构守卫：禁止 `门面 / facade / wrapper / legacy / 兼容` 生产文件回流。
5. 前端架构守卫：热点文件只允许变薄，不允许靠调高预算通过。
6. 完成矩阵守卫：只要热点未收口或真实浏览器未复跑，禁止写“满分完成”。

验收：

```powershell
cargo test --test 架构边界守卫
node scripts/check-frontend-architecture-fitness.mjs
node scripts/check-frontend-browser-app-constitution.mjs
```

### 4.2 第二阶段：先删兼容链，再拆过厚 owner

目标：删除第二入口、过渡桥、兼容链，避免一边拆一边留垃圾。

必须处理：

1. 所有生产路径里的 `兼容 / legacy / facade / wrapper / helper / common / utils` 命名。
2. 所有只转发一次的函数和 re-export。
3. 所有测试直接依赖旧私有包装函数的锚点。
4. 所有完成矩阵里把迁移债务写成完成态的描述。

验收：

```powershell
rg -n "兼容|legacy|facade|wrapper|helper|common|utils|pub use|re-export" src frontend tests scripts docs/superpowers
```

命中不等于一定失败，但每一处都必须能解释为业务语义或测试支撑；解释不通就删。

### 4.3 第三阶段：后端六边形收口

目标：后端业务核心删掉总控吸附，adapter 变薄。

执行顺序：

1. 先处理 clippy warning，包含 `SourceHash媒体复用结果` 的 `large_enum_variant`。
2. 拆薄 `src/媒体/适配.rs`，把仓储翻译按业务 owner 下沉。
3. 拆薄 `src/媒体/上传/外壳/媒体上传.rs`，把 HTTP/Tus/source_hash/forward 的协议壳分开。
4. 拆薄 `src/总装.rs`，只留下启动和依赖装配。
5. 检查 `src/应用/mod.rs` 和 `src/外壳/mod.rs`，删掉跨业务总入口趋势。

验收：

```powershell
cargo check --all-targets
cargo test
cargo clippy -- -W dead_code -W unused_imports -W unused_variables
cargo test --test 架构边界守卫
cargo test --test 媒体测试边界守卫
```

### 4.4 第四阶段：前端交互核心收口

目标：前端只保留交互真相，不抢业务真相，不制造第二播放器或第二媒体字节 owner。

执行顺序：

1. 拆薄 `frontend/房间消息窗/壳.ts`，继续下沉冻结帧、媒体窗口观察、唯一播放器宿主同步等独立 owner。
2. 拆薄 `frontend/房间消息窗/附件渲染.ts`，把图片、视频和纯投影分开。
3. 拆薄 `frontend/总装/聊天壳.ts`，让它只读快照和挂组件。
4. 拆薄 `frontend/总装/聊天应用内核.ts`，把房间、恢复、实时、媒体命令还给各自应用 owner。
5. 拆薄 `frontend/媒体/播放会话/应用.ts`，继续守住唯一播放器、协作分发和自动播边界。

验收：

```powershell
pnpm --dir frontend test
pnpm --dir frontend exec tsc --noEmit
node scripts/check-frontend-architecture-fitness.mjs
node scripts/check-frontend-browser-app-constitution.mjs
```

### 4.5 第五阶段：真实浏览器闭环

目标：证明架构收口没有破坏万人群聊关键体验。

必须覆盖：

1. 进入稳定烟测房间 `1234b`。
2. 加载历史时间线。
3. 接收实时消息。
4. 图片附件和视频附件卡片正常表达。
5. 自动播放、查看器打开关闭、滚动切换、唯一播放器 owner 交接正常。
6. 第二浏览器身份能看到同一条媒体体验。

验收方式：

```powershell
pnpm --dir frontend test
pnpm --dir frontend exec tsc --noEmit
cargo test
```

同时用真实浏览器或项目既有 Playwright/browser-trace 链路复跑 `1234b`。没有这一步，不得把前端体验写成满分。

## 6. 满分宣称格式

只有全部验收通过后，最终报告才允许这样写：

```text
DDD: 10/10
六边形边界: 10/10
简洁度: 10/10
```

报告必须同时列出：

1. 删除了哪些旧入口、兼容链、转发壳。
2. 哪些 owner 被拆薄，拆到了哪里。
3. 哪些门禁新增或收紧。
4. 哪些真实浏览器路径已经验证。
5. 哪些命令新鲜通过。
6. `git status --short` 是否为空。

禁止写法：

1. “基本满分”。
2. “理论上满分”。
3. “除了烟测都满分”。
4. “还有少量 warning 但不影响满分”。
5. “先保留兼容层，后续再删”。

第二遍：按六边形边界审查

第三遍：按简洁度审查
结论：本文没有允许新 facade 替旧 facade，也没有把大文件机械切碎写成目标。修正点：明确 clippy warning、热点文件和真实浏览器烟测都是满分阻断项。
