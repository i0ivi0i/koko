# 真 DDD 三满分最终验收规格

日期：2026-05-03
状态：Design（当前不允许宣称满分）
适用范围：`koko` 后端 Rust、前端 TypeScript、实时群聊、媒体上传与播放、恢复链、架构门禁、完成矩阵、真实浏览器烟测和后续所有“满分完成”声明。

本文只回答一个问题：**怎样才能把 `koko` 证明到 `DDD: 满分`、`六边形边界: 满分`、`简洁度: 满分`。**

本文不替代：

- `docs/superpowers/specs/2026-05-01-真DDD领域驱动重构铁律.md`
- `docs/superpowers/specs/2026-04-23-万人实时群聊去屎山长期约束.md`
- `docs/superpowers/specs/2026-04-25-项目视频播放要求.md`
- `docs/superpowers/specs/群聊视频禁止事项.md`

本文是这些规则之上的最终验收尺。旧文档负责原则和专项红线；本文负责判定什么时候可以说“已经满分”，什么时候必须降级回“验证中”。

---

## 0. 直接结论

**之前要求满分，不等于现在已经满分。**

上一轮“满分”声明的错误在于：它证明了旧根入口大量退场、关键门禁和真实浏览器烟测通过，却没有证明所有稳定语义、所有热点、所有死代码入口、所有完成声明都被同一把硬尺锁住。

当前必须撤回“三满分完成态”，降级为：

| 维度 | 当前判定 | 主要缺口 |
| --- | --- | --- |
| DDD | 验证中 | 仍要证明所有业务真相只在唯一 owner 决定，完成矩阵不能先把旧证据写成满分。 |
| 六边形边界 | 验证中 | `src/媒体/协作分发/共享语义.rs` 仍泄漏 `axum::http` 类型，稳定语义层没有纯净。 |
| 简洁度 | 验证中 | 仍有超 987 行生产热点和 TypeScript 未使用代码入口，门禁覆盖不足。 |

这不是否定已有重构。已有重构有效，但它还没有达到“彻底无屎山”的证明标准。

## 1. 为什么还没满分

### 1.1 满分声明比真实门禁更大

`docs/superpowers/reports/2026-05-01-真DDD重构完成矩阵.md` 写了 `DDD: 满分 / 六边形边界: 满分 / 简洁度: 满分`，但当前门禁没有覆盖所有能推翻满分的事实。

完成矩阵以后只能记录已经被当前代码、当前门禁、当前真实烟测共同证明的事实。任何一条证据过期、门禁漏项、真实体验未复跑，都必须降级回验证中。

### 1.2 稳定语义模块仍混入协议类型

当前 `src/媒体/协作分发/共享语义.rs` 通过 `src/lib.rs` 暴露为跨模块稳定语义入口，但文件内直接依赖 `axum::http::{HeaderMap, Uri}`，且 `读取协作分发tracker对外地址` 的 `HeaderMap` 参数没有被使用。

这说明：

1. 稳定语义层还没有彻底摆脱 HTTP / Axum。
2. adapter / shell 的协议材料仍能穿进共享语义。
3. 六边形“内层不依赖外层”还没有被硬证明。

### 1.3 热点预算只锁住部分文件

当前 `tests/架构边界守卫.rs` 的完成态热点检查只列出 6 个文件。复审时仍看到这些生产热点超过 987 物理行：

| 文件 | 复审时物理行 | 当前含义 |
| --- | ---: | --- |
| `src/媒体/资产/外壳.rs` | 1151 | 后端媒体资产 HTTP 外壳仍过厚 |
| `frontend/媒体/资产协作分发运行时.ts` | 1622 | WebTorrent 协作分发运行时仍过厚 |
| `frontend/房间消息窗/壳.ts` | 1434 | 房间消息窗壳仍过厚 |
| `frontend/媒体/媒体发布.ts` | 1261 | 媒体发布链仍过厚 |
| `frontend/媒体/媒体查看器.ts` | 1069 | 查看器壳仍过厚 |
| `frontend/媒体/媒体协作分发.ts` | 1064 | 协作分发底层适配仍过厚 |
| `frontend/媒体/videojs播放器壳.ts` | 1036 | 播放器适配壳仍过厚 |

满分不能靠“没列入门禁”绕过去。所有生产热点都必须被统一扫描、统一登记、统一收口。

### 1.4 TypeScript 死代码入口没有默认关闭

当前 `frontend/tsconfig.json` 有 `strict`，但没有开启 `noUnusedLocals` / `noUnusedParameters`。普通 `pnpm --dir frontend exec tsc --noEmit` 可以通过，但加上：

```powershell
pnpm --dir frontend exec tsc --noEmit --noUnusedLocals --noUnusedParameters
```

会暴露生产代码和测试中的未使用 import / 变量。满分状态下，死代码不能靠默认编译配置漏过去。

## 2. 满分定义

### 2.1 DDD 满分

DDD 满分不是目录名像 DDD，而是业务模型、业务语言、业务不变量都落在唯一 owner。

必须同时满足：

1. 后端 `身份 / 房间 / 消息 / 媒体 / 恢复 / 实时` 都有唯一业务 owner。
2. 前端 `房间 / 时间线 / 媒体播放会话 / 媒体查看器 / 协作分发 / 恢复 / 实时 / 总装` 只拥有交互真相、展示真相和浏览器能力适配。
3. 权限、成员资格、消息成立、媒体成立、恢复合法性只在后端 domain / application 裁决。
4. 同一业务事实不能在 adapter、shell、前端状态、localStorage、播放器、测试支架里再判一遍。
5. 领域对象和值对象必须承载不变量，不能只是字段袋子。
6. 事件必须是已经发生的领域事实，不能是 UI 指令、框架回调或技术状态冒充领域事件。
7. `contract` 只放跨壳稳定 command / query / event / snapshot / error，不放页面文案、布局词、框架类型和某个壳专属流程。
8. 完成矩阵必须与当前代码状态一致，不能把计划、历史通过记录、局部烟测写成完成态。

DDD 满分失败条件：

1. 任何业务事实有两个 owner。
2. 任何旧入口、过渡入口、兼容链、只转发一次的桥接函数仍在生产主链。
3. 前端用本地状态、实时回声、恢复缓存或播放状态自行宣布业务成立。
4. handler、repo、adapter、shell、总装里出现“顺手裁决业务”的分支。
5. 完成矩阵写满分，但当前门禁、测试或真实烟测无法证明。

### 2.2 六边形边界满分

六边形满分是依赖方向真实向内，不是文件夹名字像 port / adapter。

必须同时满足：

1. `domain / application / contract / 稳定共享语义` 不引用 `Axum / SQLx / socketioxide / tower / reqwest / DOM / localStorage / Video.js / WebTorrent` 具体 API。
2. adapter 只负责 IO、协议、鉴权材料读取、错误转码、SQL 或外部系统翻译。
3. shell 只负责用户交互编排、DOM 表达、HTTP / socket 路由、事件转译和调用应用端口。
4. 稳定共享语义只接收原始字符串、自有值对象或标准库类型；协议类型在 shell / adapter 边界被翻译掉。
5. 缺少端口实现必须编译期暴露，不能靠 `Ok(None)`、`Ok(vec![])`、默认空方法或 `系统错误` 把能力缺口藏到运行期。
6. adapter 不能横向调用另一个 adapter 的私有 helper 来拼业务结果。
7. 总装只能装配依赖，不能承载业务判断、媒体对账、清理策略、恢复策略或实时补发规则。
8. 每条外部入口都有可追踪路径：inbound adapter / shell -> application -> domain / port -> outbound adapter -> contract response。

六边形满分失败条件：

1. 内层出现外层框架类型。
2. 稳定语义模块需要 `axum::http::HeaderMap`、`SocketRef`、`HTMLElement`、`Video.js` 这类外层类型。
3. 适配器之间互相借道。
4. 总装文件继续承担业务主链。
5. 错误语义被框架错误或泛化 `系统错误` 吞掉。

### 2.3 简洁度满分

简洁度满分不是机械压行数，而是更少概念、更少路径、更短主链、更低维护成本。

必须同时满足：

1. 没有只转发一次的函数。
2. 没有只包一层的对象。
3. 没有为了“像架构”存在的文件、trait、类或目录。
4. 没有长期存在的 `兼容 / legacy / facade / wrapper / helper / common / utils / fallback / shim / temp / old / 旧 / 门面 / 包装` 生产路径。
5. 所有生产 `.rs` / `.ts` 热点都进入统一预算扫描；最终满分状态不允许生产源码文件超过 987 物理行。
6. Rust 侧 `cargo clippy --all-targets -- -D warnings` 必须零 warning。
7. TypeScript 侧 `pnpm --dir frontend exec tsc --noEmit --noUnusedLocals --noUnusedParameters` 必须通过。
8. 前端 barrel / re-export 只能服务真正稳定公开表面；不得让 `index.ts` 重新成为大而全的业务总入口。
9. 新增抽象必须删除更多复杂度；如果抽象只是搬家或拉长主链，判负。

简洁度满分失败条件：

1. 为了收口旧复杂度新建一层门面。
2. 为了迁移安全保留旧路径和新路径并存。
3. 代码变短但主链更难追。
4. 测试改成依赖私有转发壳，反向锁死冗余结构。
5. TypeScript 或 Rust 默认检查允许未使用代码、死导入、死参数长期存在。

## 3. 必须先落地的硬门禁

这些不是“优化项”，而是三满分前置条件。没有它们，不准开始大规模拆文件。

### 3.1 完成矩阵降级门禁

目标：仓库不能同时存在“当前不是满分”的 spec 和“已经满分”的完成矩阵。

必须做：

1. 把 `docs/superpowers/reports/2026-05-01-真DDD重构完成矩阵.md` 状态改为 `验证中`。
2. 在矩阵中登记本轮三条硬缺口：`media_distribution` 泄漏 Axum、热点门禁覆盖不全、TS unused 未默认阻断。
3. 新增守卫：只要任一满分前置门禁失败，完成矩阵不得出现 `DDD: 满分`、`六边形边界: 满分`、`简洁度: 满分` 或 `状态：已完成`。

验收：

```powershell
cargo test --test 架构边界守卫
```

### 3.2 稳定语义纯净门禁

目标：`domain / application / contract / 稳定共享语义` 不能泄漏外层协议类型。

必须做：

1. `src/媒体/协作分发/共享语义.rs` 删除 `axum::http::{HeaderMap, Uri}` 依赖。
2. `读取协作分发tracker对外地址` 改成只接收稳定输入，例如 `configured_tracker_public_url: &str`。
3. 如果需要解析 URL，使用自有小值对象或把解析留在 shell / adapter；不要为了一个 host 判断把 Axum / HTTP 类型带进稳定语义层。
4. `src/lib.rs` 若继续暴露 `media_distribution` 根别名，必须证明它是稳定共享语义而不是第二总入口；更优路径是让调用方直连 `crate::media::distribution` 下的明确 owner。
5. `tests/媒体测试边界守卫.rs` 增加禁止项，至少扫描 `src/媒体/协作分发/共享语义.rs` 中不得出现 `axum::`、`HeaderMap`、`Uri`、`StatusCode`、`Json<`、`State<`。

验收：

```powershell
cargo test --test 媒体测试边界守卫
cargo clippy --all-targets -- -D warnings
```

### 3.3 全量热点预算门禁

目标：不能靠“没列入数组”绕过简洁度满分。

必须做：

1. 后端新增全量生产 `.rs` 热点扫描，排除 `tests/`、`target/`、迁移 SQL、生成物，只扫 `src/`。
2. 前端新增全量生产 `.ts` 热点扫描，排除 `frontend/tests/`、`frontend/dist/`、`frontend/node_modules/`、`.d.ts`、lockfile、构建输出。
3. 满分状态下任一生产源码文件超过 987 物理行直接失败。
4. 如果执行中暂时需要阶段性拆分，完成矩阵必须保持 `验证中`，不能写满分。
5. 大文件拆分只能按真实 owner 拆，不允许新增 `helper / utils / common / wrapper / facade`。

首批必须收口的热点：

| 文件 | 满分方向 |
| --- | --- |
| `src/媒体/资产/外壳.rs` | 拆出 query 解析、Range 响应、locator 响应投影、presence 上报端点，不让一个 HTTP 外壳同时吞所有媒体资产协议。 |
| `frontend/媒体/资产协作分发运行时.ts` | 拆出会话生命周期、join ticket 续租、piece 选择、事件绑定、预算投影，保留一个明确运行时 owner。 |
| `frontend/房间消息窗/壳.ts` | 只留消息视口壳；冻结帧、播放器宿主同步、媒体窗口观察、候选预热继续下沉。 |
| `frontend/媒体/媒体发布.ts` | 拆出草稿状态、上传调度、诊断映射、完成发布编排，不能让发布器成为媒体总控。 |
| `frontend/媒体/媒体查看器.ts` | 拆出图片查看器、视频查看器、全屏适配、状态投影，不能让查看器拥有播放真相。 |
| `frontend/媒体/媒体协作分发.ts` | 拆出 WebTorrent 适配、持久 chunk store、source 探测、peer 信号适配，不能把成熟轮子再包成第二核心。 |
| `frontend/媒体/videojs播放器壳.ts` | 拆出 source 设置、宿主迁移、全屏适配、错误转译，Video.js 仍只做播放器壳。 |

验收：

```powershell
cargo test --test 架构边界守卫
node scripts/check-frontend-architecture-fitness.mjs
```

### 3.4 TypeScript dead-code 门禁

目标：未使用代码不能再靠默认 `tsc --noEmit` 漏过去。

必须做：

1. 清理生产代码和测试中的未使用 import、变量、参数、类型。
2. 开启 `noUnusedLocals` / `noUnusedParameters`，或新增等价脚本并纳入 `frontend/package.json` 的 `build` / 架构验证链。
3. 所有 `@ts-expect-error` 必须有 owner 和原因；平台适配里确实需要的类型缺口要被局部锁住，不能扩散。
4. 测试支架不允许长期保存未使用端口、未使用 fake、未使用 helper。

验收：

```powershell
pnpm --dir frontend exec tsc --noEmit --noUnusedLocals --noUnusedParameters
pnpm --dir frontend test
```

## 4. 执行顺序

必须按顺序推进，不能先做看起来爽的大搬家。

### 4.1 第一阶段：先让谎话不能通过

目标：把完成矩阵和门禁对齐，让“还没满分”能被自动检测出来。

步骤：

1. 降级完成矩阵为 `验证中`。
2. 加完成矩阵守卫：满分前置门禁失败时禁止 `状态：已完成`。
3. 加稳定语义纯净门禁，先让 `axum::http` 泄漏失败。
4. 加全量热点扫描，先让所有超 987 生产热点失败。
5. 加 TypeScript dead-code 命令，先让未使用代码失败。

这一阶段允许 RED。没有 RED，就说明门禁没有抓到真实缺口。

### 4.2 第二阶段：TDD 修掉边界泄漏

目标：修 `media_distribution` 的六边形违规。

步骤：

1. 先写或加强 `tests/媒体测试边界守卫.rs`，确认 `src/媒体/协作分发/共享语义.rs` 出现外层协议类型时失败。
2. 删除 `HeaderMap` 参数和 `Uri` 依赖，把协议解析留在 shell / adapter。
3. 修改调用方，只传稳定字符串或自有值对象。
4. 跑媒体边界守卫、clippy、相关媒体测试。

验收：

```powershell
cargo test --test 媒体测试边界守卫
cargo test --test 协作分发测试
cargo clippy --all-targets -- -D warnings
```

### 4.3 第三阶段：TDD 清死代码入口

目标：让 TypeScript 未使用代码默认不可通过。

步骤：

1. 运行 `pnpm --dir frontend exec tsc --noEmit --noUnusedLocals --noUnusedParameters`，记录 RED。
2. 按 owner 清理未使用 import、变量、参数；测试里也是同一标准。
3. 对确实需要的副作用 import，改成显式 side-effect import 或加局部说明。
4. 把 unused 检查写入 `frontend/package.json` 或 `tsconfig.json`。
5. 跑前端测试和类型检查。

验收：

```powershell
pnpm --dir frontend exec tsc --noEmit --noUnusedLocals --noUnusedParameters
pnpm --dir frontend test
node scripts/check-frontend-architecture-fitness.mjs
```

### 4.4 第四阶段：按 owner 拆热点

目标：所有生产源码文件低于 987 物理行，同时主链更短、更清楚。

执行规则：

1. 每个热点先写 characterization test 或边界守卫，锁住当前行为。
2. 先移动纯投影、纯解析、纯适配，再移动生命周期 owner。
3. 每拆一次必须删掉旧路径，不留兼容入口。
4. 每个新增文件名必须表达业务 owner，不准叫 helper / common / wrapper。
5. 每个阶段结束都跑对应局部测试，不等最后再补。

验收：

```powershell
cargo test --test 架构边界守卫
cargo test --test 媒体测试边界守卫
node scripts/check-frontend-architecture-fitness.mjs
pnpm --dir frontend test
```

### 4.5 第五阶段：删除第二表面和过宽 barrel

目标：没有大而全总入口、没有隐性第二主链。

必须审查：

1. `frontend/媒体/index.ts` 是否只是稳定公开表面，还是又变成媒体业务总入口。
2. Rust `pub use` 是否只是稳定领域语言，还是隐藏跨 owner 入口。
3. 测试支架是否只支撑测试，还是替生产 owner 做判断。
4. `scripts/` 和 dev 工具是否被生产链路扫描成第二入口。

验收：

```powershell
rg -n "\bpub use\b|export \* from|export \{.*\} from" src frontend -g "*.rs" -g "*.ts"
node scripts/check-frontend-architecture-fitness.mjs
```

命中不等于必删，但每一处必须有稳定公开表面理由；解释不通就直连真实 owner。

### 4.6 第六阶段：真实浏览器闭环

目标：证明大刀阔斧后没有破坏万人群聊关键体验。

必须覆盖稳定房间 `1234b`：

1. A/B 两个干净浏览器身份进房。
2. 历史时间线加载。
3. 文本实时增量秒达。
