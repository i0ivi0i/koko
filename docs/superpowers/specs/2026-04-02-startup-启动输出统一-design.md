# 启动输出统一设计

日期：2026-04-02

## 背景

当前项目的启动体验分裂在两层：

- Rust 主程序掌握后台口令真相、监听地址真相、启动成败真相
- `run.ps1` 又额外维护一套面向人的启动提示

这样会带来两个问题：

1. Windows 本地开发和未来 Linux 直接运行二进制时，看到的启动信息不一致
2. 首页地址、`/admin` 地址、当前管理员口令这类面向部署者的信息会出现双份逻辑，长期必然漂移

## 目标

把“启动时该告诉部署者的信息”统一收回 Rust 主程序，让 `run.ps1` 退回薄启动器。

本次只解决启动输出统一，不改后台会话模型，不改 `/admin` 认证协议，不扩其他运维功能。

## 核心决策

### 1. Rust 统一打印人话启动横幅

Rust 主程序在启动成功后统一打印：

- 首页地址
- `/admin` 地址
- 当前管理员口令

如果本次是首次创建 `config/koko.toml` 或首次从 `KOKO_ADMIN_TOKEN` 导入口令，还要额外打印一句一次性提示，明确告知部署者当前口令来源和是否需要立即备份。

这些输出使用普通 `println!`，不走 `tracing`。

原因：

- 这是面向人的部署提示，不是面向调试系统的技术日志
- 需要在 PowerShell、Linux 终端、systemd/journal 里都保持同一套可读文案

### 2. `run.ps1` 退回薄启动器

`run.ps1` 继续负责：

- 准备数据库
- 执行前端 bundle
- 设置环境变量
- 启动 Rust 二进制
- 可选自动打开浏览器

`run.ps1` 不再负责：

- 解析配置文件并打印管理员口令
- 维护首页地址和 `/admin` 地址的人话提示逻辑
- 复制 Rust 已经知道的启动文案

PowerShell 里最终看到的主要启动提示，应直接来自 Rust 标准输出。

可执行边界必须明确成这样：

- `run.ps1` 在真实启动链路里，不再把 Rust stdout/stderr 完全吞到日志文件后自己复述核心启动提示
- PowerShell 终端最终看到的首页地址、`/admin`、当前管理员口令，必须直接来自 Rust 标准输出
- 如果仍需保留日志文件，最多允许“终端直通 + 同步落日志”，不允许“脚本吞 stdout 再手工重播核心启动横幅”
- `-DryRun` 仍可保留脚本自己的准备步骤预演，但不能伪造一套 Rust 已成功启动后的首页地址、`/admin`、当前管理员口令横幅

### 3. 管理员口令真相保持不变

后台口令真相仍然保持在 `config/koko.toml`：

- 文件存在：直接读取
- 文件不存在：首次启动自动创建目录、生成口令并写入文件
- 若首次启动时存在 `KOKO_ADMIN_TOKEN`：只做一次性导入，写入文件后由文件接管

本次不改变这条真相链，只统一“如何把真相告诉部署者”。

## 启动行为

### Rust 二进制直接启动

无论在 Windows 还是 Linux，只要 Rust 二进制成功启动，都应该打印统一启动横幅，例如：

```text
==> 首页地址: http://127.0.0.1:8080/
==> 管理入口: http://127.0.0.1:8080/admin
==> 当前管理员口令: admin-xxxxxxxx
```

地址派生规则必须统一，不允许脚本和 Rust 各算一套：

- 若监听地址是 `0.0.0.0:<port>` 或空 host：
  - Rust 打印本机地址 `http://127.0.0.1:<port>/`
  - Rust 额外打印所有可用局域网 IPv4 地址
- 若监听地址是 IPv6 unspecified（例如 `:::<port>`）：
  - Rust 至少打印一个本地可访问地址和可用局域网地址，不能把 `::` 直接当作最终用户访问地址
- 若监听地址是明确 hostname / IPv4 / IPv6：
  - Rust 按该 host 直接生成首页地址与 `/admin` 地址

Windows 的 `run.ps1` 和未来 Linux 直接运行二进制，都必须复用这一套规则。

如果本次是首次生成或首次导入口令，再补一句：

```text
==> 本次已写入 config/koko.toml，请立即备份管理员口令
```

### `run.ps1` 启动

`run.ps1` 负责把服务启动起来并让 Rust 自己输出上述横幅。

Rust 横幅触发点必须晚于以下步骤全部成功：

- 数据库连接成功
- 后台 session store 迁移成功
- HTTP listener bind 成功

也就是：只有当服务已经具备可接受请求的条件时，才允许打印首页地址、`/admin` 地址和当前管理员口令。

如果脚本需要在服务真正 ready 前提示一些步骤，只允许保留准备阶段信息，例如：

- 正在准备数据库
- 正在构建前端/后端
- 正在启动服务

而真正的“访问哪里、后台在哪里、口令是多少”，统一由 Rust 输出。

## 验证

最小验证应覆盖：

1. Rust 启动横幅 helper 覆盖：
   - 首页地址
   - `/admin` 地址
   - 当前管理员口令
2. 地址派生规则覆盖：
   - `0.0.0.0`
   - 显式 hostname / IPv4 / IPv6
   - 局域网地址列表生成
3. 首次生成配置文件时：
   - 会打印当前管理员口令
   - 会打印“首次生成并写入配置文件”的一次性提示
4. 首次从 `KOKO_ADMIN_TOKEN` 导入时：
   - 会打印当前管理员口令
   - 会打印“已一次性导入配置文件”的一次性提示
5. 非首次启动时：
   - 仍会打印当前管理员口令
   - 但不再打印“首次生成/首次导入”的一次性提示
6. `run.ps1 -DryRun`：
   - 只保留准备步骤预演
   - 不伪造 Rust 启动横幅
   - 不自己打印后台口令
7. `run.ps1` 实启动链：
   - PowerShell 终端能直接看到 Rust 打印的首页地址、`/admin` 和当前管理员口令
8. 现有后台配置文件首次生成/导入行为不回归

## 风险与边界

- 本次不改变后台口令真相位置，因此不会影响现有 `/admin` 登录逻辑
- 本次不改变 `run.ps1` 的数据库/构建/启动职责，只收缩它的人话输出职责
- 本次不试图把所有启动日志都改成统一日志框架；只统一面向人的启动横幅
