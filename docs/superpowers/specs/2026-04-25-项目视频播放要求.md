## 0. 一句话裁决

**媒体资产只认 canonical 真相；正式媒体字节只认唯一 `WebTorrent` whole-file swarm；正式播放表面只认一颗 `Video.js` player/container；离屏、回屏、查看器、全屏都只是同一条播放会话的迁移。**

---

## 1. 统一真相

### 1.1 媒体资产真相

1. `source_hash` 只表示上传前原始 `File` 字节的 `SHA-256`。
2. `source_hash` 只服务“受权限约束的精确原文件复用”，不是全局存在性探针，不做模糊查重，不做 AI 相似度。
3. `content_hash / swarm_id / torrent_info_hash` 只认 canonical 共享字节；相同 canonical 字节只能对应一份全局物理媒体资产和一套分发身份。
4. `message / attachment / attachment_ref` 是房间内业务事实；复用的是全局 canonical 资产，不是复用旧消息或旧附件事实。
5. 转发与分享只允许复用“当前可见源附件绑定的 canonical 资产”，不能重新上传、重新转码或重新生成第二套 torrent / swarm。
6. 播放器不拥有媒体身份真相，`WebTorrent` 也不反向决定业务附件是不是同一个附件。

### 1.2 正式分发真相

1. 新主链附件的正式媒体字节只允许走唯一 `WebTorrent` whole-file swarm。
2. `0-24 小时` 内，服务器只能作为 swarm 内的 `backend strong seed` 参与，包括 `WebSeed + WebRTC seeder`；它不是前端第二正式播放链。
3. `24 小时` 起点只认后端 `complete_at`；到点后服务器退出正式媒体字节供给，但控制面、权限、删除语义、metainfo 与 tracker/signaling 仍可保留。
4. 失败态只允许用稳定状态码表达：`MEDIA_READY`、`MEDIA_CONNECTING_TO_PEERS`、`MEDIA_NO_ONLINE_SEED`、`MEDIA_DELETED`。
5. `MEDIA_CONNECTING_TO_PEERS` 的默认连接窗口是 `8 秒`；窗口内重试节奏默认 `2 秒`；进入 `MEDIA_NO_ONLINE_SEED` 后默认重试节奏是 `15 秒`。
6. “当前没有在线种子”和“内容已删除”必须分开；前者是可恢复缺席态，后者是不可恢复终态。
7. 用户滑到媒体后的正式路径固定为：优先拿到首眼可显示/可播的关键字节，然后继续补齐整文件，补齐后继续做种。
8. 滑出视口、切到别的消息、关闭 viewer 或进入后台，可以停止前台重解码和 UI 占用，但不能把“继续补齐、继续帮助、继续做种”的主链真相改写成默认结束。
9. 正式主链禁止回退到 `HLS`、原文件直链、`poster/still` 正式查看链、CDN 正式播放链、`p2p-media-loader` 旁路或任何第二正式字节入口。
10. 秒开、丝滑、冷启动和 viewer/fullscreen 接管都只能靠同一条 `WebTorrent` 主链、首段优先、缓存与 owner 调度解决，不能靠降码率、降分辨率、第二链路或模糊失败态伪造。

### 1.3 正式播放真相

1. 全应用同一时刻只允许一颗活着的正式 `Video.js` player/container。
2. 消息流自动播放、查看器、真全屏、退出归位都必须复用同一颗 canonical player；不允许并存第二颗正式 player、第二颗正式 `<video>` 或第二套 fullscreen owner。
3. 播放位置真相继续只认运行时里的 `inlineAutoplayPositionByAttachmentId`；DOM 私有字段、壳层临时状态和 poster 都不能拥有第二套 `currentTime` 真相。
4. 非 owner 卡片如果还要表达画面，只能是宿主槽位、只读帧投影或冷启动兜底，不能继续拥有自己的 live player。
5. 只要当前附件已经有同源播放源和有效保存位置，画面就禁止退回开头 `poster`、首帧占位或可见区里的 `IMG -> VIDEO` 换壳。
6. 时间线视频永远无控件；控件只属于查看器或真全屏欣赏态。
7. 当前自动播 owner 被点击时，用户得到的结果必须是“同一颗活跃播放器直接升格到查看器/全屏”；点击别的视频时，也只能迁移同一颗播放器，不能新开第二颗。
8. 离屏中断不等于自然播完；离屏、owner 切换、viewer 接管、页面 hidden、生命周期降级都必须保存位置并保留续播资格；只有真实播到结尾才允许自然循环回到 `0`。

## 2. 当前代码已经写死的边界

1. 自动播同一时刻只允许一个 owner。
2. 当前最小可见阈值是 `0.6`。
3. 当前“完整可见优先”阈值是 `0.98`；一旦有候选几乎完整进入视口，就不能再让“更靠中心但只露半屏”的候选压住它。
4. 当前排序规则是：先按离视口中心更近，再按可见比例更高；若当前 owner 仍在竞争集合内，优先保持粘性。
5. 当前 `pending owner` 稳定等待是 `80ms`；它只允许吸收几何抖动，不允许被做成肉眼可见的视觉空窗。
6. 当前实现不会因为单次空观测立刻释放 owner；必须连续空观测才真正退场。
7. 当前代码已经存在唯一播放器 owner 模块、自动播编排模块、`source_hash` 复用入口和稳定 `media_state`；后续实现只能继续收口，不能再把这些真相拆回多头共管。

## 3. 硬禁令

1. 禁止为新主链附件再长第二正式媒体资产、第二正式视频变体、第二正式图片真相或第二正式 torrent / swarm。
2. 禁止把 `source_hash` 做成全局媒体存在性探针、模糊查重、感知哈希或 AI 相似度服务。
3. 禁止把“发到不同房间”解释成“不同媒体”；房间只拥有消息和附件引用，不拥有媒体资产身份。
4. 禁止把转发、分享、复用命中实现成重新上传、重新转码、重新生成 canonical 或重新生成 torrent。
5. 禁止让播放器、viewer、fullscreen 壳层持有媒体身份、删除真相、成员权限真相或 swarm ready 真相。
6. 禁止把 viewer / fullscreen 体验修复成第二正式播放链、第二 live player 或第二套 `currentTime` 存储。
7. 禁止在已经拿到正式 `src` 和有效位置后继续长期展示 `poster`，或在可见区里做 `IMG -> VIDEO` 主节点换壳。
8. 禁止把“继续帮助后人”实现成“继续保活大量前台级 live `<video>`、reader、listener、bootstrap 和 probe”。
9. 禁止为了减负而削弱 `WebTorrent` 主链、减少帮助者、减少补齐、减少做种或恢复服务器第二主链。
10. 禁止用降分辨率、降帧率、降码率、隐性重编码或低清版本伪造秒开和丝滑。
11. 禁止用 `HLS`、原文件直链、CDN、`p2p-media-loader`、临时 range 服务或静态预览缓存冒充新主链成功。
12. 禁止把“当前没有在线种子”和“内容已删除”混成一类文案、同一状态码或同一恢复逻辑。

## 4. 验收门禁

### 4.1 资产与复用

1. 同一原始 MP4 或图片在同一授权上下文重复上传，第二次必须命中 `source_hash`，且不重新转码、不重新上传媒体字节。
2. `source_hash` 命中后，新消息仍然拥有自己的 `room_event / message / attachment_ref`。
3. 不同原文件但最终 canonical 字节相同，上传完成后仍必须通过 `content_hash` 共享同一 physical asset / `swarm_id / torrent_info_hash`。
4. 转发与分享必须复用已有 canonical 资产，而不是重新上传。
5. 未授权上下文不能通过 `source_hash` 或转发路径探测到别处媒体是否存在。
6. 删除后的附件不能通过 `source_hash`、转发、缓存或 viewer 路径复活成 ready。

### 4.2 分发与状态

1. 新主链附件的正式播放、正式查看、正式补齐都必须落在同一个 `WebTorrent` whole-file swarm 上。
2. `0-24 小时` 阶段必须能证明服务器强参与来自 swarm 内的 `WebSeed + WebRTC seeder`，而不是第二播放链。
3. `24 小时` 到点判断必须只认后端 `complete_at`，且服务重启不会重置。
4. `MEDIA_READY / MEDIA_CONNECTING_TO_PEERS / MEDIA_NO_ONLINE_SEED / MEDIA_DELETED` 四种状态必须在前后端统一存在，不能各壳再发明第二套状态机。
5. “没有在线种子”和“内容已删除”必须在真实浏览器烟测里走出两条不同路径。
6. 任何新主链附件如果实际命中了 `HLS`、原文件直链、CDN、`p2p-media-loader` 或临时 range 服务，都应判定为主链失败。

### 4.3 播放与连续性

1. 同屏多候选时只有一个自动播 owner。
2. owner 仍在阈值内时必须具备粘性；轻微滚动不能来回抖。
3. `pending owner` 稳定等待不能制造可见空窗。
4. 单次空观测不会立刻释放 owner。
5. 离屏中断后回屏必须从上次位置继续，不能回到 `0` 再 seek。
6. 带 `posterSrc` 和不带 `posterSrc` 的场景都必须通过同一条连续性测试。
7. 点击当前自动播视频进入 viewer / fullscreen 时，不得新增第二颗正式 player、第二个正式 `<video>` 或第二条正式播放会话。
8. 点击另一条视频时，也只能迁移同一颗 canonical player。
9. 时间线 `<video>` 永远无控件。
10. 退出 viewer / fullscreen 后，如果该附件仍满足 owner 条件，就必须归位回消息流继续同一条时间轴；若不满足，也必须保留正确续播资格而不是回退开头画面。

### 4.4 真实浏览器烟测

1. 必须在真实 HTTPS 环境下完成。
2. 必须覆盖真实图片和真实 MP4。
3. 必须覆盖时间线自动播放、滑走、滑回、viewer 打开、真全屏、退出归位、再次点击同一附件。
4. 必须覆盖“前 `24 小时` 强 seed 阶段”和“后 `24 小时` peer 接力阶段”。
5. 必须覆盖“后来的用户能因为前面的用户变快”这一条协同收益，而不是只测一个人本机能播。
6. 必须证明同一轮烟测里没有第二正式播放链、没有 `poster -> video` 可见换壳、没有 `MaxListenersExceededWarning`、没有旧代次 reader/listener 长尾泄漏。

## 5. 代码锚点

1. `src/媒体上传外壳.rs`：`source_hash` 复用入口、canonical 资产写入、分发元数据落库。
2. `src/媒体附件适配.rs`：`source_hash` 持久化与复用查询。
3. `src/媒体协作分发.rs`：`content_hash / swarm_id / torrent_info_hash`、`WEB_SEED_TTL秒`、稳定 `media_state`、重试节奏与 tracker/announce 对外语义。
4. `frontend/媒体/全局唯一播放器.ts`：唯一正式播放器生命周期 owner、时间线/查看器/全屏迁移与归位。
5. `frontend/媒体/消息视频自动播编排.ts`：owner 阈值、完整可见优先、中心距离排序、连续性候选。
6. `frontend/聊天媒体编排.ts`：房间级媒体编排、自动播位置真相、viewer 接管、帮助链协调。
7. `frontend/房间消息窗.ts`：消息流宿主槽位、时间线表达、无控件表面。
8. `frontend/媒体/videojs播放器壳.ts`：同一颗播放器壳、container-first fullscreen、无第二壳。

## 6. 最终裁决

以后在 `koko` 里，视频播放和多媒体复用都按下面这句话理解：

**同一个 canonical 媒体资产，既是上传复用和转发分享复用的物理真相，也是 `WebTorrent` 正式分发平面的唯一真相；同一颗 `Video.js` player/container，既是消息流自动播放、离屏续播、查看器和全屏的唯一正式播放表面，也是所有 viewer/fullscreen/归位动作必须复用的唯一会话。**

从这句话自然推出全部红线：

1. 禁止第二媒体资产真相。
2. 禁止第二正式字节主链。
3. 禁止第二正式播放器真相。
4. 禁止第二套 `currentTime` 真相。
5. 禁止把 `poster`、`thumbnail`、`runtime preview` 做回视频主真相。
6. 禁止把协同收益做成“看过就算了、滑走就停了、补齐后不种了”的半截逻辑。
7. 禁止用“先这样能跑”保留旧支路、旧入口、旧文档或旧裁决。
