# 匿名内部身份与主题化花名设计

日期：2026-04-14  
状态：设计已确认，待写 implementation plan  
适用范围：`koko` 仓库当前匿名聊天身份引导、会话恢复、消息发送者展示花名，以及未来个人资料修改功能的身份边界。  

关联资料：

- `src/适配.rs`
- `src/契约.rs`
- `src/房间外壳.rs`
- `src/房间阅读适配.rs`
- `src/消息事件适配.rs`
- [`uuid` crate 官方文档](https://docs.rs/uuid/latest/uuid/)
- [`names` crate 官方文档](https://docs.rs/names/latest/names/)
- [`RFC 9562`](https://www.ietf.org/rfc/rfc9562)

## 1. 这份 spec 为什么存在

当前匿名身份链路已经有两个明显问题：

1. 花名生成还是 MVP 级手搓词表，组合太少，也没有主题层。  
2. 匿名内部身份、会话锚点、展示花名的边界还不够干净，未来一旦加“个人资料修改”，很容易把真相和投影揉成一团。  

如果继续在现有实现上打补丁，最容易长出三类屎山：

- 继续往 `生成展示花名()` 里堆更多手搓词表和分支；
- 继续把内部身份直接透给前台，后面再为了“别暴露时间特征”补第二套公开 ID；
- 继续让 `sessions.display_name` 和 `anonymous_identities.display_alias` 共同承载当前资料真相。  

这份 spec 的目标不是“把昵称词库加大一点”，而是一次把：

- 内部身份真相
- 会话锚点
- 当前资料投影
- 主题化花名生成
- 未来资料修改的演进边界

讲清楚，并且明确哪些地方直接复用成熟轮子，哪些地方才是项目自己的业务真相。

## 2. 已确认产品口径

这次设计以以下口径为硬约束：

1. 花名要有“主题”，但主题是**项目级公共主题库**，不是“一个房间只能有一个主题”。  
2. 同一房间允许并存不同主题的匿名花名。  
3. 新匿名身份创建时，系统自动随机分配 `主题 + 花名`。  
4. 当前阶段不做：
   - 改名次数配额
   - 零点重置
   - 手动选主题
   - 撞名治理  
5. 当前前台不显示主题，主题只作为系统内部组织词库的结构。  
6. `主题 + 花名` 都只是启动时的临时资料投影；未来做“个人资料修改”功能之后可以变化。  
7. 历史消息的发送者显示，跟随当前资料投影变化，不保留发送瞬间的花名快照。  
8. 内部真实身份使用 `UUIDv7`，但对用户不暴露时间特征，也不在当前阶段决定公开匿名资料 ID 的方案。  
9. 整体实现必须遵守：
   - DDD：真相 owner 单一
   - Unix：模块小而专、可组合、可删除
   - 不重复手搓成熟轮子

## 3. 核心结论

核心结论只有一句：

**匿名聊天需要三层明确分离的身份语义：内部身份、会话锚点、当前资料投影。**

展开后就是：

1. `内部身份` 是系统真实身份锚点，使用 `UUIDv7`，只供后端和数据库内部使用。  
2. `会话锚点` 仍然只负责运行时恢复和冷/热路径编排，不承载展示语义。  
3. `当前资料投影` 负责主题和花名，是可变外衣，不是主键。  
4. 花名生成器不再手搓，直接复用 Rust 成熟轮子 `names`；项目只维护“主题词库”这层业务数据。  
5. 当前前台 bootstrap 结果只拿真正需要的最小表面：`session_id + display_alias`。  
6. 未来如果需要公开稳定匿名资料 ID，再单独设计，不把内部 `UUIDv7` 裸露出去。  

## 4. 领域模型

### 4.1 匿名内部身份

匿名内部身份是领域真相，不是壳层显示态。它至少包含：

- `identity_uuid`: `UUIDv7`，内部真实锚点
- `theme_key`: 当前主题键
- `display_alias`: 当前展示花名

它回答的问题是：

- 这个匿名用户在系统内部到底是谁？
- 它当前对外显示什么资料投影？

它不回答：

- 当前页面是不是活着
- socket 现在连不连着
- 某条历史消息当时显示什么花名

### 4.2 会话锚点

会话继续保持运行锚点语义：

- 浏览器/端侧恢复
- 房间冷/热路径衔接
- 设备入口凭证映射

它不拥有当前资料真相。

### 4.3 当前资料投影

当前资料投影是匿名内部身份的一个可变表面，包括：

- `theme_key`
- `display_alias`

约束：

1. 现在由系统自动分配。  
2. 未来个人资料修改功能只改这一层，不改内部身份。  
3. 历史消息、实时消息、快照全部读取当前投影，而不是消息发送瞬间快照。  

### 4.4 标识映射表

为了避免实现阶段把“内部身份”“数据库外键”“旧字符串身份”“会话锚点”混在一起，这次明确采用下面这张映射表：

| 标识 | 所在位置 | 语义 | 是否对前台暴露 | 状态 |
|---|---|---|---|---|
| `identity_uuid` | `anonymous_identities.identity_uuid` | 匿名内部身份的唯一真实锚点，使用 `UUIDv7` | 否 | 新权威字段 |
| `id` | `anonymous_identities.id` | 数据库内部自增外键，只服务 join 和持久化映射 | 否 | 保留，adapter 内部使用 |
| `anonymous_identity_id` | `anonymous_identities.anonymous_identity_id` | 旧字符串身份字段 | 否 | 迁移兼容字段，切换完成后删除 |
| `sessions.anonymous_identity_id` | `sessions` 表 | 指向 `anonymous_identities.id` 的数据库外键，不是领域身份锚点 | 否 | 保留，后续可单独考虑重命名 |
| `session_id` | `sessions.session_id` | 运行时会话锚点 | 是 | 保留 |

实现硬约束：

1. 应用层与领域层一律把 `identity_uuid` 视为内部身份真相。  
2. `anonymous_identities.id` 与 `sessions.anonymous_identity_id` 只允许停留在 adapter / SQL 层。  
3. 旧 `anonymous_identity_id` 文本字段只允许作为迁移缝存在，不得继续进入新契约、新查询、新测试。  

## 5. 轮子策略

### 5.1 UUID 轮子

内部身份不再手搓短字符串，直接复用 Rust 官方主流 `uuid` crate。

选择理由：

- `uuid` 是 Rust 生态事实标准；
- `RFC 9562` 已把 `UUIDv7` 正式纳入标准；
- `UUIDv7` 具备时间有序特征，适合数据库内部主键与索引局部性；
- 仍可保持“内部使用、不对用户暴露”的边界。  

实现原则：

1. 运行时生成由 Rust 侧完成，避免把内部身份生成真相下沉到适配层或数据库默认值。  
2. PostgreSQL 只负责存储 `uuid` 类型，不负责决定业务身份语义。  
3. 内部 `UUIDv7` 不出现在前台契约、URL、用户可见文案里。  

### 5.2 花名轮子

花名生成不再手搓，复用 `names` crate。

选择理由：

1. 纯 Rust，符合当前项目主轴。  
2. 官方文档明确支持自定义 adjective / noun 词典。  
3. 生成器边界足够薄，只负责组合字符串，不偷带身份真相。  

适配原则：

1. `names` 负责“从词典组合出名字”。  
2. 项目只维护“主题 -> 词典”的业务映射。  
3. 如需把默认连字符格式转成中文花名，只允许做一层极薄字符串格式适配；禁止 fork 轮子，更禁止再造第二套生成器。  

### 5.3 不选的路线

当前不选：

- 在前端使用 JS 名称生成轮子作为正式真相 owner
- 自己维护大段随机算法或碰撞治理逻辑
- 为了防撞名引入房间级占位或在线成员去重系统

因为这些都超出了当前产品约束，属于无意义复杂化。

## 6. 主题库模型

主题库是**项目级公共资源**，不属于某个房间，也不属于某个前台壳。

每个主题包含：

- `theme_key`
- 前缀词典
- 后缀词典
- 可选的格式配置

当前阶段的主题库约束：

1. 不对前台公开。  
2. 不允许房间配置“当前主题”。  
3. 不做用户手动选择。  
4. 不做主题可见性策略。  

它只服务于“当前资料投影如何生成”。

当前阶段的主题库真相位置也明确写死：

- 主题库先落在 Rust 后端编译期常量中，由 `用户身份` 收口模块持有；
- 当前不落数据库、不做管理后台配置、不引入外部配置文件；
- 等未来出现“运营可编辑主题库”这类真实需求，再单独做持久化演进。  

## 7. 数据模型

### 7.1 `anonymous_identities`

`anonymous_identities` 成为匿名资料真相 owner。

建议演进为：

- `id BIGSERIAL PRIMARY KEY`（保留，数据库内部 join 用）
- `identity_uuid UUID NOT NULL UNIQUE`
- `theme_key TEXT NOT NULL`
- `display_alias TEXT NOT NULL`
- `anonymous_identity_id TEXT`（旧字段，仅迁移兼容）

这里回答：

- 匿名内部身份是谁
- 当前主题是什么
- 当前花名是什么

### 7.2 `sessions`

`sessions` 只保留运行时锚点语义：

- `session_id`
- `anonymous_identity_id`（这里指向 `anonymous_identities.id` 的数据库外键）
- `device_anonymous_token`

其中 `display_name` 进入退场路径：

1. 迁移期可保留字段兼容旧查询。  
2. 新逻辑不再把它视为当前资料真相。  
3. 相关读取链全部切走后，再删除或冻结。  

### 7.3 消息与事件

消息表和事件表不新增发送者花名快照字段。

原因：

1. 已确认历史消息跟随当前资料投影。  
2. 当前阶段没有必要再长一套消息级别的身份快照真相。  
3. 让消息读取统一 join 当前资料投影，边界更简单。  

## 8. 契约边界

### 8.1 当前对外契约

当前对外契约只保留壳真正需要的最小表面：

- `session_id`
- `display_alias`

当前不再继续把匿名内部身份返回给前台。

受影响的契约与读模型表面必须一次性扫清：

- Rust 侧：
  - `src/契约.rs` 中的匿名身份引导结果
  - 房间快照 / 历史页 / 增量事件里的 `发送者花名`
- TypeScript 侧：
  - `frontend/契约.ts` 中的匿名身份引导结果
  - 房间恢复、历史页、实时事件相关 read model
- HTTP / realtime adapter：
  - `房间外壳`
  - 房间历史与增量事件读取链

这次改造不要求这些 surface 改字段名，但必须保证：

1. bootstrap 结果不再包含匿名内部身份；  
2. 各消息 surface 的 `sender_display_alias` / `发送者花名` 统一改为从当前资料投影读取；  
3. 不允许 Rust 和 TS 两侧出现一边已去掉内部身份、一边还保留旧契约的半切换状态。  

### 8.2 当前不暴露的字段

下面这些当前不进入共享契约：

- `identity_uuid`
- `theme_key`
- 任何“公开匿名资料 ID”

原因：

1. `identity_uuid` 是内部真相，不应暴露时间特征。  
2. `theme_key` 当前只用于系统内部词典组织。  
3. 公开匿名资料 ID 尚无产品需求，强行设计只会制造第二入口。  

### 8.3 未来演进

未来如果个人资料功能需要一个对外稳定匿名资料锚点：

1. 单独设计公开 handle；  
2. 不直接复用内部 `UUIDv7`；  
3. 不在本次改造里提前发明。  

## 9. 读取链与写入链

### 9.1 引导匿名身份

新链路：

1. 设备入口凭证进入应用层。  
2. 若已有匿名内部身份，则恢复当前 `display_alias`。  
3. 若没有：
   - 生成内部 `UUIDv7`
   - 随机选择项目级主题
   - 用 `names` + 主题词典生成花名
   - 持久化到 `anonymous_identities`
   - 建立 `session` 锚点  

并发幂等约束：

1. 同一 `device_anonymous_token` 的并发 bootstrap 只能收敛到同一个匿名内部身份。  
2. 第二个并发请求必须复用已建立的身份与会话结果，而不是新建第二行匿名身份。  
3. 这条语义属于应用 + 持久化协同边界，不能丢给前台重试运气解决。  

### 9.2 历史消息、增量事件、快照

统一从 `anonymous_identities.display_alias` 读取当前展示花名。

禁止：

- 历史页从 `sessions.display_name` 读
- 实时事件从一条链读 `sessions`，历史快照从另一条链读 `anonymous_identities`

只允许一条当前资料投影读取链。

### 9.3 未来修改资料

未来个人资料修改功能只改：

- `theme_key`
- `display_alias`

不改：

- `identity_uuid`
- `session_id`

这样旧消息自然跟随当前资料投影变化，不需要消息回写。

## 10. 模块边界与文件结构

### 10.1 模块目标

可以新增 `用户身份` 收口点，但它必须是真相收口模块，不是代码收纳盒。

它只负责：

- 匿名内部身份领域语义
- 当前资料投影
- 花名生成接轮子
- 引导匿名身份与未来资料修改的应用编排

### 10.2 不允许的拆法

不允许为了“看起来像 DDD”而制造：

- `manager.rs`
- `service.rs`
- `coordinator.rs`
- `facade.rs`
- 多层纯转发 repository 壳  

这些都不提供真实边界价值，只会把热点变成层级迷宫。

### 10.3 推荐落法

当前阶段更推荐：

1. 先新增一个小而硬的 `src/用户身份.rs`，把身份与资料投影的逻辑收口进去；  
2. 只有在它真的继续变胖时，再按 `领域 / 用例 / 适配` 拆成极少数子文件；  
3. 新模块必须同步删除旧分支或旧读取链，不能只新增包装。  

## 11. 迁移策略

迁移必须分阶段，避免双活屎山。

### 阶段 1：加新字段

- 给 `anonymous_identities` 加 `identity_uuid`
- 给 `anonymous_identities` 加 `theme_key`
- 暂时保留旧 `anonymous_identity_id` 文本字段
- 暂时保留 `sessions.display_name`

### 阶段 2：回填

- 为存量匿名身份回填 `identity_uuid`
- 为存量匿名身份回填一个 `legacy` 或 `default` 主题
- 保留现有 `display_alias`，不在迁移时强制重抽花名  
- 明确旧 `anonymous_identity_id` 只作为兼容映射存在，不再被应用层读取  

### 阶段 3：切读取链

- bootstrap、历史页、增量事件、实时消息统一改成从 `anonymous_identities` 取当前花名
- 前台契约停止接收匿名内部身份

执行清单至少覆盖：

- bootstrap 引导结果
- 房间快照
- 历史分页
- 增量事件
- realtime 首帧补齐
- 实时新消息广播
- Rust `契约.rs`
- TypeScript `frontend/契约.ts`

### 阶段 4：退场旧路径

- 仓库里不再有活路径读取 `sessions.display_name` 作为当前资料真相
- 仓库里不再有活路径读取旧 `anonymous_identity_id` 文本字段作为身份真相
- 完成验证后，删除或冻结旧字段

## 12. 测试策略

这次必须以保护真相边界为中心补测试，而不是只测“能生成个名字”。

至少补这些测试：

1. bootstrap 成功时只返回 `session_id + display_alias`，不再暴露匿名内部身份。  
2. 新匿名身份创建时会生成内部 `UUIDv7`。  
3. 新匿名身份创建时会自动选择项目级主题，并生成花名。  
4. 同一设备重复 bootstrap 会恢复同一个当前资料投影。  
5. 历史页、增量事件、实时消息都从同一条当前资料投影链取 `display_alias`。  
6. 修改当前资料投影后，旧消息显示跟随变化。  
7. 仓库内不存在活查询继续把 `sessions.display_name` 当当前花名真相。  
8. 同一 `device_anonymous_token` 的并发 bootstrap 不会创建重复匿名身份。  

## 13. 旧路径退场原则

下面这些路径不允许长期共存：

1. `UUIDv7` 身份真相和旧手搓字符串身份真相双活  
2. `anonymous_identities.display_alias` 和 `sessions.display_name` 双真相  
3. `names` 轮子和私有随机算法双主链  
4. 主题库已存在，但房间层、壳层仍各自偷偷维护主题语义  

只要这些路径同时活着，就说明改造没有真正完成。

## 14. 失败判定

后续实现只要出现下面任一情况，就说明开始漂：

1. 把内部 `UUIDv7` 继续透给前台  
2. 只换轮子，不收口当前资料真相 owner  
3. `sessions.display_name` 继续被多条读链当当前花名真相  
4. 为了防撞名引入房间级占位或在线去重系统  
5. 新建一堆 DDD 仪式文件，却没有删掉旧复杂度  
6. 因为主题化而再造第二套昵称生成器  

## 15. 完成定义

做到下面这些，才算这次身份设计真正落地：

1. 内部匿名身份已切到 `UUIDv7`。  
2. 前台当前不再接收匿名内部身份。  
3. 花名生成已切到 `names` 轮子。  
4. 主题库已成为项目级公共资源，不再有房间级主题真相。  
5. `anonymous_identities` 成为当前资料投影唯一真相 owner。  
6. 历史消息、增量事件、实时消息统一读取当前资料投影。  
7. `sessions.display_name` 已退出真相位。  
8. 没有新增无价值的 DDD 包装层。  

## 16. 一句话结论

终局不是继续把“匿名身份、会话、花名”揉在一起打补丁。  
终局应该是：
