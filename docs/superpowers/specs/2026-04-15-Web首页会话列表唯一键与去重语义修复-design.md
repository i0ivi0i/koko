# Web 首页会话列表唯一键与去重语义修复设计

日期：2026-04-15  
状态：Draft  
适用范围：`koko` Web 首页历史会话列表、浏览器本地存储、房间恢复入口。

关联文件：

- `frontend/存储.ts`
- `frontend/房间恢复编排.ts`
- `frontend/tests/聊天壳测试.spec.ts`
- `frontend/tests/聊天壳引导与入房测试.spec.ts`

## 1. 问题定义

当前首页列表会出现两个相同的房间号。  
这不是简单的渲染脏数据，而是**首页列表的唯一键定义错了**。

现状代码把首页历史当成“按 `roomId` 去重的技术记录列表”：

- 同一个 `roomCode`
- 只要后端内部 `roomId` 不同
- 首页就会保留两条

这和产品语义冲突。

## 2. 产品语义裁决

首页这个列表不是数据库房间实例列表。  
它是**用户会话列表**，语义上更接近 Telegram 首页：

- 一个群，只能出现一条
- 一个私聊对象，只能出现一条
- 再次进入同一个会话时，只更新这条记录
- 不允许因为内部实例标识变化而长出第二条

当前群聊阶段，首页列表的用户可感知唯一身份是：

`roomCode`

因此本期裁决是：

- 首页历史列表按 `roomCode` 去重
- 同一个 `roomCode` 只保留最新一条
- 被保留记录的 `roomId` 更新为最新那条记录里的 `roomId`

## 3. 边界与 Owner

这次修复必须收口在 `frontend/存储.ts`，不能散落到首页组件或壳层。

原因：

1. 这里已经是首页历史的唯一读写 owner
2. 读路径和写路径都在这里，适合顺手修复旧脏数据
3. 如果在 UI 层临时隐藏重复项，只是遮羞布，不是根因修复

本期各层职责：

- `storage`
  - 负责首页历史的读取、规范化、去重、排序、删除
- `房间恢复编排`
  - 只表达“这个房间刚刚成功进入过”
  - 不自己拼列表去重逻辑
- `壳层 / 首页渲染`
  - 只消费已规范化的历史列表
  - 不做第二套去重

## 4. 设计方案

### 4.1 唯一键

当前群聊阶段：

- 首页列表唯一键：`roomCode`

不是：

- `roomId`

### 4.2 规范化规则

`规范化首页房间历史(...)` 应改成：

1. 过滤掉空 `roomId`、空 `roomCode`、非法 `lastEnteredAt`
2. 按 `roomCode` 建唯一索引
3. 同一个 `roomCode` 出现多条时，保留 `lastEnteredAt` 最新的那条
4. 最终按 `lastEnteredAt` 倒序输出

保留最新记录时：

- `roomCode`：保留该条的值
- `roomId`：更新成最新那条记录的 `roomId`
- `lastEnteredAt`：保留最新值

### 4.3 旧脏数据修复

只修“写入时去重”还不够。  
必须保证本地已经脏掉的 `koko_home_sessions` 在读取时也会被自动收口。

因此：

- `读取首页房间历史()` 继续先走 `规范化首页房间历史(...)`
- 读取旧存量时也能把同 `roomCode` 的脏记录合并掉

这样用户不必手动清浏览器存储，bug 也能自动恢复。

## 5. 测试策略

### 5.1 存储层单测

新增失败测试，锁住：

- 两条记录 `roomCode` 相同
- `roomId` 不同
- `lastEnteredAt` 不同

期望：

- 最终只剩一条
- 保留最新 `lastEnteredAt`
- `roomId` 变成最新那条的 `roomId`

### 5.2 旧脏数据读取测试

直接往 `koko_home_sessions` 塞入旧格式脏数据：

- 相同 `roomCode`
- 不同 `roomId`

期望读取后只剩一条。

### 5.3 首页渲染测试

首页启动时读取本地历史：

- 若本地存储里有两条相同 `roomCode`
- 页面最终只能渲染一条该房间号

这条测试用来防止以后有人又把去重绕回 UI 层或别的入口层。

## 6. 非目标

这次不做以下事情：

1. 不重做首页列表 UI
2. 不改后端房间模型
3. 不引入新的共享 contract 字段
4. 不在壳层补临时隐藏逻辑
5. 不把未来私聊唯一键问题一起提前做大

## 7. 后续演进

当前群聊阶段按 `roomCode` 去重是正确的产品语义。  
如果未来引入私聊、可改群号、会话别名或其他会话类型，再升级成显式的 `conversationKey / sessionListKey`。

但在当前阶段，不需要提前造第二套抽象。

## 8. 最终裁决

本次 bug 的根因不是“首页渲染重复了”，而是：

**首页列表把技术实例标识 `roomId` 错当成了用户会话唯一键。**

本次修复标准是：

1. 首页历史列表以 `roomCode` 作为当前群聊阶段唯一键
2. 读取旧脏数据时也会自动合并重复项
3. 壳层和组件里不再长第二套去重
4. 用户首页同一个房间号永远只看到一条

只要还出现下面任意一条，就说明修复失败：

1. 同一个 `roomCode` 仍可能显示两条
2. 去重逻辑漂到 UI 层而不是 `storage` owner
3. 只有新写入会去重，旧脏数据读取后仍重复
