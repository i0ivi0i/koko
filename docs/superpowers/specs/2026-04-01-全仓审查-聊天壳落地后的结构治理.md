## 总体结论
仓库当前还没有塌成私有框架。`app.rs` 和大部分后端 truth 仍然站在正确层里，`contract.rs` 也没有被 UI 枚举、布局字段、页面流程语义直接污染。  
真正的问题集中在 4 个方向：共享面里仍混着 app-only 身份输入、浏览器 realtime 外围正在长成 repo 私有 runtime、HTTP/RT 会话解析走了两套流程、以及测试基础设施又手搓了一层成熟能力。  
这说明项目目前还是“可演进”，但已经开始在外围 adapter 和测试支撑层积累长期债；如果不收口，后面不是先坏在 domain，而是先坏在 Web/realtime/test 基础设施上。

## 立即治理
- 标题: `contract.rs` 仍混有带 `session_id` 的 app-only 输入 DTO
- 违反法则: [AGENTS.md](/E:/koko/AGENTS.md) 关于“`contract` 是多壳共享唯一通用表面”；[审查维护.md](/E:/koko/审查维护.md) 关于 `contract` 禁止承载权威真相与 app-only 输入
- 类别: `contract pollution` / authority-of-truth leakage
- 关键证据: [src/contract.rs](/E:/koko/src/contract.rs#L17) 的 `JoinOrCreateRoomByCodeCommand` 和 [src/contract.rs](/E:/koko/src/contract.rs#L48) 的 `LoadRoomSnapshotQuery` 都携带 `session_id`；[src/http.rs](/E:/koko/src/http.rs#L132) 与 [src/http.rs](/E:/koko/src/http.rs#L187) 先从 cookie 解身份再构造它们，说明它们实际是 app 输入，不是共享 wire contract
- 为什么重要: 共享面一旦混入 adapter 注入身份后的 DTO，未来多壳扩展会越来越难判断“哪些类型可直接复用、哪些类型只是某个入口专用”；这会持续诱发第二套入口 DTO 和真相下沉
- 修复方向: 把这两个类型移回 [src/app.rs](/E:/koko/src/app.rs) 作为 app-only input，或明确拆成“共享 contract DTO + adapter 注入身份后的 app input”；再补一条治理测试，禁止 `src/contract.rs` 中出现带 `session_id` 的共享 command/query/snapshot

- 标题: `web.rs` 已开始把 realtime 协议桥和恢复策略硬化成壳内私有 runtime
- 违反法则: [AGENTS.md](/E:/koko/AGENTS.md) 关于“adapter 只翻译、shell 只持有交互编排”；[审查维护.md](/E:/koko/审查维护.md) 关于删除优先于堆叠、避免 repo 私有桥接层；baseline 关于 thin adapters outrank repo-local pseudo-frameworks
- 类别: repo 私有前端框架债 / realtime adapter 漂移
- 关键证据: [src/web.rs](/E:/koko/src/web.rs#L30) 的 `REALTIME_BRIDGE_SCRIPT`、[src/web.rs](/E:/koko/src/web.rs#L111) 的 `RealtimeCommand/RealtimeEvent` 镜像、[src/web.rs](/E:/koko/src/web.rs#L470) 的 `spawn_realtime_bridge`、[src/web.rs](/E:/koko/src/web.rs#L601) 的 `App` 编排，把 socket 客户端协议、房间订阅、补二次 snapshot、pending/reject/reset 策略都绑在一个壳文件里
- 为什么重要: 现在改一个 realtime 行为，要同时改 JS bridge、Rust 镜像类型、effect 编排和测试语义；继续这样长下去，未来换壳、换 wasm 形态、换客户端时，复用点会极少，仓库会越来越像围着 `socketioxide` 长出的私有前端 runtime
- 修复方向: 把浏览器 realtime 接入收成单独 adapter 边界，让 [src/web.rs](/E:/koko/src/web.rs) 只消费 typed command/event；把 `document::eval` 字符串桥缩到只剩 socket 客户端胶水，不再继续承载补水/恢复/pending 策略

- 标题: HTTP 与 realtime 维护了两套 `koko_session` 解析流程
- 违反法则: [审查维护.md](/E:/koko/审查维护.md) 关于禁止第二套流程、重复造轮子；baseline 关于 duplicate flows are governance problems；anti-wheel calibration rule 1
- 类别: 重复 helper / 第二套流程 / 低边界价值私有胶水
- 关键证据: [src/http.rs](/E:/koko/src/http.rs#L102) 到 [src/http.rs](/E:/koko/src/http.rs#L123) 走 `CookieJar`；[src/rt.rs](/E:/koko/src/rt.rs#L64) 到 [src/rt.rs](/E:/koko/src/rt.rs#L82) 又手工遍历 `COOKIE` 头、`split(';')`、`split_once('=')` 重写解析
- 为什么重要: 同一会话真相走两条解析链，任何关于编码、空白、多 cookie header 的修复都可能只落一边；这类差异会直接落在 realtime 鉴权热路径上
- 修复方向: 删除 [src/rt.rs](/E:/koko/src/rt.rs) 手工字符串解析，改用成熟 cookie parser，或抽一个共享 session extractor 供 HTTP/RT 共用；目标是只保留一套解析语义

- 标题: `tests/http_support` 自建了整套 Postgres 测试数据库生命周期，重复了成熟 `sqlx::test`
- 违反法则: [审查维护.md](/E:/koko/审查维护.md) 关于禁止手搓成熟轮子、复用优先；baseline 关于 mature ecosystem reuse outranks hand-rolled commodity infrastructure
- 类别: 手搓成熟轮子 / 测试基础设施私有实现
- 关键证据: [tests/http_support/mod.rs](/E:/koko/tests/http_support/mod.rs#L24) 到 [tests/http_support/mod.rs](/E:/koko/tests/http_support/mod.rs#L300) 自写数据库名派生、drop/create、迁移运行、销毁与 reset 逻辑；整个 `HttpHarness` 建在这套私有 DB harness 之上
- 为什么重要: 每个 HTTP 集成测试都绑到仓库私有数据库生命周期框架上；后续只要 fixture、隔离策略、迁移入口变化，维护者必须先理解这套私有基础设施，而不是直接复用 `sqlx` 已经提供的成熟能力
- 修复方向: 把数据库生命周期交还给 `#[sqlx::test]`，只保留路由装配和前端 fixture 路径这类薄 helper；目标是删掉私有 `destroy/reset/run_migrations` 逻辑

- 违反法则: [AGENTS.md](/E:/koko/AGENTS.md) 关于“完成声明必须建立在新鲜验证上”；[审查维护.md](/E:/koko/审查维护.md) 关于高风险改动必须有真实验证证据
- 类别: verification debt / runtime assembly risk
- 关键证据: 真正生产装配在 [src/main.rs](/E:/koko/src/main.rs#L13) 到 [src/main.rs](/E:/koko/src/main.rs#L34)；但 [tests/http_support/mod.rs](/E:/koko/tests/http_support/mod.rs#L68) 只装 `http::app_router(...)`，不挂 realtime layer，`rt_flow` 又单独起最小 router；当前专项补审也明确写着还缺本机 `cargo run` 实启证据
- 为什么重要: 以后只要改入口装配、socket 挂载、静态资源路由、环境变量启动链路，分拆测试仍可能全绿，但真实进程起不来或 `/`、`/api/*`、`/socket.io` 组合失真
- 修复方向: 提取一个与 [src/main.rs](/E:/koko/src/main.rs) 同构的 app factory，让 smoke test 或 CI 能同时证明 `/`、`/api/session/bootstrap` 和 realtime 握手在同一进程内可用

- 标题: HTTP flow 测试开始把前端 DOM/CSS 标记当成后端契约
- 违反法则: [审查维护.md](/E:/koko/审查维护.md) 关于 backend 不得为某壳硬编码展示语义；baseline 关于 shared contracts must stay shell-neutral
- 类别: backend-to-shell 验证耦合
- 关键证据: [tests/http_flow.rs](/E:/koko/tests/http_flow.rs#L242), [tests/http_flow.rs](/E:/koko/tests/http_flow.rs#L265), [tests/http_flow.rs](/E:/koko/tests/http_flow.rs#L370), [tests/http_flow.rs](/E:/koko/tests/http_flow.rs#L399) 直接断言 `koko-web-shell`、`.tg-*`、CSS 结构
- 为什么重要: 这会让 HTTP/router 层回归测试对壳专属标记过敏；后续只要前端结构或壳更换，后端测试就会跟着抖，持续强化“web 是唯一壳”的心理模型
- 修复方向: HTTP flow 只保留路由/fallback/静态资源可达性与状态码断言；DOM/CSS 断言挪回 web shell 验收层

## 待补证观察项
- `JoinedRoomSummary` / `RoomSearchResult` 里的 `display_title`、`latest_preview` 可能已经偏向壳层展示模型，但目前还缺足够证据证明它们不是跨壳稳定语义。下一步需要先定义它们到底是“业务中立摘要”还是“Telegram 列表卡片字段”。
- [src/admin.rs](/E:/koko/src/admin.rs#L37) 直接依赖 [src/web.rs](/E:/koko/src/web.rs#L229) 的 browser/url helper，出现壳到壳横向依赖迹象。现在影响还小，但若继续增长，应收回更中立的 browser adapter helper。
- [src/support.rs](/E:/koko/src/support.rs#L56) 的 `app_error_code()` 有重复包装倾向，但还缺证据证明 tracing/HTTP payload 能完全直接承载 `AppErrorCode` 而不引入兼容噪音。
- [scripts/dx-bundle-web.ps1](/E:/koko/scripts/dx-bundle-web.ps1#L22) 到 [scripts/dx-bundle-web.ps1](/E:/koko/scripts/dx-bundle-web.ps1#L36) 用 regex 解析 `Cargo.lock` 拿 `dioxus` 版本，像低价值脚本胶水；但替代面还没补齐证据，所以先降级观察。
- `CommandRejected`、`RoomStreamSubscribed` 和 HTTP 错误 payload 的显式 wire-shape 契约测试仍偏薄，目前更多是“被当前 Web/RT 测到了”，还不是“被多壳共享契约明确锁住”。

## 重复造轮子与冗余实现专项结论

  - `rt.rs` 对 `koko_session` 的私有 cookie 解析，重复了成熟 parser 与已有 HTTP 入口流程

  - `http_flow/admin_flow` 的测试 helper 分叉

## 成熟生态复用与手搓轮子专项结论
- 核心业务层还基本站在 Rust 生态肩膀上：
  - HTTP 入口用 `axum`
  - realtime 主通道用 `socketioxide`
  - 数据访问用 `sqlx`
- 真正开始手搓的地方不在核心业务，而在外围：
  - 测试数据库生命周期
  - cookie 解析
  - 浏览器 realtime 外围 bridge/runtime
- 结论：仓库还没整体背离成熟生态，但外围已经开始出现“本来能复用，结果自己接了一层又一层”的趋势。

## 分层与前后端解耦专项结论
- 当前后端 truth 大体还守在后端，未发现明显的“前端判权限/成员资格/消息成立”的失守。
- `contract.rs` 的主要问题不是 UI 字段直接污染，而是 app-only 输入 DTO 仍混在共享面里。
- `web.rs` 的主要问题不是直接 carrying business truth，而是 shell 与 adapter 边界开始粘连。
- 结论：分层没有塌，但已经出现“外层边界越来越厚”的漂移，需要尽快止住。

## 测试与验证结论
- 当前测试能较好覆盖：
  - joined/search 查询行为
  - Web 壳状态机
  - sender exclusion 的 realtime 行为
  - 同源入口与静态资源 fallback
- 当前测试不足在：
  - 缺 production assembly smoke
  - HTTP 层混入壳 DOM/CSS 断言
  - 多壳共享 wire contract 仍有未锁死的边角
- 结论：验证面不是“太少”，而是“关键总装验证还缺、部分验证层次放错了”。

## 冲突裁决与过滤说明
- 我保留了 `contract session_id 污染`，但否决了“`display_title/latest_preview` 已经必然是 contract 污染”的更强说法，因为这块仍存在“业务中立摘要”的合理解释，证据还不够硬。
- 我保留了 `web.rs` realtime bridge 膨胀`，但没有把它直接裁成“truth 已经前移”，因为目前消息真相与成员真相仍在后端。
- 我保留了 `sqlx::test` 重复造轮子`，因为本地证据和外部官方校准都够硬。
- 被过滤或降级的主要候选：
  - `app_error_code()` 的重复包装
  - `dx-bundle-web.ps1` 的 lockfile regex
  - admin shell 对 web helper 的横向依赖
  - `display_title/latest_preview` 的 presenter 倾向
