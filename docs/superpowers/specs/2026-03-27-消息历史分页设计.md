# 消息历史分页设计

**目标**

把当前“整房间消息一次性返回”的实现，收敛成适合聊天软件的第一阶段分页模型：进入房间只加载最新一页消息，后续向上加载更老消息，避免长历史把前端渲染、滚动和网络都拖垮。

**范围**

只改现有文件，不新增 `.rs` 文件：
- `contract/src/lib.rs`
- `server/src/http.rs`
- `server/src/message_repo.rs`
- `web/src/client.rs`
- `web/src/state.rs`
- `web/src/app.rs`
- `web/src/chat.rs`
- 现有相关测试文件

**不做**

- 不做 `around` 跳转
- 不做全文搜索
- 不做消息虚拟列表
- 不改后端框架
- 不拆新 crate

## 方案

### 1. 契约层

给消息历史接口增加最小分页参数与返回信息：
- 请求：`before_message_id`、`limit`
- 响应：`items`、`has_more`

语义：
- `before_message_id = None` 时，返回最新一页消息
- `before_message_id = Some(id)` 时，返回比该消息更早的一页消息
- `items` 保持按时间升序，便于前端直接渲染
- 排序与裁剪规则固定为 `(created_at, id)`，避免同一时间戳下漏消息或重复消息
- `before_message_id` 非法、不存在或不属于当前房间时，返回 `400`

### 2. 后端层

`message_repo` 改成“按 `(created_at DESC, id DESC)` 取 `limit + 1` 条，再在内存中反转”为升序输出，避免整表/整房间全量返回。

`http::list_room_messages` 改成读取查询参数：
- 默认 `limit` 走安全上限
- 非法 `limit` 回退到默认值
- 非法 `before_message_id` 返回 `400`

### 3. 前端层

进入房间时：
- 只加载最新一页消息
- 把 `has_more` 和当前最早消息 id 存进状态

后续加载更老消息时：
- 调用同一接口，传 `before_message_id`
- 把更老消息 prepend 到现有消息列表
- 不重复追加已有消息

### 4. 交互层

这轮先不做自动滚动触发，只把能力和状态打通。
先提供明确的“加载更早消息”入口，保证行为稳定，再做滚动触发。

## 边界

- 领域层这轮不引入新分页领域对象，先保持最小侵入
- 分页是传输/仓储层能力，不改变 `send_text_message` 等核心业务规则
- 前端分页状态只放现有 `state.rs`，不新开文件

## 验证

至少覆盖：
- 后端最新页分页测试
- 后端 `before_message_id` 分页测试
- 后端同时间戳分页不漏消息测试
- 后端非法/跨房间 `before_message_id` 返回 `400` 测试
- 前端状态 prepend 不重复测试
- Web 端现有测试仍通过
- `cargo check` / `cargo test` 通过
