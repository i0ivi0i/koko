# 上传热路径性能瓶颈消除 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 消除上传热路径中的 5 个资源浪费瓶颈，让小图小视频的上传→ready 延迟降低 50%+。

**Architecture:** 3 个 Phase 按依赖关系分批交付。Phase 1 独立可交付（最低挂果）；Phase 2 依赖 Phase 1（共享 Client 已在 state 里）；Phase 3 依赖 Phase 2（spawn_blocking 已就绪）。所有改动限制在 shell/adapter 层，不动 domain/application/contract。

**Tech Stack:** Rust (Tokio, Axum, reqwest, object_store, memmap2)

**Spec:** `docs/superpowers/specs/2026-05-16-上传热路径性能瓶颈消除-design.md`

## 风险清单

| 风险 | 影响 | 缓解 |
|---|---|---|
| 共享 Client 的 timeout 不适合所有请求 | 某些请求超时或过早断开 | Tus 流式 body 需要长 timeout（300s），其它请求可覆盖 |
| put_multipart 在本地文件存储不支持 | 编译通过但运行时错误 | object_store LocalFileSystem 支持 put_multipart |
| spawn_blocking 线程池耗尽 | 高并发 complete 排队 | tokio 默认 512 线程，配合 media_complete_gate 信号量已有背压 |
| mmap drop 时机错误 | 流式写入中途文件被 unmap | Phase 2 显式在 upload.complete() 之后 drop |
