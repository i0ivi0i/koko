# 全屏退出视频卡片黑闪修复 实现计划

> **面向 AI 代理的工作者：** 必需子技能：使用 superpowers:executing-plans 逐任务实现此计划。

**目标：** 消除群聊视频全屏退出后卡片闪黑的视觉缺陷
**架构：** 两层防御——(1) canvas 冻结帧自愈守卫消除 GPU context loss 导致的画面丢失；(2) overlay 延迟移除消除同步移除暴露旧卡片的时序窗口。所有改动限定在 adapter/shell 层，不穿透 domain/application/contract。
**技术栈：** Lit、Canvas 2D API（contextlost/contextrestored）、requestAnimationFrame

## 前因后果

用户报告：在部分设备上，群聊内点开视频全屏欣赏后返回，视频卡片会先"黑一下"再恢复。根因是三条路径交叉作用：

1. **Canvas GPU 上下文丢失**：全屏进退触发浏览器 GPU 重置，`<canvas>` 冻结帧表面被清空，而 Lit 的 `ref()` 不会在此时重新触发重绘
2. **overlay 同步移除**：`overlay.remove()` 是同步操作，聊天时间线立即暴露，但 Lit re-render 要等下一微任务
3. **poster 兜底缺失**：部分视频无 poster，冻结帧也可能不存在，导致所有兜底层都无有效像素

核心矛盾：**overlay 同步移除暴露了时间线卡片，但卡片的视觉表面尚未就绪**。

### Task 2: GREEN — 实现 canvas context 守卫

**文件：** `frontend/房间消息窗/视频桥接帧.ts`

**步骤：**

1. 新增 `挂载冻结帧画布守卫` 函数：

```typescript
export const 挂载冻结帧画布守卫 = (
  canvas: HTMLCanvasElement,
  frame: 时间线自动播冻结帧
): void => {
  const 重绘 = (): void => {
    绘制时间线冻结帧到画布(frame, canvas);
  };
  canvas.addEventListener("contextrestored", 重绘);
  canvas.addEventListener("contextlost", (e: Event) => {
    e.preventDefault();
  });
};
```

关键说明：
- `contextlost` 上调用 `preventDefault()` 告知浏览器我们会处理恢复，不要丢弃 context
- `contextrestored` 上执行重绘
- 监听器跟着 canvas 元素生命周期走，canvas 被 GC 时自动清理，无需手动 removeEventListener

**文件：** `frontend/房间消息窗/视频附件表面渲染.ts`

2. 在 frozen-frame canvas 的 `ref()` 回调中，绘制完成后挂载守卫：

```typescript
${ref((canvas) => {
  if (!(canvas instanceof HTMLCanvasElement) || !frozenTimelineFrame) {
    return;
  }
  绘制时间线冻结帧到画布(frozenTimelineFrame, canvas);
  挂载冻结帧画布守卫(canvas, frozenTimelineFrame);
})}
```

```typescript
const 已挂载守卫画布 = new WeakSet<HTMLCanvasElement>();

  canvas: HTMLCanvasElement,
  frame: 时间线自动播冻结帧
): void => {
  if (已挂载守卫画布.has(canvas)) {
    return;
  }
  已挂载守卫画布.add(canvas);
  // ...监听器挂载逻辑
};
```

WeakSet 不阻止 canvas 被 GC，无泄漏风险。

### Task 5: GREEN — 实现 overlay 延迟移除

**文件：** `frontend/媒体/媒体查看器.ts`

**步骤：**

1. 在 `cleanup()` 函数中，将 `overlay.remove()` 替换为延迟移除：

```typescript
// 原来：
overlay.remove();
lifecycle.结束视口占用();

// 改为：
overlay.style.cssText = "position:fixed;inset:0;z-index:2147483647;opacity:0;pointer-events:none;";
overlay.removeAttribute("role");
overlay.removeAttribute("aria-modal");
overlay.removeAttribute("aria-label");
lifecycle.结束视口占用();

// 等待 2-3 帧让 Lit re-render 完成，再移除 overlay
requestAnimationFrame(() => {
  requestAnimationFrame(() => {
    overlay.remove();
  });
});
```

关键说明：
- 立即透明化 + `pointer-events:none`：用户看不见也点不到
- 移除 ARIA 属性：避免 VoiceOver 继续拦截焦点（iOS Safari 无障碍兼容）
- 双层 rAF：第一帧浏览器完成全屏退出渲染，第二帧 Lit 完成 re-render，overlay 使命完成后安全移除
- 超时兜底不需要：rAF 本身保证会在有限帧内执行，overlay 不会无限悬挂

## 拒绝方案

- **轮询检查 canvas 像素**：每帧 `getImageData` 读 1px 判断是否为空 → CPU 持续消耗，违反零成本原则
- **CSS background-image 替代 canvas**：需要把 `ImageBitmap` 导出为 blob URL → 额外内存+编码开销，改动范围大
- **全局 MutationObserver 监控 canvas**：过度杀伤，canvas 内容变化不会触发 DOM 属性变化

## 100% 信心循环

**已解决的漏洞：**
1. Lit `ref()` 重复挂载守卫 → WeakSet 去重
2. iOS Safari 透明 overlay ARIA 拦截焦点 → 移除 aria-modal/role
3. `exitFullscreen()` 异步结算期间 canvas 重绘 → 双层 rAF 等待浏览器完成全屏退出
