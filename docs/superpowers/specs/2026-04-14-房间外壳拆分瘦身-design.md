# 房间外壳拆分瘦身设计

日期：2026-04-14  
状态：Draft  
适用范围：`koko` 仓库后端 `src/房间外壳.rs` 及其在 `src/外壳.rs` 中挂载的 HTTP 路由。  
关联文档：

- `docs/superpowers/specs/2026-04-13-群聊媒体实时收发全链路TDD疏通-design.md`
- `docs/superpowers/specs/2026-04-13-跨端志愿者媒体资产与P2P分发协议-design.md`
- `docs/superpowers/specs/2026-04-14-Web单一视频播放器壳与外置分发层-design.md`

## 1. 背景

`src/房间外壳.rs` 当前同时承载了：

1. 房间 HTTP 入口；
2. 媒体上传准备与完成；
3. Rustus hook 处理；
4. 图片与视频内容解析；
5. 流媒体打包与清单重写；
6. 媒体资产 locator / blob / stream / torrent / presence / content 读取。

这已经不是“房间外壳”，而是一个跨 `shell / adapter / 媒体处理` 的胖文件。继续在这里加功能，只会放大下面这些问题：

1. 房间接口与媒体链路纠缠，改一个能力要读完整个大文件；
2. HTTP 壳层直接携带大量媒体细节，边界退化；
3. 热点文件持续变胖，回归风险上升；
4. helper 更容易失控变成私有垃圾层。

本次设计目标不是把大文件切碎，而是把职责重新放回正确 owner，并且不引入新冗余、不制造双轨旧代码。

## 2. 目标与非目标

### 2.1 目标

1. 把 `src/房间外壳.rs` 恢复成真正的房间 HTTP 壳；
2. 允许新增 `5` 个 `.rs` 文件，按能力 owner 分担媒体相关职责；
3. 不改变现有对外 HTTP 契约、错误码语义和媒体主链行为；
4. 迁移过程中坚持 TDD，先补失败测试，再搬逻辑，再删旧实现；
5. 拆分后没有双轨实现、没有 `common/utils/helper` 垃圾层。

### 2.2 非目标

1. 不改写 `src/用例.rs` 与 `src/领域/*` 的业务真相归属；
2. 不更换 Rustus、对象存储、图片/视频解析、流媒体打包所依赖的成熟轮子；
3. 不顺手做跨仓库、跨上下文的大重构；
4. 不通过“先复制一份新实现再慢慢切换”来拖着旧代码共存。

## 3. 核心原则

### 3.1 DDD 边界

1. 业务真相继续留在 `application / domain`；
2. HTTP handler 只做协议解析、鉴权承接、调用用例、错误转码、响应翻译；
3. 媒体字节解析、外部命令调用、对象存储读取等能力属于 adapter，不留在房间壳层。

### 3.2 Unix 哲学

1. 一个文件只做一件清楚的事；
2. 文件名直接表达职责，不用 `utils / common / service / manager` 这类垃圾名；
3. helper 默认跟 owner 走，只有两个以上 owner 真共享且语义完全一致时才允许外提；
4. 拆分必须压缩复杂度，不能只是把同样的脏逻辑挪到更多文件里。

## 4. 目标结构

### 4.1 保留在 `src/房间外壳.rs`

只保留房间接口相关入口：

1. `bootstrap_session`
2. `join_or_create_room`
3. `load_room_snapshot`
4. `update_room_read_anchor`
5. `load_room_events`
6. `load_room_history`

以及只服务这些接口的 query/body 解析。

### 4.2 新增 5 个文件

#### `src/媒体上传外壳.rs`

职责：

1. `prepare_media_upload`
2. `complete_media_upload`
3. complete 前等待运输回执的轮询编排
4. 只服务上传链路的标识、令牌、类型校验 helper

不负责：

1. Rustus hook 入口；
2. 流媒体打包细节；
3. locator / blob / stream 读取。

#### `src/rustus_hook外壳.rs`

职责：

1. `handle_rustus_hook`
2. `handle_rustus_hook_pre_create`
3. `handle_rustus_hook_post_finish`
4. hook 名称、metadata、授权头、临时文件路径解析

不负责：

1. complete 链路编排；
2. 媒体资产读取。

#### `src/媒体内容解析.rs`

职责：

1. 图片类型识别与 EXIF 方向处理；
2. 缩略图、完整图生成；
3. 视频轨道宽高、旋转方向解析；
4. 媒体字节到结构化结果的纯解析。

不负责：

1. HTTP；
2. 数据库；
3. 对象存储；
4. 外部路由挂载。

#### `src/流媒体打包.rs`

职责：

1. `ffmpeg / ffprobe / shaka-packager` 调用；
2. 打包产物收集；
3. HLS / DASH 清单重写；
4. 打包产物上传。

不负责：

1. 房间接口；
2. Rustus hook；
3. 对外 HTTP 响应拼装。

#### `src/媒体资产外壳.rs`

职责：

1. `load_media_locator`
2. `load_blob_asset_content`
3. `load_streaming_asset_content`
4. `load_media_torrent`
5. `update_media_distribution_presence`
6. `load_attachment_content`
7. `Range` 解析、受控 URL/路径构造、媒体资产响应体翻译

不负责：

1. 上传准备与完成；
2. Rustus hook；
3. 媒体字节解析与打包实现本体。

## 5. 路由归属调整

`src/外壳.rs` 中现有全部挂在 `房间外壳::*` 的媒体路由，需要改为分别指向新 owner：

1. `/api/media/{attachment_kind}/prepare` -> `媒体上传外壳`
2. `/api/media/{attachment_id}/complete` -> `媒体上传外壳`
3. `/internal/rustus/hooks` -> `rustus_hook外壳`
4. `/api/media/{attachment_id}/locator` -> `媒体资产外壳`
5. `/api/media/{attachment_id}/blob/{asset_variant}` -> `媒体资产外壳`
6. `/api/media/{attachment_id}/stream/{*asset_path}` -> `媒体资产外壳`
7. `/api/media/{attachment_id}/torrent` -> `媒体资产外壳`
8. `/api/media/{attachment_id}/presence` -> `媒体资产外壳`
9. `/api/attachments/{attachment_id}/content` -> `媒体资产外壳`

房间接口路由继续留在 `房间外壳`。

## 6. 迁移顺序

迁移顺序必须遵守“先纯函数，后外壳；先内脏，后入口”：

1. 先补护栏测试，不改行为；
2. 先抽 `媒体内容解析.rs`；
3. 再抽 `流媒体打包.rs`；
4. 再抽 `rustus_hook外壳.rs`；
5. 再抽 `媒体上传外壳.rs`；
6. 最后抽 `媒体资产外壳.rs`，并同步改 `src/外壳.rs` 路由归属；
7. 每迁完一簇逻辑，同提交删除原文件中对应旧实现。

这样做的原因是：

1. 先搬纯能力，回归半径最小；
2. 先把最脏、最不该留在房间壳里的实现拿走；
3. 最后再改总入口，避免一开始就把所有风险叠在路由层。

## 7. TDD 与验证护栏

### 7.1 施工规则

1. 先写失败测试或补足现有缺口，再搬实现；
2. 每一轮迁移只搬一簇 owner；
3. 任何新模块启用后，旧实现必须当轮删除；
4. 新模块默认 `pub(super)`，避免无意义扩大暴露面。

### 7.2 必跑验证

至少覆盖并通过这些回归面：

1. 媒体上传相关测试；
2. Rustus hook 相关测试；
3. 媒体共享契约测试；
4. blob / streaming 资产契约测试；
5. 房间接口回归测试；
6. 最终全量 `cargo test`。

如果某一轮拆分不能证明这些风险面仍然成立，就不能宣称完成。

## 8. 完成定义

做到下面这些，才算这份设计真正落地：

1. `src/房间外壳.rs` 不再包含媒体上传、Rustus hook、媒体解析、流媒体打包、媒体资产读取实现；
2. 新增的 `5` 个 `.rs` 文件各自只有一个明确 owner，没有第二职责；
3. `src/外壳.rs` 中媒体路由不再全部指向 `房间外壳::*`；
4. 迁移后不存在新旧双轨共存的实现；
5. 迁移后全量回归通过；
6. 项目 `.rs` 文件总数仍满足仓库约束；
7. 没有新增 `common / utils / helpers / manager / service` 之类的垃圾抽象层。

## 9. 一句话结论

这次拆分不是把 `src/房间外壳.rs` 机械切碎，而是把它恢复成真正的房间 HTTP 壳：  
房间留房间，上传归上传，hook 归 hook，媒体解析归解析，流媒体打包归打包，资产读取归资产读取。  
只新增 `5` 个有明确 owner 的文件，不引入冗余代码，不保留双轨旧实现，不再让这个热点继续失控变胖。
