# 视频卡片黑屏根因修复 Spec

## 1. 现象

群聊消息流中滑动时，非当前自动播 owner 的视频卡片显示为黑色/深色方块，而非封面图。owner 切换后，上一个 owner 也变成黑卡片。

## 2. 领域模型：视频卡片视觉表面栈

每张视频卡片 `.message-video-card` 拥有一组可选视觉表面，同一时刻应有且仅有一个"最高优先级的、已拥有可见像素的表面"对用户可见。

| 表面 | CSS 选择器 | 语义 | 优先级 |
|------|-----------|------|--------|
| canonical-host | `.message-video-canonical-host` | 唯一播放器的 live 画面 | 最高 |
| frozen-frame | `.message-video-frozen-frame` | 退场时画布冻结的帧 | 高 |
| preview-video | `.message-video-preview` | 预加载的 `<video>` 元素 | 中 |
| poster | `.message-video-poster` | 静态封面图 | 最低（兜底） |

**不变量（invariant）**：用户永远不应看到卡片的裸露 CSS 渐变背景。至少有一个表面必须有可见像素。

## 3. 根因分析

### 根因 A：CSS 层叠架构破碎——poster 作为兜底层却被裁剪

**当前 DOM 模板顺序**（`视频附件表面渲染.ts` L129-204）：
```
.message-video-card (position: relative; overflow: hidden; explicit W×H)
  └ button.message-video-preview-trigger (position: relative; 100%×100%)
      ├ canvas.message-video-frozen-frame   → position: absolute; inset: 0; z-index: 2  ✓
      ├ div.message-video-canonical-host    → position: absolute; inset: 0; z-index: 1  ✓
      ├ video.message-video-preview         → position: RELATIVE; height: 100%          ✗
      └ img.message-video-poster            → position: RELATIVE; height: 100%          ✗
```

**问题**：preview video 和 poster 都是 `position: relative; height: 100%`。在文档流中，video 先占满整个卡片高度，poster 被推到 video 下方，被 `overflow: hidden` 裁剪掉。poster 作为"最低优先级兜底层"在 DOM 中却永远不可见。

frozen-frame 和 canonical-host 已经用 `position: absolute; inset: 0` 正确叠加。**poster 和 preview-video 没有遵循同一叠加模型**——这是架构不一致。

### 根因 B：渲染决策用"意图"压制 poster，而非用"实际像素就绪"

`shouldSuppressPosterForContinuity`（L288-297）在以下条件压制 `<img>` poster：
```typescript
(Boolean(restorableTimelineFrame) ||
  shouldReuseSavedTimelineFrameAsPreview ||  // ← 只是"打算 seek 到保存位置"
  hasFrozenTimelineFrame ||
  hasCurrentCanonicalRevealReady)
```

`restorableTimelineFrame` 和 `shouldReuseSavedTimelineFrameAsPreview` 只代表**意图**（"将来该 seek 到哪"），不代表**事实**（"video 当前 DOM 已有可见像素"）。当 video 还未 decode 任何帧时，poster 已被压制，用户只看到 video 的 CSS 背景。

`previewVideoPoster`（L457-463）的 native poster 属性在多数场景能部分弥补，但依赖两个前提：
1. video CSS background 必须透明（当前共享规则给了深色渐变 → **已被我的 CSS 修复覆盖**）
2. 浏览器 native poster 行为跨引擎一致（Chromium/Firefox/Safari 对 `<video poster>` + `object-fit: cover` 的表现有差异）

### 根因 C：共享 CSS 规则给了 preview video 错误的深色背景

```css
.message-video-poster,
.message-video-frozen-frame,
.message-video-preview {          /* ← 三个语义不同的表面共享一条规则 */
  position: relative;
  background: radial-gradient(...), linear-gradient(...);  /* 深色渐变 */
}
```

frozen-frame 随后被覆盖为 `position: absolute; background: transparent`。preview video 没有被覆盖。这是一个 CSS 架构不一致。

## 4. 修复方案

### 4.1 CSS 层叠架构统一（根因 A + C）

**原则**：所有视觉表面统一使用 `position: absolute; inset: 0` 叠加模型。卡片 `.message-video-card` 通过 `attachmentCardStyle` 持有显式 W×H，所有子元素无需参与文档流定位。

**目标 z-index 栈**：
```
z-index: 0  →  poster (img)                    兜底，始终作为最底层
z-index: 1  →  preview video                    有帧时覆盖 poster，无帧时透明
z-index: 2  →  frozen-frame (canvas)            退场快照，覆盖 preview
z-index: 3  →  canonical-host (div)             live 播放
z-index: 4  →  poster--canonical-cover (img)    owner warmup 期间的封面遮罩
z-index: 5  →  first-frame-guard (img)          无 poster 时的首帧占位
```

**具体 CSS 改动**：

1. **`.message-video-preview`**：从共享规则的 `position: relative` 覆盖为 `position: absolute; inset: 0; z-index: 1; background: transparent`

2. **`.message-video-poster`**（非 `--canonical-cover` 状态）：从共享规则的 `position: relative` 覆盖为 `position: absolute; inset: 0; z-index: 0`

3. canonical-host 的 z-index 从 1 调整为 3

4. `.message-video-poster--canonical-cover` 的 z-index 从 2 调整为 4（需覆盖 canonical-host）

5. `.message-video-first-frame-guard` 的 z-index 调整为 5（需覆盖一切）

6. 共享规则保留 `display: block; width: 100%; height: 100%; border-radius: inherit; object-fit: cover; pointer-events: none`，但移除 `position: relative; z-index: 0; background: ...`（各表面自己声明）

### 4.2 渲染决策逻辑简化（根因 B）

**原则**：poster 压制逻辑本身就是错误的方向。当 CSS 层叠正确时，poster 在底层**永远不会视觉干扰上层**。压制只是浪费复杂度。

**策略**：**有封面就渲染，让 z-index 栈决定可见性。删除所有 poster 压制逻辑。**

**改动**：将 `shouldRenderPreviewPosterSurface` 从 16 行复杂条件替换为 1 行不变量：

```typescript
// 之前：16 行布尔 flag 组合 + 3 个 OR 分支
const shouldRenderPreviewPosterSurface =
    ((...16 lines...) || (...)) ||
    shouldRenderCanonicalLoadingPosterCover ||
    shouldRenderRetiringOwnerFrozenFramePosterSafetyNet;

// 之后：有封面就渲染，z-index 栈物理保证不干扰上层
const shouldRenderPreviewPosterSurface = hasStablePreviewPosterSurface;
```

**可删除的 poster 专用变量**（唯一消费点均在旧 `shouldRenderPreviewPosterSurface` 中）：
- `shouldSuppressPosterForContinuity`（~10 行）
- `shouldRenderCanonicalLoadingPosterCover`（~8 行）
- `shouldRenderRetiringOwnerFrozenFramePosterSafetyNet`（~5 行）
- `shouldKeepCanonicalCoverDuringGuardedPreviewWarmup`（~3 行）

净减 ~45 行复杂度。`shouldKeepPosterDuringSavedPositionOwnerWarmup` 因被 video 逻辑引用（`shouldSuppressColdPlaceholderPreviewVideo`、`shouldSuppressPosterBackedOwnerWarmupPreview`）而保留。

**为什么正确**：
- poster 在 z:0，preview video 在 z:1（transparent bg），frozen frame 在 z:2，canonical 在 z:3
- 任何更高优先级表面有像素时，自然遮住 poster，无需显式压制
- poster 是一个 `<img>`，被完全遮挡时浏览器不会重绘
- `--canonical-cover` class 由模板里 `shouldRenderInlineVideo && !shouldRevealCanonicalHost` 控制，不受影响

### 4.3 清理已完成的临时 CSS 修复

上述 4.1 完成后：
- 删除当前 session 添加的 `.message-video-preview { background: transparent }` 单独覆盖（被 4.1 的完整覆盖替代）
- `shouldGatePreviewVideo` 不再需要，`--gated` class 仍只由 `shouldShowFirstFrameGuard` 控制（无 poster 且无帧时的极端兜底）

## 5. 验证标准

### 5.1 不变量测试（新增）

| # | 场景 | 断言 |
|---|------|------|
| T1 | 非 owner 有 poster、有预算 → video + poster 共存 | DOM 中同时存在 `img.message-video-poster` 和 `video.message-video-preview` |

| T4 | owner 退场、frozen frame 存在 | DOM 中同时存在 poster (z:0) 和 frozen frame (z:2)，frozen frame 覆盖一切 |

## 7. 风险

- **poster absolute 后高度贡献消失**：卡片 `.message-video-card` 已通过 `attachmentCardStyle` 持有显式 W×H，子元素无需参与文档流定位。只需确认卡片无依赖子元素 intrinsic height 的路径。
- **canonical-host z-index 调整**：从 1→3，需确认 `.message-video-canonical-host[data-covered="true"]` 的 opacity:0 仍正常工作（不应受 z-index 影响）。
- **现有测试可能断言 position/z-index**：需逐个检查并更新。
